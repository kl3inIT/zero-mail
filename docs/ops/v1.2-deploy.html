This runbook lands the compose and operator procedure for the v1.2 admin console foundation. The live VPS cutover is out-of-scope-for-merge: merge only the compose definitions and this runbook, then schedule the migration as a separate deploy step with a rollback operator present.

The target stack keeps the existing postgres, redis, worker, api, and frontend services. Phase 8A adds nginx-proxy-manager for public TLS routing and 9router as a loopback-bound sidecar on 127.0.0.1:20128.

¶ 1. Pre-Migration Backup

  1. SSH into the VPS as the deploy operator.

    ssh root@vps
cd /opt/zeromail

  2. Capture the current hand-managed nginx configuration before starting NPM.

    mkdir -p /opt/zeromail/backups/nginx-$(date -u +%Y%m%dT%H%M%SZ)
cp -a /etc/nginx /opt/zeromail/backups/nginx-$(date -u +%Y%m%dT%H%M%SZ)/
nginx -T > /opt/zeromail/backups/nginx-current-full.conf

  3. Capture the active compose model and env names.

    docker compose config > /opt/zeromail/backups/compose-before-v1.2.yml
env | grep '^ZEROMAIL_' | sort > /opt/zeromail/backups/env-names-before-v1.2.txt

  4. Confirm the OAuth callback URL must remain bit-for-bit identical:

    https://zeromail.com/login/oauth2/code/google

  5. Confirm these secrets exist before first boot:

    test -n "$ZEROMAIL_9ROUTER_JWT_SECRET"
test -n "$ZEROMAIL_9ROUTER_INITIAL_PASSWORD"
test -n "$ZEROMAIL_ADMIN_AUDIT_HMAC_KEK_BASE64"

¶ 2. NPM Boot And Parallel Routing Test

  1. Start NPM without stopping the existing nginx service yet.

    docker compose pull nginx-proxy-manager 9router
docker compose up -d nginx-proxy-manager 9router
docker compose ps nginx-proxy-manager 9router

  2. Access the NPM UI only through an SSH tunnel. Compose binds port 81 to 127.0.0.1 for this reason.

    ssh -L 8181:127.0.0.1:81 root@vps

  3. Open http://127.0.0.1:8181 locally, rotate the default NPM password, and create proxy hosts:

    Host Scheme Forward host Forward port Notes
    zeromail.com http zeromail-frontend 3000 Preserve Google OAuth callback path.
    zeromail.com/api http zeromail-api 8080 Use NPM location rule for /api.
    admin.zeromail.com http zeromail-frontend 3000 Admin SPA route /enroll is frontend-owned.
    admin.zeromail.com/api/admin http zeromail-api 8080 Backend token path is /api/admin/enrollment/session.

  4. Configure NPM advanced headers for both public hosts.

    proxy_set_header Host $server_name;
proxy_set_header X-Forwarded-Host $server_name;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

  5. Validate routing through a staging host or local hosts-file override before DNS cutover.

    curl -I https://staging.zeromail.com/
curl -I https://staging.zeromail.com/api/actuator/health
curl -I https://admin-staging.zeromail.com/login
curl -I https://admin-staging.zeromail.com/api/admin/me

¶ 3. DNS Cutover

  1. Lower DNS TTL for zeromail.com and admin.zeromail.com before the window.

  2. Ensure NPM has certificates for both hosts.

    docker compose logs --tail=200 nginx-proxy-manager

  3. Stop hand-managed nginx only after the NPM staging route is healthy.

    systemctl stop nginx
docker compose up -d nginx-proxy-manager

  4. Point public DNS records at the VPS IP:

    zeromail.com          A     <vps-ip>
admin.zeromail.com    A     <vps-ip>

  5. Recheck the OAuth callback and admin split.

    curl -I https://zeromail.com/login/oauth2/code/google
curl -I https://admin.zeromail.com/enroll
curl -I https://admin.zeromail.com/api/admin/enrollment/session

¶ 4. Rollback

  1. If NPM cannot route either public host, stop it first.

    docker compose stop nginx-proxy-manager

  2. Restore hand-managed nginx from the pre-migration backup.

    cp -a /opt/zeromail/backups/nginx-*/nginx /etc/nginx
nginx -t
systemctl start nginx

  3. Restore DNS if the cutover already changed records.

  4. Keep 9router stopped during rollback unless the API already points at it.

    docker compose stop 9router

  5. Write an incident note with the failed curl command, NPM access logs, and the rollback timestamp.

¶ 5. Post-Migration Backup

  1. Back up NPM /data, NPM LetsEncrypt material, and 9Router SQLite state. The default backup flow is tar | gpg | rsync.

    backup_stamp=$(date -u +%Y%m%dT%H%M%SZ)
tar -C /opt/zeromail -cpf - npm-data npm-letsencrypt 9router-data \
  | gpg --symmetric --cipher-algo AES256 \
  | rsync -av - backup@example-backup-host:/srv/backups/zeromail/v1.2-$backup_stamp.tar.gpg

  2. Keep only encrypted backups off-host. Do not copy plaintext NPM data or the 9Router SQLite database to a workstation.

  3. Verify the backup is readable without restoring over production.

    rsync -av backup@example-backup-host:/srv/backups/zeromail/v1.2-$backup_stamp.tar.gpg /tmp/
gpg --decrypt /tmp/v1.2-$backup_stamp.tar.gpg | tar -tf - | head
rm -f /tmp/v1.2-$backup_stamp.tar.gpg

¶ 6. 9Router First-Run

  1. Start 9Router and open it through an SSH tunnel only.

    docker compose up -d 9router
ssh -L 20128:127.0.0.1:20128 root@vps

  2. Open http://127.0.0.1:20128, rotate ZEROMAIL_9ROUTER_INITIAL_PASSWORD, generate an API key, and connect provider accounts.

  3. Store the generated API key in the VPS secret source used by the API service. Do not paste the value into shell history.

  4. Restart the API only after the secret source is updated.

    docker compose restart api

¶ 7. Admin Bootstrap STDOUT Capture

  1. Bootstrap admin enrollment tokens are printed to STDOUT only. Do not run the first API boot detached when capturing a new enrollment URL.

    ZEROMAIL_ADMIN_BOOTSTRAP_EMAILS=you@example.com \
ZEROMAIL_ADMIN_AUDIT_HMAC_KEK_BASE64=$(openssl rand -base64 32) \
docker compose up api 2>&1 | tee /tmp/admin-bootstrap.log

  2. Extract the enrollment URL and delete the temporary file.

    grep enrollment /tmp/admin-bootstrap.log
shred -u /tmp/admin-bootstrap.log || rm -f /tmp/admin-bootstrap.log

  3. Expected line shape:

    [ZeroMail Admin Bootstrap] you@example.com enrollment URL: https://admin.zeromail.com/enroll?token=<32hex> (valid 10 minutes)

¶ 8. Lost-Passkey Recovery

Use this only for a verified operator identity. This is the lost-passkey recovery path for a passkey that cannot satisfy WebAuthn user verification.

ssh root@vps
cd /opt/zeromail
docker compose exec api psql -U zeromail_app zeromail

UPDATE admin_users
SET status='PENDING_ENROLLMENT',
    credential_id=NULL,
    public_key_cose=NULL,
    signature_counter=0
WHERE email='lost@example.com';

Single-command form for audited recovery notes:

docker compose exec api psql -U zeromail_app zeromail -c "UPDATE admin_users SET status='PENDING_ENROLLMENT', credential_id=NULL, public_key_cose=NULL, signature_counter=0 WHERE email='lost@example.com';"

Then restart the API without detached mode and capture the new STDOUT enrollment URL using the bootstrap procedure above.

¶ 9. IP Allowlist

NPM Access List is the approved optional IP allowlist mechanism for admin.zeromail.com.

  1. In NPM, create an Access List named Zero Mail Admin Operators.
  2. Add trusted office/VPN CIDRs only.
  3. Apply the Access List to admin.zeromail.com.
  4. Do not apply the Access List to zeromail.com because it would block users and Google OAuth callback traffic.

¶ 10. Security Considerations

  • Heap dumps: keep -XX:+HeapDumpOnOutOfMemoryError disabled unless running a supervised incident capture. Heap dumps can contain session, token, or prompt material.
  • JMX: do not expose remote JMX on the VPS. Use local docker compose exec and actuator health endpoints instead.
  • Memory swap: keep swap encrypted or disabled. If swap is enabled, verify the host uses encrypted swap before production traffic.
  • NPM admin UI: port 81 is loopback-bound in compose. Use SSH tunneling rather than opening it to the internet.
  • Host headers: NPM config must pin Host and X-Forwarded-Host to $server_name to avoid cookie-scope confusion between zeromail.com and admin.zeromail.com.
