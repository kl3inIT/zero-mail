### (d) Confirmation that the OAuth round-trip lands the user on a CONNECTED card

**Cannot exercise live OAuth in this session** for the same backend-not-reachable reason. The W3 surface is wired to the W2 success-handler invariant the W2 SUMMARY asserts: `CalendarOAuthSuccessHandler.resolveActiveMailboxIdFromSession` reads `snapshot.targetMailboxId()` from the callback session attribute set by `IntentCarryingAuthorizationRequestRepository.removeAuthorizationRequest`, and `CalendarSnapshotIngestionService.ingestSnapshot` then seeds 3 preference rows (FREEBUSY + EVENT_WRITE + BRIEF_SOURCE) for the primary calendar against that `targetMailboxId` (W2 test `ingestSnapshot_insertsCalendarRowsAndPrimaryDefaultRoles`).

W3 closes the missing piece — stamping the snapshot at OAuth init via `POST /api/calendar/connect-intent`. The chain is:

1. User clicks "Connect Google Calendar" on `/settings/mailboxes/{id}/calendar` → `ConnectCalendarButton.onClick` calls `useConnectCalendarIntent.mutate()`.
2. `prepareCalendarConnect(mailboxId)` POSTs `/api/calendar/connect-intent` with `{mailboxId}` + the XSRF header (echoed via `xsrfHeader()`).
3. `CalendarConnectIntentController.prepareConnect` validates mailbox ownership via `GmailConnectionService.resolveOwnedConnectionOrThrow` (T-12-08 tampering mitigation), stamps `OAuthIntentSnapshot(INTENT_CALENDAR_CONNECT, mailboxId, tenantId)` on `request.getSession(true)`, persists the initiating SecurityContext, returns `{authorizationUrl: "/oauth2/authorization/google-calendar"}`.
4. Hook navigates `window.location.assign(response.authorizationUrl)`.
5. `GoogleAuthorizationRequestResolver.customizeAuthorizationRequest` reads the pending snapshot, promotes it onto `OAuth2AuthorizationRequest.attributes` (new W3 `validManagementIntent` case accepts `INTENT_CALENDAR_CONNECT` when `targetMailboxId != null`).
6. After Google grants, `IntentCarryingAuthorizationRequestRepository.removeAuthorizationRequest` snapshots the attributes back into the `CALLBACK_INTENT_SESSION_ATTRIBUTE`.
7. `CalendarOAuthSuccessHandler.resolveActiveMailboxIdFromSession` reads `snapshot.targetMailboxId()` → `CalendarSnapshotIngestionService` seeds 3 preference rows for that mailbox → success redirect.
8. The browser lands back on `/settings/calendar` (W2 redirect target), the user navigates to `/settings/mailboxes/{id}/calendar`, and `useCalendarConnections` (5s staleTime) returns the new CONNECTED card with the primary calendar already tagged for the 3 roles.

This is the full D-06 contract. Manual verification deferred to first integration run; the unit-test gates pin the seams (CalendarConnectIntentControllerTest at the stamp end, W2 CalendarSnapshotIngestionServiceTest at the consume end, W2 CalendarOAuthSuccessHandlerTest at the success-handler bridge).
