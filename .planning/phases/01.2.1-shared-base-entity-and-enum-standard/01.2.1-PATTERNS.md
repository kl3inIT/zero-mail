### `core.shared.persistence.AbstractEntity` (NEW — `@MappedSuperclass`)

**Analog:** `backend/core/src/main/java/com/zeromail/core/tenant/persistence/TenantEntity.java`

**`id` field pattern** (TenantEntity.java lines 15-16):

**Constructor + getter pattern — protected no-arg + public getter** (TenantEntity.java lines 24-31):
```java

    public TenantEntity(UUID id, String displayName) { ... }

    public UUID getId() { return id; }
```

**What `AbstractEntity` should hoist:** the `UUID id` `@Id` field, the `protected` no-arg constructor for JPA, and the public `getId()` getter. Mark the class `@MappedSuperclass` (NOT `@Entity`) and `public abstract`. Use **jakarta.** imports only (CLAUDE.md lock).

### `core.shared.persistence.AbstractAuditableEntity` (NEW — extends `AbstractEntity`)

**Analog:** `TenantEntity.java` line 21-22 (current `createdAt` field) + Spring Data JPA Auditing convention.

**Existing `createdAt` pattern that must be hoisted** (TenantEntity.java lines 21-22):
```java
    @Column(name = "created_at", nullable = false, insertable = false, updatable = false)
    private Instant createdAt;
```

**What changes per D-A2/D-A4:**
- Field stays `private Instant createdAt;` (column `created_at`).
- Drop `insertable=false, updatable=false` — the `AuditingEntityListener` populates the value, not a DB default. (Liquibase changeset must keep the existing `created_at` column DEFAULT for back-compat with Phase 1.0 inserts; new code paths let the listener write.)
- Add new field `private Instant updatedAt;` mapped to column `updated_at`.
- Annotate class with `@MappedSuperclass` and `@EntityListeners(AuditingEntityListener.class)`.
- Annotate `createdAt` with `@CreatedDate`, `updatedAt` with `@LastModifiedDate` (Spring Data `org.springframework.data.annotation.*`).
- Add `@Version private Integer version;` per D-A3 (column `version` with DEFAULT 0 from Liquibase).
- Public getters; **no setters** for audit fields.

**Document in Javadoc the D-A5 caveat** (paste verbatim into `package-info.java`):
> `@PreUpdate` / `@LastModifiedDate` lifecycle callbacks DO NOT fire for bulk JPQL `@Modifying @Query`, native SQL via `entityManager.createNativeQuery(...)`, or `JdbcTemplate` updates. If a future bulk update is needed, set `updated_at = NOW()` explicitly in the query.

```java
package com.zeromail.core.shared.lang;

public interface IdentifiedEnum {
```

### S-2: Constructor delegation pattern (concrete entity → abstract base)

**Source:** This pattern is being **introduced** by this phase (no current analog — entities currently flat). The shape is mandated by JPA `@MappedSuperclass` + Java records can't extend, so plain class hierarchy.

**Apply to:** All 4 concrete entity edits.

**Reference shape** (model after this — synthetic but mandated):
```java
public UserEntity(UUID id, UUID tenantId, String googleSubject, String email) {
    super(id, tenantId);                              // → AbstractTenantOwnedEntity(UUID, UUID)
    this.googleSubject = googleSubject;
    this.email = email;
}

protected UserEntity() {} // JPA proxy requirement — kept on concrete class even though base also has one
```

The base classes themselves need:
- `AbstractEntity` — `protected AbstractEntity() {}` + `protected AbstractEntity(UUID id) { this.id = id; }`.
- `AbstractAuditableEntity` — `protected AbstractAuditableEntity() {}` + `protected AbstractAuditableEntity(UUID id) { super(id); }`.
- `AbstractTenantOwnedEntity` — `protected AbstractTenantOwnedEntity() {}` + `protected AbstractTenantOwnedEntity(UUID id, UUID tenantId) { super(id); this.tenantId = tenantId; }`.
