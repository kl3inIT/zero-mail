# Phase 01.2.1 Plan 02: Shared Lang Module + IdentifiedEnum/OrderedEnum Interface Standard Summary

Three new files in a new `core.shared.lang` Modulith leaf module — the contract that every domain enum will implement so persistence is decoupled from Java symbol layout (D-C2) and ordering is decoupled from declaration order (D-B5). Pure interface introduction with zero consumers in this plan; Plan 03 applies the interfaces to `OnboardingStep` and `GmailConnectionStatus` and updates the cross-domain Modulith `allowedDependencies` arrays.

## Final Interface Signatures

```java
// IdentifiedEnum — base contract
public interface IdentifiedEnum {
    String id();                                    // D-C2: when implementer is enum, MUST equal name()
    default String labelKey() {                     // D-B3: <ClassSimpleName>.<id> format
        return getClass().getSimpleName() + "." + id();
    }
}

// OrderedEnum — adds explicit weight (closes WR-02 ordinal()-shift bug)
public interface OrderedEnum extends IdentifiedEnum {
    int weight();                                   // D-B5: use 10/20/30/40 with gaps
}
```

## Documented Invariants

| ID | Invariant | Enforcement |
|---|---|---|
| **D-C2** | When an `IdentifiedEnum` implementer is a Java `enum`, `id()` MUST equal `name()` | Documented convention + `@Enumerated(EnumType.STRING)` on entity field + Plan 03 `OnboardingStepPersistenceTest` round-trip + raw column assert. ArchTest enforcement explicitly OUT of scope (would require enum-constructor-call introspection which ArchUnit 1.4.x does not natively support). |
| **D-C3** | `AttributeConverter` upgrade trigger: when a future enum needs to rename its Java symbol while keeping the DB column value (e.g. `ACCOUNT_CREATED` → `JUST_REGISTERED` while DB stays `"ACCOUNT_CREATED"`) | Document in that enum's class Javadoc. Do NOT preemptively convert — `@Enumerated(STRING)` is fine until the first decoupling need. |
| **D-B3** | `labelKey()` default = `<ClassSimpleName>.<id>` (e.g. `OnboardingStep.GMAIL_CONNECTED`) | Default method body. Frontend i18n bundles (`apps/web/messages/{vi,en}.json`) use this key shape. Override only when default is wrong for some reason. |
| **D-B4** | `fromId(String)` is a per-enum static method (NOT interface-abstract — Java does not allow abstract statics on interfaces). Throws `NoSuchElementException` on unknown id (NOT `IllegalArgumentException`). | Documented pattern with worked example in `IdentifiedEnum` Javadoc. Plan 03 implements the actual `fromId` methods. |

`OnboardingStep` skeleton (Plan 03 implements):
```java
public enum OnboardingStep implements OrderedEnum {
    SIGNED_IN(10), GMAIL_CONNECTED(20), TEMPLATE_SELECTED(30), COMPLETE(40);
    private final int weight;
    OnboardingStep(int weight) { this.weight = weight; }
    @Override public String id() { return name(); }
    @Override public int weight() { return weight; }
    public static OnboardingStep fromId(String id) {
        return Stream.of(values()).filter(e -> e.id().equals(id)).findFirst()
                .orElseThrow(() -> new NoSuchElementException("Unknown OnboardingStep id: " + id));
    }
}
```

`GmailConnectionStatus` skeleton (no `weight()` — status is unordered per D-B5):

## Notes for Future Phases

- The `IdentifiedEnum` / `OrderedEnum` contract is the **lock** for ALL future enums — no Phase 2A/2B/2C/3/4 enum should re-invent the `id()` / `weight()` / `fromId()` pattern.
- If a future enum needs an Integer ID (e.g. an external system's numeric code), introduce a sibling `IdentifiedIntEnum` interface — do NOT retrofit generics onto `IdentifiedEnum` (D-B2 lock).
- The `labelKey()` default format `<ClassSimpleName>.<id>` becomes the i18n bundle key contract — Phase 1.3 frontend (when localized enum strings land) MUST follow this shape in `apps/web/messages/{vi,en}.json`.
- The first time a domain enum needs to be renamed in Java without breaking the DB column value, switch THAT enum to a per-class `AttributeConverter` (D-C3). The trigger is documented in `core/shared/lang/package-info.java` Javadoc.
