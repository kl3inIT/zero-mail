## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] MockMvc cannot drive TenantContext ScopedValue**

- **Found during:** Task 2 GREEN run — initial MockMvc-based tests all returned 409 (`IllegalStateException: No tenant bound on this thread`) instead of 200 / 400.
- **Issue:** `MockMvcBuilders.webAppContextSetup(context).build()` invokes the controller chain but does NOT execute the test-only `OncePerRequestFilter` registered through `TestSessionSupport`'s `testSecurityChain`. That filter is the one that reads `X-Test-Subject` / `X-Test-Email` and invokes `ScopedValue.where(TenantContext.TENANT, ...).run(...)` around the downstream chain. Without it bound, every controller call to `TenantContext.currentOrThrow()` raises `IllegalStateException` → handled → 409.
- **Fix:** Switched both `MeLanguageIntegrationTest` and `LocaleResolutionTest` to the live-Tomcat pattern Phase 1 already established (`@LocalServerPort` + `RestClient.create("http://localhost:" + port)`). The `RestClient` flow goes through the actual servlet filter chain, the test auth filter binds the ScopedValue, and the controller sees the right tenant.
- **Files modified:** `MeLanguageIntegrationTest.java`, `LocaleResolutionTest.java`
- **Commit:** `ac704f4`
- **Note:** This is a worked example for downstream plans (Plan 07 Playwright fixture, future controller tests): if you need TenantContext bound during a test, drive it via `RestClient` + `@LocalServerPort`. MockMvc's standalone setup is fine for tests that fail fast at validation (e.g., `ProblemDetailContractTest`'s rejection-only paths) but cannot reach controller bodies that depend on the ScopedValue.

**2. [Rule 3 — Doc-comment containing `MessageSource` literal]**

- **Found during:** Task 2 acceptance-grep verification.
- **Issue:** The MeController class-level Javadoc contained the phrase "never calls {@code MessageSource}" as a positive statement of the invariant. The acceptance criterion `grep -rn "MessageSource\|getMessage(" ... = 0` is intended to catch ACTUAL imports/calls, but the regex matches the doc text too.
- **Fix:** Reworded the Javadoc to "never resolves localized prose on the server side" — same invariant, no false positive on the grep.
- **Files modified:** `MeController.java`
- **Commit:** `ac704f4`
- **Privacy/safety impact:** none. The behavior was already correct; only the comment changed.
