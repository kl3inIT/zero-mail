```typescript
export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale;
  const locale = hasLocale(routing.locales, requested) ? requested : routing.defaultLocale;
  return {
    locale,
    messages: (await import(`../messages/${locale}.json`)).default,
  };
});
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser cookie store → SSR locale resolution | NEXT_LOCALE cookie chooses which dictionary loads |
| Translation file → rendered DOM | ICU `{var}` placeholders may be exploited if libraries treat them as HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.1.05-01 | Tampering | NEXT_LOCALE cookie tampering forces locale | accept | Locale is non-sensitive; tampering at worst flips display language. Authenticated `/me` overwrite (Plan 06) reasserts server truth on first SSR. |
| T-1.1.05-02 | Information Disclosure | Cookie session-only loses unauth user pref | mitigate | Explicit `localeCookie.maxAge = 31536000` (1y), `sameSite=lax`, `secure=true` per Pitfall 4 — verified by grep on routing.ts |
| T-1.1.05-03 | Tampering | XSS via translation interpolation | accept | next-intl ICU MessageFormat treats `{var}` as literal substitution (no HTML by default); `<RichText>` is opt-in only and not used here |
| T-1.1.05-04 | Information Disclosure | Hydration-time SSR/CSR `<html lang>` mismatch | mitigate | Async layout + `getLocale()` server-side; verified by `grep "lang={locale}"` |
</threat_model>
