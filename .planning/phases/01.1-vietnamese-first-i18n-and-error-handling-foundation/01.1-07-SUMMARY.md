## Deviations from Plan

### 1. [Rule 3 — Blocking] Playwright at workspace root, not apps/web

- **Found during:** Task 2 install (`pnpm --filter ./apps/web add -D @playwright/test`).
- **Issue:** Next.js 16 declares `@playwright/test` as an OPTIONAL peer dep (`peerDependenciesMeta.@playwright/test.optional: true`). When Playwright is installed under apps/web, pnpm creates a second peer-permutation of `next` to satisfy the now-resolvable optional peer. Two physical `next` installs end up on disk: `apps/web/node_modules/next` AND `node_modules/next`. TypeScript sees the two as DIFFERENT type identities (`[Internal]` and `[INTERNALS]` brand markers don't unify), and `proxy.ts` fails to compile because `next-intl/middleware`'s `NextResponse` (resolved through root's `next`) doesn't match `NextResponse` declared at the proxy boundary (resolved through apps/web's `next`).
- **Fix:** Move `@playwright/test` to the workspace ROOT package.json. Add `pnpm.peerDependencyRules.ignoreMissing: ["@playwright/test"]` to root package.json. Wire the apps/web `test:e2e` script to invoke `node ../../node_modules/@playwright/test/cli.js` directly because pnpm's filtered `exec` doesn't pick up workspace-root-hoisted bins from a child workspace's `.bin`.
- **Files modified:** `package.json` (root), `apps/web/package.json` (script change), `pnpm-lock.yaml`.
- **Commit:** rolled into `01ae7b8`.

### 2. [Rule 3 — Blocking] proxy.ts type-bridging cast at NextResponse boundary

- **Found during:** `pnpm exec tsc --noEmit` after deviation 1 was applied.
- **Issue:** Even with Playwright at root and `peerDependencyRules.ignoreMissing` set, the duplicate-`next` install at `node_modules/next` persists (pnpm leaves it because `next-intl` requires `next` as a peer, and the resolution graph branches anyway). TypeScript still produces `TS2345: Argument of type ... NextRequest ... is not assignable to ...` at the proxy.ts handleI18n call site, AND `TS2741: Property '[INTERNALS]' is missing` at the return statement.
- **Fix:** Add type-only `as unknown as Parameters<typeof handleI18n>[0]` cast on the request argument and `as unknown as NextResponse` cast on the response result. Documented inline in proxy.ts with a Plan 07 deviation comment. Runtime is identical — both `NextResponse` identities ARE the same Next implementation under the hood.
- **Carry-forward:** A future plan should add `resolve.dedupe: ['next']` (and possibly `vitest.config.ts` aliases mirroring the React dedupe Plan 06 set up) to fully collapse the duplicate-next identity. Out of scope for Plan 07.
- **Files modified:** `apps/web/proxy.ts`.
- **Commit:** rolled into `01ae7b8`.

### 3. [Rule 1 — Bug] Vitest must exclude __tests__/e2e/**

- **Found during:** Vitest run after Task 2 spec file was created.
- **Issue:** `vitest.config.ts` `include: ['__tests__/**/*.{test,spec}.{ts,tsx}']` matched the new Playwright spec under `__tests__/e2e/`. Vitest's transform loaded the file, and `@playwright/test`'s `test()` threw `Playwright Test did not expect test() to be called here` (Playwright's `test()` requires the Playwright runner context).
- **Fix:** Add `exclude: ['**/node_modules/**', '__tests__/e2e/**']` to vitest config so vitest only runs the unit/component tests it was always intended to run. Playwright runs its own spec discovery via `playwright.config.ts#testDir`.
- **Files modified:** `apps/web/vitest.config.ts`.
- **Commit:** rolled into `01ae7b8`.
