# Phase 1.1 - UI Design Contract

> Visual and interaction contract for Vietnamese-first i18n and frontend-localized API error handling across the existing Phase 1 web surface. This phase localizes and stabilizes messaging only; it must not redesign auth, onboarding, Gmail connection, account deletion, or future Phase 2+ product flows.

---

## Scope Boundary

| Area | Contract |
|------|----------|
| Routes | Preserve unprefixed routes: `/login`, `/onboarding`, `/settings`. Do not add `/vi/*` or `/en/*` route variants. |
| In-scope components | `TemplateCard`, `ConnectionHealthBadge`, `ReconnectPrompt`, `DeleteAccountDialog`, route-level loading/error states, localized metadata, API error displays, and the new `LanguageSwitcher`. |
| Language scope | Exactly `vi` default and `en` secondary. No browser-language auto-detection and no Accept-Language negotiation. |
| Login surface | Existing Google OAuth entry, safety bullets, API/OAuth errors, localized metadata, and compact language switcher. |
| Onboarding surface | Connect Gmail, template-card selection, completion state, loading state, API error state, and compact authenticated language switcher in page chrome if chrome exists. |
| Settings surface | Account, Gmail connection health, reconnect/disconnect, privacy/safety copy, explicit language preference row, delete-account dialog, localized API and field errors. |
| Backend error display | Frontend displays localized messages from `code`, `params`, and `fieldErrors` only. Raw `title`, `detail`, exception names, SQL strings, stack traces, raw Gmail content, prompts, completions, and refresh tokens are never shown. |
| Out of scope | Phase 2+ screens, locales beyond `vi`/`en`, server-localized user prose, JHipster runtime dependencies, full rules CRUD, analytics, billing, drafts, audit logs, and business-flow redesign. |

Sources: `01.1-SPEC.md`, `01.1-CONTEXT.md`, `ROADMAP.md`, `REQUIREMENTS.md`, prior Phase 1 UI contract, `apps/web` route/component scan.

Declared values; all spacing uses multiples of 4px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text gap inside compact controls, badge inner gap |
| sm | 8px | Inline form gaps, switcher item gaps, alert title/body gap |
| md | 16px | Default stack gap, mobile card padding, form-control spacing |
| lg | 24px | Desktop card padding, route header-to-body gap, settings row padding |
| xl | 32px | Page gutters, settings section spacing, onboarding grid gap |
| 2xl | 48px | Major route section separation and centered login vertical rhythm |
| 3xl | 64px | Desktop-only top/bottom page spacing |

Exceptions: interactive controls must meet a 44px minimum hit target even when the visual Base UI button height is 32-36px. This exception applies to compact language-switcher triggers, dialog close buttons, template-card selectable buttons, and destructive dialog actions. OAuth provider logos may be 20px inside a 44px button.

## Typography

Use exactly these four sizes and two weights.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 14px | 600 | 1.4 | Field labels, switcher labels, status metadata, badge text, helper copy |
| Body | 16px | 400 | 1.5 | Default paragraphs, localized error messages, privacy/safety explanation |
| Heading | 20px | 600 | 1.2 | Card titles, route section headings, dialog titles |
| Display | 28px | 600 | 1.15 | Login headline and highest onboarding headline only |

Rules:
- Only weights `400` and `600` are allowed.
- Vietnamese copy must be written in sentence case and tested for line wrapping with diacritics.
- English copy mirrors meaning, not word count; never shrink font size to force bilingual parity.
- Long error and privacy text stays body-sized; do not hide trust-critical content in tiny legal text.

## Visual Hierarchy And Focal Points

| Surface | Primary Focal Point | Secondary Information | What Must Not Compete |
|---------|---------------------|-----------------------|------------------------|
| `/login` | Display headline plus `Sign in with Google` / `Đăng nhập bằng Google` CTA | Safety bullets and compact language switcher | Language switcher must be visible but visually quieter than OAuth CTA |
| `/onboarding` connect step | `Connect Gmail` / `Kết nối Gmail` CTA after consent explanation | Step indicator and privacy reassurance | Do not show dashboard placeholders or future automation claims |
| `/onboarding` template step | Selected template card and `Save starter template` / `Lưu mẫu khởi đầu` CTA | Step indicator and phase-scope note | Template cards must not imply real rule execution is active |
| `/settings` | Gmail connection health and recovery/action row | Account identity, privacy copy, language row | Danger zone must be separated and lower priority until user enters it |
| Error displays | Localized problem statement plus next action | Field-specific inline guidance | Raw server diagnostics, stack traces, SQL names, and exception classes never appear |
| Language preference | Current locale and two-option switcher | Persistence helper copy | It must not look like a global product navigation menu |

Hierarchy rules:
- Each route has one primary CTA in accent at a time.
- Settings may contain multiple actions, but only the recovery action for `DISCONNECTED` may use accent emphasis; destructive actions use destructive styling.
- Alerts sit immediately above or inside the failed section, not at the top of the whole page unless the whole page failed to load.
- Loading skeletons match the final card/row shape to avoid layout shift after locale data and `/me` resolve.

## Language Switcher Contract

| Location | Contract |
|----------|----------|
| `/login` | Compact switcher in the card header or top-right of the auth shell. It shows `Tiếng Việt` / `English` or `VI` / `EN` with an accessible label. It writes `NEXT_LOCALE` only. |
| Authenticated chrome/header | Compact switcher at the top-right of authenticated routes if a shared header exists. It writes cookie immediately and persists through `PATCH /me/language`. |
| `/settings` | Explicit `Language` / `Ngôn ngữ` row near the top of settings, before privacy and danger zone. This row shows current preference, two choices, helper text, save/pending/error state, and success status. |
| Mobile | Same options remain reachable at 320px width with no horizontal scrolling. Use stacked row layout on settings. |

Persistence behavior:
- Supported locales are exactly `vi` and `en`.
- Unauthenticated default is `vi`. `/login` may remember `NEXT_LOCALE` for that browser before auth.
- Authenticated source of truth is `users.preferred_language`.
- Switcher writes `NEXT_LOCALE` immediately for the next SSR pass, then calls `PATCH /me/language`.
- On first authenticated render, if `/me.preferred_language` differs from `NEXT_LOCALE`, the server value wins and overwrites the cookie.
- Unsupported locale values are rejected, the stored preference is unchanged, and the user sees localized error copy.

Routing behavior:
- Configure next-intl routing with `localePrefix: "never"`.
- Middleware/proxy matches unprefixed app routes and excludes API/static/internal paths.
- Root layout is async, gets the active locale from next-intl request context, renders `<html lang={locale}>`, and wraps client components in `NextIntlClientProvider`.
- `generateMetadata` localizes Phase 1 route title and description from dictionaries.

## API Error Localization Contract

Backend shape:
- RFC 7807 `ProblemDetail` remains the transport shape.
- Frontend-localizable extension members are `code`, `params`, and `fieldErrors`.
- `message` may remain for one transitional release as an alias of `code`, but the frontend must not use it for display.
- Field errors are `{ field: string, code: string, params?: Record<string, scalar> }`.

Frontend rendering:
- Look up `code` in `messages/{locale}.json` under the `errors` namespace.
- Pass backend `params` into ICU placeholders after scalar allow-list validation.
- Render field errors adjacent to controls by `field` path.
- For unknown codes, render the localized generic fallback and never expose raw server text.
- Do not display `title`, `detail`, raw `message`, stack traces, exception class names, SQL state/constraint names, raw Gmail content, prompts, completions, refresh tokens, tenant IDs, or unrelated PII.

Required code examples for dictionaries:

| Code | Vietnamese Default | English Secondary |
|------|--------------------|-------------------|
| `error.auth.unauthorized` | `Phiên đăng nhập đã hết hạn. Hãy đăng nhập lại bằng Google.` | `Your session expired. Sign in with Google again.` |
| `error.auth.forbidden` | `Bạn không có quyền thực hiện thao tác này.` | `You do not have permission to perform this action.` |
| `error.auth.currentUserNotFound` | `Không tìm thấy tài khoản hiện tại. Hãy đăng nhập lại.` | `The current account could not be found. Sign in again.` |
| `error.validation.field.preferredLanguage.invalid` | `Ngôn ngữ này chưa được hỗ trợ. Hãy chọn Tiếng Việt hoặc English.` | `This language is not supported. Choose Vietnamese or English.` |
| `error.gmail.disconnected` | `Quyền truy cập Google đã bị thu hồi hoặc hết hạn. Hãy kết nối lại Gmail.` | `Google access was revoked or expired. Reconnect Gmail.` |
| `error.conflict` | `Dữ liệu đã thay đổi trước khi thao tác hoàn tất. Hãy tải lại trang rồi thử lại.` | `The data changed before the action finished. Reload the page and try again.` |
| `error.dataIntegrity` | `Không thể lưu thay đổi vì dữ liệu không hợp lệ.` | `The change could not be saved because the data is invalid.` |
| `error.badRequest` | `Yêu cầu không hợp lệ. Hãy kiểm tra lại và thử lần nữa.` | `The request is invalid. Check it and try again.` |

## Accessibility Contract

| Area | Requirement |
|------|-------------|
| Document language | `<html lang="vi">` by default and `<html lang="en">` after English is active. No hydration mismatch or client-only language correction. |
| Bilingual copy | Vietnamese diacritics must render correctly in Geist Sans; line wrapping must be checked at 320px. |
| Keyboard | Language switcher, template cards, OAuth/connect/reconnect buttons, dialogs, and destructive confirmations are fully keyboard operable. |
| Focus | Visible focus ring uses `var(--ring)`/accent. Focus returns to trigger after dialog close and moves to the invalid field on field errors. |
| Labels | Compact language switcher has an accessible label such as `Chọn ngôn ngữ` / `Choose language`. Icon-only controls require `aria-label` and tooltip/help text if the icon is not obvious. |
| Status announcements | Connection status, language update success/failure, loading completion, and API errors use visible text and `aria-live="polite"` where state changes after a request. |
| Alerts | API and field errors are programmatically associated with the failed section/action. |
| Dialogs | Destructive dialogs use `DialogTitle`, descriptive body copy, focus trap, escape/close behavior, and non-destructive cancel path. |
| Contrast | Text and controls meet WCAG 2.2 AA. Warning/destructive states use text plus color, never color alone. |
| Responsive | `/login`, `/onboarding`, `/settings`, language switcher, and dialogs are usable at 320px width with no horizontal scrolling. |
| Motion | Loading indicators are non-essential and respect `prefers-reduced-motion`. |

## Trust And Safety UX

| Principle | UI Contract |
|-----------|-------------|
| Frontend owns user-facing localization | Server returns stable codes and safe params; browser renders Vietnamese or English. |
| No diagnostic leakage | Raw server diagnostics are not displayed, even when localized lookup fails. |
| Consent clarity | Gmail connection copy explains why access is requested before `Connect Gmail`. |
| No overclaiming | Copy must not imply Phase 1 performs triage, labels, archives, billing, analytics, AI drafting, or production rules execution. |
| Revocation recovery | `DISCONNECTED` is a visible recovery state with one obvious reconnect path. |
| Destructive clarity | Disconnect and delete actions remain separated from routine settings and use explicit confirmation. |
| Privacy posture | Settings keeps localized copy for no auto-send, no long-term raw body/prompt/completion/embedding storage, revoke-anytime, and BYOK planned later. |
