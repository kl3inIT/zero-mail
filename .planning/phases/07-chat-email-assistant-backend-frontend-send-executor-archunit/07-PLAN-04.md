<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → POST /api/chat (long-lived SSE) | TenantContext must propagate; cookie auth verified |
| SseEmitter lifecycle → Reactor Disposable | Mis-wired hooks leak virtual threads + paid LLM tokens after disconnect |
| Reconciliation cron → assistant_pending_action rows | Must rebind TenantContext per row; must respect optimistic CAS |
| Spring AI observation filter → log appender | Default `log-prompt: true` would leak email content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-17 | DoS / Cost | Disconnect leaks subscription + heartbeat task | mitigate | Bind `onCompletion/onTimeout/onError` to `dispose() + future.cancel(false)`; integration test simulates disconnect |
| T-07-18 | Information Disclosure | Spring AI observation logs raw prompts | mitigate | `application.yml` sets `log-prompt: false` AND `log-completion: false`; integration test asserts at runtime |
| T-07-19 | Spoofing | Cross-tenant chat access via guessed chatId | mitigate | Every chat endpoint resolves `TenantContext.currentTenantUuid()` + filters by `chat.tenant_id = tenantId`; 404 (not 403) on tenant mismatch |
| T-07-20 | Tampering | Frontend race — Send before chat_message.parts persisted | mitigate | Orchestrator emits `data-persistence` envelope AFTER `ChatMessageJdbcRepository.save(...)` commits; Wave 5 frontend gates Send on it |
| T-07-21 | DoS | Reconciliation cron runs in worker which isn't exercised v1.1 | mitigate | D-05 lock — cron lives in `backend/api`; single-instance VPS, no ShedLock |
| T-07-22 | Tampering | Confirm endpoint without executor wires up an open hole | mitigate | Wave 3 ships `ConfirmController` shell that returns 501 NOT_IMPLEMENTED; Wave 4 wires executor; ArchUnit + grep gate hold count == 0 until Wave 4 atomic flip |
</threat_model>
