| Boundary | Description |
|----------|-------------|

| Reactor Scheduler thread → TenantContext ScopedValue | Pitfall 5 — wrong scheduler drops tenant binding mid-stream |
| Streaming chunk → tool-call reconstruction | ARCH-07 — Spring AI aggregator returns empty toolCalls |
| Read tool handler → v1.0 backend (rules engine, Gmail reader, sender_safety_entry) | Cross-module call must filter by tenantId at every join |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11 | Information Disclosure | Reactor scheduler drops TenantContext → cross-tenant data | mitigate | `TenantAwareReactorScheduler` wraps every task in `ScopedValue.where(TENANT, capturedTenantId)`; `ChatNoReactorSchedulerTest` ArchUnit rule (Wave 0) bans direct `Schedulers.*` usage |
| T-07-12 | Tampering | Spring AI aggregator returns empty toolCalls → confirmation never fires → silent failure | mitigate | `ChatToolCallRegistry` populates from raw chunks; `ZeroMailChatMemory` replays from DB not from in-memory aggregator |
| T-07-13 | Information Disclosure | Spring AI imports leak outside adapter package | mitigate | `ChatLlmAdapterBoundaryTest` (Wave 0) enforces; `ChatLlmGateway` interface is Spring-AI-free |
| T-07-14 | Tampering | `VercelProtocolEmitter` emits events out of order → `useChat` parses partial JSON → frontend crash | mitigate | `VercelProtocolEmitter` ordering enforcement + unit test sweeps invariants |
| T-07-15 | Spoofing | Read tool returns data from wrong tenant | mitigate | Each handler resolves `TenantContext.currentTenantUuid()` AT call time + filters every query/repo call by tenantId |
| T-07-16 | Information Disclosure | Tool output leaks email body into `chat_message.parts` despite read-only tool | mitigate | All tool outputs route through `SanitizingSink` (wraps `ChatStreamSink` + applies `ToolOutputSanitizer` before persist) |
