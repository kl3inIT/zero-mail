# Phase 5C — UI Design Contract

> Visual and interaction contract for the **authenticated `/analytics` screen**, the **`/settings` Notifications subsection** (opt-out toggle + send-hour selector), and the **daily digest email** (HTML + plaintext, vi + en). Generated by gsd-ui-researcher.
>
> **Inheritance:** This contract inherits Phase 5A's token contract (Geist Sans / Geist Mono / Instrument Serif fonts, paper-warm `--background` neutrals, teal `--primary` `#0E5E5A` light / `#6FB3A8` dark accent, base-nova shadcn preset). Authenticated screens stay on the base teal contract — **never** the `.zm-proto` / `.zm-auth` clay skin. New surfaces are built from raw shadcn `base-nova` primitives bound to existing CSS-variable tokens. Rule of three before wrapping any primitive (project convention).
>
> **Frontend design skill (MANDATORY):** invoke the Anthropic `frontend-design` skill before writing any UI code; pass this rule forward to the planner and into executor subagents touching the analytics route, settings notifications section, or the Thymeleaf digest templates.

## Surfaces in scope

1. **A. `/analytics` page** — authenticated, inside `(protected)/(app)` shell. Four panels (volume, time saved, top-3 senders, per-rule hits) with preset window chips 7d / 30d / 90d.
2. **B. `/settings` → Notifications subsection** — opt-out toggle (`digest_enabled`), send-hour selector (0–23, default 20), read-only time-zone label `Asia/Ho_Chi_Minh` (v1).
3. **C. Daily digest email** — HTML + plaintext, vi or en per tenant `preferred_language`. Subject line, header, prior-day totals, top-3 senders, top-3 rules with applied/reverted, CTA → `/analytics`, footer with `/settings` opt-out link.

## Spacing Scale

Inherits 5A 8-point scale verbatim — **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64**. Tailwind utilities only.

| Token | Value | Usage on this phase's surfaces |
|-------|-------|--------------------------------|
| 2xs | 4px | Icon-to-label gap inside window chips, badge inner padding |
| xs | 8px | Card title to body gap; sender list row gap; rule table cell vertical padding (dense) |
| sm | 12px | Window chip horizontal padding; settings form field internal padding |
| md | 16px | Default gap between sibling sections; panel inner body gap; settings form-field stack gap |
| lg | 24px | `Card` body padding (default); gap between the four analytics panels; settings section padding |
| xl | 32px | Page content gutters (desktop); gap between the panel grid and the rule-hits table |
| 2xl | 48px | Empty-state vertical centering padding inside each panel |
| 3xl | 64px | Page-level top/bottom rhythm |

**Touch targets:** window chips (`Tabs` triggers), send-hour `Select` trigger, and notifications `Switch` all render with a **min 40px hit area** on desktop / **44px on 320px**. Pad the hit area, not the glyph.

**Exceptions:**
- Per-rule table uses **dense row rhythm** (`py-2` ≈ 8px vertical cell padding, ~36–40px row height) at `≥ md` — matches the audit log "evidence-locker" density from 5A. Below `md`, table reverts to card-list renderer with `lg` (24px) padding.
- Digest email uses **wider vertical rhythm**: 24px between sections, 32px above/below the CTA button, 16px around the footer divider. Email clients render compactly by default — extra space prevents the digest looking cramped on Gmail mobile.

## Typography

Inherits 5A's four-size scale verbatim — **12 / 14 / 20 / 28** — no fifth size, no exceptions.

| Role | Size | Weight | Line Height | Usage on this phase |
|------|------|--------|-------------|---------------------|
| Label / small | 12px | 500 | 1.4 | Window chip label, panel eyebrow ("VOLUME" / "TIME SAVED" / "TOP SENDERS" / "RULE HITS" — uppercase, 0.06em tracking), table column headers, "Last refreshed" mono timestamp, settings field labels, mono action-type tag in rule table |
| Body | 14px | 400 | 1.5 | Panel body text, sender row text, rule table cells, settings helper copy, digest-email body |
| Heading | 20px | 600 | 1.25 | Page heading "Analytics" / "Notifications"; section headings inside `/settings`; panel-title card heading inside each of the four panels (e.g. "Volume", "Time saved", "Top senders", "Rule hits") — differentiated from page heading by leading + color (`--muted-foreground` if subordinate, `--foreground` if peer) |
| Display | 28px | 600 | 1.2 | The **headline figure** inside the Volume panel (e.g. `1,247`) and the Time Saved panel (e.g. `4h 12m`). This is the focal element of each panel. Used nowhere else on this phase. |

**Mono (`--font-mono`) usage on this phase:** the per-rule applied/reverted counts in the rule-hits table, the "last refreshed" timestamp under the window chips, the action-type tag (`label` / `archive` / `save_draft`) in the rule table, the digest email's prior-day-totals numbers, the digest's "Hôm qua, … / Yesterday, …" date stamp. Mono renders at the 12px Label step (it is the data variant of the existing 12px size, not a fifth size).

**Serif (Instrument Serif italic):** not used on `/analytics` or `/settings/notifications` (utility surfaces, no headline moments). **Permitted once** in the digest email: a single italicized word in the greeting headline if vi/en parity allows (`"Xin chào, hôm qua bạn đã *hoàn tất* …"` / `"Hi — yesterday you cleared *…*"`). Optional; not required.

**Email-specific weight policy:** digest HTML uses **400 and 600 only** (no 500). Email-client font-weight rendering is unreliable for 500 — collapse to 400.

## Color

60 / 30 / 10 split, reading the existing `--*` tokens from 5A. Authenticated screens stay on the **base teal contract** (`:root` teal `#0E5E5A` / dark `#6FB3A8`).

| Role | Token (light → dark) | Usage on this phase |
|------|----------------------|---------------------|
| Dominant (~60%) | `--background` `#FAFAF7` → `#131312` | `/analytics` and `/settings/notifications` page canvas; digest email body background `#FAFAF7` |
| Secondary (~30%) | `--card` `#FFFFFF` → `#1C1C1A`, `--secondary` / `--muted` `#F1EFE7` → `#232220` | The four panel `Card`s; the rule-hits `Table` row background; the inactive window chips (`Tabs` non-selected); the settings form group container; digest email "content card" background `#FFFFFF`; the email-footer band background `#F1EFE7` |
| Accent (~10%) | `--primary` / `--accent` / `--ring` `#0E5E5A` → `#6FB3A8`; `--accent-soft` `#D6E8E5` → `#1F3A37` | See reserved-for list below |
| Destructive | `--destructive` `#B0413E` → `#DA8480` | Not used on this phase's surfaces — analytics is read-only, settings has no destructive action (opt-out is **not** destructive — it is a reversible preference; uses neutral `Switch`, no red) |
| Warning (secondary semantic) | `--warning` / `--amber` `#B5731F` → `#D9A064` | Reserved for future "digest paused due to repeated bounces" surface — **not implemented in 5C** |
| Success (status only) | `--green` `#2F7D5C` → `#6FB389`; `--green-soft` | Time-saved panel may use a subtle `--green-soft` accent stripe on the headline figure (optional; planner's call within the frontend-design skill) — **not** accent-teal, because "time saved" reads as a small ambient win, not a CTA |
| Info | `--blue` `#2C5BA8` → `#8DA8E0`; `--blue-soft` | Not used |

**Accent reserved for** (explicit — never "all interactive elements"):
- The **selected** window chip in the `Tabs` strip (`7d` / `30d` / `90d` — only one is accent at a time; the other two are neutral `--muted-foreground`).
- The active `/analytics` nav item indicator in the sidebar.
- Focus rings (`--ring`) on the window chips, the `Switch`, and the `Select`.
- The **CTA button** in the digest email body ("Xem chi tiết / View details" → `/analytics`). Accent-teal background, white foreground. Single CTA per email.
- The single inline text link in the digest email footer ("Tắt nhận email / Turn off this email" → `/settings/notifications`). Accent-teal underline-on-hover.
- The "Top sender" rank-1 row's left-edge accent stripe (4px wide, optional) — read as "this one drove the most volume".

**Accent NOT used for:**
- The Display-size headline figures in Volume / Time Saved panels — those render in `--foreground` (with optional `--green-soft` accent stripe for Time Saved). Accent on the figure itself would over-claim.
- The `Switch` "on" state — `Switch` uses its default token (which already maps to `--primary` via shadcn); this is the **only** non-CTA accent use on the settings page and is acceptable because it is the only interactive state-bearing control there.
- Rule-table row backgrounds — neutral only.

**Status colors on this phase:** none. There is no "Connected / Action needed / Disconnected" status visible on `/analytics` or `/settings/notifications`. The chrome health dot from 5A remains in the persistent shell unchanged.

## Visual Hierarchy — Primary Anchor Per Surface

- **`/analytics`** — the **four-panel grid** is the focal area; within the grid, the **Volume** panel's Display-size headline figure is the eye-magnet (top-left in LTR). Window chips above frame it; the rule-hits table below supports it. Chrome and sidebar are peripheral.
- **`/settings` → Notifications subsection** — the **`Switch` toggle row** ("Daily digest email" + state helper text) is the focal element. The send-hour `Select` and the read-only time-zone label sit beneath it as supporting controls. Disabled state when the switch is off: send-hour `Select` greys out (does not vanish — preserves cognitive map).
- **Digest email** — the **prior-day totals row** (volume number + time saved figure, side-by-side at `≥480px`, stacked below) is the focal element. The CTA button is the secondary anchor (top-right of totals row on wide, full-width below on narrow). Top-3 senders + rules are scannable supporting lists. Footer is muted.

## Accessibility Contract

- **Window chips:** rendered as a `Tabs` (`role="tablist"`). Arrow-key navigation between triggers; Home/End jump first/last; selected tab announces on focus via `aria-selected`.
- **Panel headings:** each panel `Card` has an `<h3>` (or aria-labelled section) so screen readers can navigate panel-by-panel.
- **Numbers + abbreviations:** the time-saved figure `Xh YYm` is paired with a screen-reader-only full form via `<span class="sr-only">` (e.g. `4 hours 12 minutes / 4 giờ 12 phút`).
- **Loading state:** an `aria-live="polite"` region announces "Loading analytics… / Đang tải phân tích…" while skeletons render.
- **Tooltips:** all `tooltip` content must also be readable from focused state (keyboard reveal), not hover-only.
- **`Switch`:** native semantics via Radix — label is associated via `htmlFor`/`id`; helper text is associated via `aria-describedby`.
- **`Select`:** Radix `Select` ships keyboard semantics; the disabled state when digest is OFF still announces via `aria-disabled="true"` (not removed from the DOM).
- **Digest email:** plaintext fallback satisfies screen-reader and low-bandwidth email clients. HTML version includes a hidden preheader (`<span style="display:none;...">` with the preview text). All links have descriptive text (no "click here").
- **Color contrast:** all body text on `--background` and `--card` clears WCAG AA 4.5:1 (verified by 5A's Phase 1.6 contrast table). The mono `--muted-foreground` 12px text must be checked against `--card` — if borderline, switch to `--foreground` at 12px or upsize to 14px.
- **Reduced motion:** no decorative animation introduced on this phase. (`Tabs` underline transition is a token default — under 200ms — and respects `prefers-reduced-motion` via shadcn's primitives.)

## Notes for the Planner

- **Single TanStack Query per window** (D-21): `useAnalyticsSummary(window)` returns `{volume, timeSaved, topSenders, ruleHits}` as one typed response. Four panels render off one query — no per-panel fetch, no waterfall. Loading skeletons appear/disappear coherently. Query key = `['analytics', 'summary', window]`. `staleTime` ~60s (analytics doesn't drift second-by-second); no polling.
- **Window chip = URL search param**, not local state. Lets the user share `/analytics?window=30d` and back/forward navigation works. `Tabs.value` binds to `useSearchParams().get('window') ?? '7d'`; on change, `router.replace(?window=...)` with `scroll: false`.
- **Empty-state numbers are real zeros, not em-dashes or "—".** SPEC requires "no NaN, no spinner stuck" — render `0`, `0m`, empty lists. Skeleton → empty state must transition cleanly without flashing a stale value.
- **Settings save is optimistic via 5A's pause-toggle recipe (D-13)** — reuse the `onMutate`/`onError`/`onSettled` shape; mutation cache key = `['notifications', 'preferences']`. No "Save" button; controls are the save trigger.
- **Send-hour `Select` stays mounted when digest is OFF** — disabled state, not unmounted. Avoids layout shift and signals reversibility.
- **Time-zone is NOT user-editable in v1.** Read-only label only. D-14 ships the column with default `Asia/Ho_Chi_Minh`; surfacing a `Select` of all IANA zones is deferred.
- **Digest email uses Thymeleaf fragments** (D-02 planner discretion): `th:fragment="header"`, `th:fragment="footer"`, `th:fragment="totals(volume, timeSaved)"`. The vi/en switch is driven by Spring `MessageSource` (`#{digest.subject(...)}`) — same key namespace as web (`digest.*`). One template file per locale × format (`digest.vi.html.thymeleaf`, `digest.en.html.thymeleaf`, `digest.vi.txt.thymeleaf`, `digest.en.txt.thymeleaf`) OR one template with locale-driven fragments — planner picks. **Plaintext sibling generated from the same model.**
- **Inline CSS only in the digest HTML.** No `<style>` block, no `@import`, no webfont. Use a CSS-inlining step at template render OR write inline `style="..."` attributes directly. Tested against Gmail web, Gmail mobile (iOS + Android), Apple Mail iOS, Outlook web — Outlook desktop is best-effort (no `flex`, no `grid` — use `<table>` for two-column totals row).
- **CTA URL carries a `?source=digest` tracking param** so analytics page-side `event_source` instrumentation can attribute incoming traffic to the digest funnel (Phase 6+ telemetry; this is a forward-compatible hook, not a v1 telemetry requirement).
- **Opt-out link goes to `/settings?section=notifications`** (or `/settings/notifications` if the planner routes the subsection) — the URL is stable + bookmarkable.
- **Authenticated screens never use the `.zm-proto` / `.zm-auth` clay skin** — base teal token contract only. Don't import or apply those classes.
- **Frontend-design skill is mandatory** — invoke before writing UI; pass forward to executor subagents. Icon choices, micro-layout, skeleton exact shapes, and the optional accent stripe on rank-1 sender are left to the skill within everything above.
- **HTML prototype:** the planner can reference `05C-PROTOTYPE.html` (sibling file) as the visual ground truth for the three surfaces — it locks the exact spacing, typography rhythm, and accent reservation.
