<objective>
Wave 3 frontend slice for Phase 10. Backend pairing UX (`POST /api/integrations/telegram/pairing`, `GET /api/integrations/telegram/status`, `POST /api/integrations/telegram/disconnect`) is delivered by Plan 06; this plan consumes that surface and delivers the user-facing portion of TG-08 (pairing UX) + TG-09 (status read) + TG-15 (REST surface consumed FE-side).

Scope:
1. Feature module `apps/web/features/telegram-integration/` — typed API wrappers, TanStack query keys, three hooks (status read with conditional polling, start-pairing mutation, disconnect mutation), TelegramCard + ConnectDialog components, vi/en messages bundle.
2. New Next.js sub-route `apps/web/app/(protected)/(app)/settings/connected-apps/page.tsx` hosting `<TelegramCard />`. `SettingsClient.tsx` gains exactly ONE new nav-entry pointing to the sub-route (Task 9) — TG-18; the rest of the Settings card grid is untouched.
3. OpenAPI types regeneration — explicit step that boots the backend (Plans 03/06 must have shipped first) and runs `pnpm --filter web run generate:api`, committing `apps/web/lib/api/schema.d.ts`.
4. Playwright happy-path spec at `apps/web/e2e/telegram-pairing.spec.ts` (Wave 0 skeleton fill: Connect → fake pairing → polling flip to CONNECTED → Disconnect).
5. Operator runbook at `docs/integrations/telegram-setup.md` covering BotFather, env vars, `setWebhook` invocation with `secret_token`, smoke test, troubleshooting.

Hard constraints encoded in must_haves above:
- NO hand-written DTO mirrors — types come from `apps/web/lib/api/schema.d.ts`.
- NO `toast.success` / `toast.error` calls in hooks/components — use `meta.successMessage` / `meta.errorMessage` (CLAUDE.md §11).
- NO hex colors — semantic tokens only (CLAUDE.md §11).
- NO emoji in code, docs, or any committed artifact.
- shadcn primitive check first (CLAUDE.md §7); install only if missing.
- 401 redirect already handled by fetch-layer middleware in `apps/web/lib/api/client.ts` — do NOT add per-callsite 401 handling.
- Vietnamese first in `messages.ts` (project default locale per existing `apps/web/features/ai/messages.ts`).
- Playwright spec lives ONLY under `apps/web/e2e/**` (CLAUDE.md §8).
- Threat T-10-08 (pairing code phishing): mitigated by short backend TTL (10min) + single-use idempotent consume, both owned by Plan 06; FE additionally renders an 8-minute countdown so users see expiry approaching and never copy a stale code. Threat T-10-15 (stale status leak): mitigated by `invalidateQueries({ queryKey: telegramQueryKeys.all })` on disconnect mutation success and dialog close.

Purpose: A real user opens `/settings/connected-apps`, sees a Telegram card, clicks Connect, scans the QR or taps the deep-link, sends `/start <code>` to the bot, watches the dialog auto-close, and ends up looking at a connected card. This is the single user-facing thread that turns Phase 10's backend infrastructure into a shippable feature.

Output: Connected-apps sub-route + Telegram card + Connect dialog + happy-path e2e + operator runbook. Wave 3 Plan 09 already covered the streaming chat sink (no FE for chat — chat lives inside Telegram itself).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → backend REST | User session cookie crosses here; mutations carry XSRF token via fetch-layer middleware (CLAUDE.md §11 admin client parity). The three Telegram endpoints follow the existing user-session SecurityFilterChain — no new auth surface introduced FE-side. |
| backend → Telegram (`t.me/<bot>?start=<code>`) | The pairing deep-link surfaces a one-time signed code in the URL; the URL is briefly visible in the user's browser, in `<img>` decoder logs, and (if the user copies it) in clipboard history. Mitigated by short TTL + single-use idempotent consume — both owned by Plan 06; this plan reinforces by displaying an 8-minute countdown so users see expiry approaching. |
| browser polling → cached status | Once the user disconnects, a stale `connected: true` entry in the TanStack Query cache would mislead the UI into rendering the connected state. Mitigated by `invalidateQueries({ queryKey: telegramQueryKeys.all })` in the `useDisconnect` mutation's `onSuccess` — explicitly closes T-10-15. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-08 | Spoofing / Information Disclosure | `ConnectDialog` (pairing code surfaced in deep-link + QR) | mitigate | Backend TTL 10min (Plan 06); FE displays an 8-minute countdown capped via `min(remaining, 8 * 60)` so users see expiry approaching and never copy a stale code. Deep-link `<a>` uses `rel="noopener noreferrer"` to prevent referrer leakage to `t.me/`. The pairing code is consumed single-use idempotently (backend `INSERT ... ON CONFLICT` per TG-08); a phished code that has already been consumed returns "Đã kết nối từ trước" instead of granting a second tenant access.
