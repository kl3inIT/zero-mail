# Plan 01-08 Summary — Next.js frontend + FND-06 end-to-end codegen

## What was built

### Workspace (3 root files)
- `pnpm-workspace.yaml` — registers `apps/*`.
- `package.json` — root workspace package with `web:dev`, `web:build`, `generate:api` proxy scripts; pinned `packageManager: pnpm@10.33.2`.
- `turbo.json` — task graph for build/dev/generate:api.

### Next.js scaffold (`apps/web/`, scaffolded via `create-next-app@16.2.4` then customized)
- `package.json` — name `zeromail-web`; deps Next 16.2.4, React 19.2.4, TanStack Query 5.100.1, openapi-fetch 0.17.0; devDeps openapi-typescript 7.13.0, tsx, Tailwind 4. Added `generate:api` script.
- `app/layout.tsx` — wraps tree in `<QueryProvider>`; metadata `Zero Mail`.
- `app/page.tsx` — server-side `redirect("/login")`.
- `app/login/page.tsx` — UI-SPEC copy verbatim, "Sign in with Google" CTA pointing to `/oauth2/authorization/google` on the backend.
- `app/onboarding/page.tsx` — 4-state dispatcher on `users.onboarding_step`: `SIGNED_IN` (Connect Gmail form posting to `/tenant/connect-gmail`), `GMAIL_CONNECTED` (3 `<TemplateCard>`s + Save button), `TEMPLATE_SELECTED` (Continue to settings), `COMPLETE` (redirecting placeholder).
- `app/settings/page.tsx` — sections: Account, Gmail connection, Privacy & safety (WEB-03 in spirit), Danger zone (Disconnect + Delete dialog).
- `proxy.ts` — Next 16's renamed `middleware.ts` convention (the plan's old name is deprecated). Redirects unauthenticated `/onboarding/*` and `/settings/*` requests to `/login` based on `ZEROMAIL_SESSION` cookie.
- `lib/api/client.ts` — `openapi-fetch createClient<paths>()` with `credentials: include`; exports `xsrfHeader()` helper that reads the readable `XSRF-TOKEN` cookie and emits `X-XSRF-TOKEN`.
- `lib/api/schema.d.ts` — **regenerated by Task 3** from the live `/v3/api-docs`; all 7 Phase 1 operations + `MeResponse`, `TenantStatusResponse`, `SelectTemplateRequest` typed.
- `lib/query-client.tsx` — `"use client"` `<QueryClientProvider>` wrapper.
- `scripts/generate-api.ts` — tsx script that fetches the live spec to `apps/web/openapi/spec.json` and runs `openapi-typescript` → `lib/api/schema.d.ts`.
- `.env.local.example` — `NEXT_PUBLIC_API_BASE`, `API_SPEC_URL`.

### shadcn/ui components (added via `pnpm dlx shadcn@latest add ...`)
`button, card, alert, input, badge, dialog, skeleton, separator` — Base UI under the hood (`@base-ui/react`), not Radix.

### Phase 1 components (4 files)
- `components/ConnectionHealthBadge.tsx` — `Badge` with variants for `CONNECTED | DISCONNECTED | NOT_CONNECTED | PENDING`; `aria-live="polite"`.
- `components/TemplateCard.tsx` — selectable card button with `aria-pressed`.
- `components/ReconnectPrompt.tsx` — amber `Alert` + Reconnect button; renders for the DISCONNECTED state per UI-SPEC.
- `components/DeleteAccountDialog.tsx` — typed-phrase confirmation (`delete my data`), uses Base UI Dialog's `render` prop pattern.

### FND-06 end-to-end verification
- `scripts/verify-codegen.sh` — bash script that:
  1. Brings up `zero-mail-postgres-1` + `zero-mail-redis-1` via docker compose (with a temp `DOCKER_CONFIG` to bypass the missing `docker-credential-desktop` helper on Git-Bash-on-Windows).
  2. Boots `:backend:api:bootRun` in the background with stub `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, and 32-zero-byte AES key (so OAuth2 client autoconfig validates without ever calling Google).
  3. Polls `/actuator/health` (default 180s timeout) until UP.
  4. Runs `pnpm -C apps/web generate:api` against the live spec.
  5. Asserts every Phase 1 path appears in the regenerated `apps/web/lib/api/schema.d.ts`, plus the `auto-generated by openapi-typescript` banner is present (proves real codegen ran, not a placeholder).
  6. Tears down the api pid on EXIT.
