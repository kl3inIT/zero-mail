  4. `backend/core/src/main/java/com/zeromail/core/privacy/SensitiveMarkerScrubFilter.java` — per RESEARCH Topic 10 but with a `ThreadLocal`-free recursion guard (use `Scope`-local via static `volatile boolean` is wrong; use per-thread via Logback's own `scrubbed` MDC check). Simpler implementation: scan + mutate via a copy + emit via the root logger with recursion guard using a single concurrent map keyed by thread id is still ThreadLocal. **The cleanest safe pattern allowed by the ArchUnit rule is to return FilterReply.NEUTRAL but replace the arguments via a side-effect-free transform**. Use the `JsonProvider` approach per RESEARCH Topic 10's "Simpler alternative" — avoids recursion entirely:

     Actually simplest and ArchUnit-safe: implement as a `TurboFilter` but do NOT re-log from within it. Instead, mutate the MDC and replace the `params` array contents to redact before logback renders the message. If the TurboFilter API does not permit mutating params, fall back to: FilterReply.NEUTRAL + rely on `Sensitive.toString()` alone (which already redacts). Because `Sensitive.toString()` already returns `***REDACTED***`, the TurboFilter's job is only to catch the rare case where someone passed `new Sensitive<>(...)` through a formatter that bypassed `toString()` (e.g., a custom `{}` placeholder resolver). Implementation:
     ```java
     package com.zeromail.core.privacy;
     import ch.qos.logback.classic.Level;
     import ch.qos.logback.classic.Logger;
     import ch.qos.logback.classic.turbo.TurboFilter;
     import ch.qos.logback.core.spi.FilterReply;
     import org.slf4j.MDC;
     import org.slf4j.Marker;
     import org.slf4j.helpers.MessageFormatter;
     public class SensitiveMarkerScrubFilter extends TurboFilter {
         private static final String TOKEN = "Sensitive(";
         private static final String REDACTED = "[REDACTED](";
         @Override
         public FilterReply decide(Marker marker, Logger logger, Level level,
                                    String format, Object[] params, Throwable t) {
             if (format == null) return FilterReply.NEUTRAL;
             String rendered = MessageFormatter.arrayFormat(format, params).getMessage();
             if (rendered == null || !rendered.contains(TOKEN)) return FilterReply.NEUTRAL;
             MDC.put("scrubbed", "true");
             MDC.put("scrub_reason", "sensitive_marker");
             // Rewrite by mutating the passed `params` array in place so downstream formatter renders the scrubbed content.
             if (params != null) {
                 for (int i = 0; i < params.length; i++) {
                     if (params[i] != null && params[i].toString().contains("Sensitive(")) {
                         params[i] = params[i].toString().replace(TOKEN, REDACTED);
                     }
                 }
             }
             return FilterReply.NEUTRAL;
         }
     }
     ```
     This avoids the recursion issue (no re-log from within the filter). MDC is cleaned up by logback after the event is emitted; add an `@AfterEach` in tests to call `MDC.clear()` to prevent bleed between tests.

  ```java
  package com.zeromail.core.arch;
  import com.tngtech.archunit.core.domain.JavaClass;
  import com.tngtech.archunit.core.importer.ImportOption;
  import com.tngtech.archunit.junit.AnalyzeClasses;
  import com.tngtech.archunit.junit.ArchTest;
  import com.tngtech.archunit.lang.ArchCondition;
  import com.tngtech.archunit.lang.ArchRule;
  import com.tngtech.archunit.lang.ConditionEvents;
  import com.tngtech.archunit.lang.SimpleConditionEvent;
  import java.util.Set;
  import static com.tngtech.archunit.lang.syntax.ArchRuleDefinition.*;

  @AnalyzeClasses(packages = "com.zeromail", importOptions = ImportOption.DoNotIncludeTests.class)
  public class SafetyContractArchTests {
      private static final String SENSITIVE = "com.zeromail.core.privacy.Sensitive";
      private static final Set<String> DENY = Set.of(
          "body", "bodyText", "prompt", "completion", "rawContent", "refreshToken", "accessToken");
      private static final String DENY_REGEX = String.join("|", DENY);

      @ArchTest
      static final ArchRule sensitive_names_wrapped =
          fields().that().haveNameMatching(DENY_REGEX)
              .should().haveRawType(SENSITIVE)
              .because("FND-03/04: deny-listed names must be Sensitive<T>");

      @ArchTest
      static final ArchRule no_sensitive_in_logger =
          noClasses().should(new ArchCondition<JavaClass>("pass Sensitive to Logger") {
              @Override public void check(JavaClass item, ConditionEvents events) {
                  item.getMethodCallsFromSelf().forEach(call -> {
                      if (!call.getTargetOwner().isAssignableTo("org.slf4j.Logger")) return;
                      boolean passesSensitive = call.getTarget().getRawParameterTypes().stream()
                          .anyMatch(t -> t.getName().equals(SENSITIVE));
                      if (passesSensitive) {
                          events.add(SimpleConditionEvent.violated(call,
                              "Logger call at " + call.getSourceCodeLocation() + " passes a Sensitive value"));
                      }
                  });
              }
          });
  }
  ```

  Note on rule (d): ArchUnit cannot reliably resolve actual argument types at call sites (only declared parameter types of the called method). Logger.info accepts `Object...` so the declared-parameter path finds nothing. The practical version uses `getRawParameterTypes()` on the overload — it catches the case where a custom logger method explicitly declares a `Sensitive` parameter, plus a fallback via a parameterless scan. For call-site argument resolution, a later hardening pass may replace this with a bytecode scan; for Phase 1, the combination of `Sensitive.toString()` + the TurboFilter + the deny-list field rule (e) gives defense-in-depth. Document this limitation in a `// NOTE:` comment inside the test class.
