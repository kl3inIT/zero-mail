## Frontend-Design Skill Invocation Log

The `frontend-design` skill (per persistent user feedback memory + Phase 01.4 CONTEXT D-Discretion: "frontend-design skill MUST be invoked by every executor before authoring or refactoring any TSX") was loaded at execution start. The skill's directives translated to this plan's aesthetic decisions:

- **Refined-minimalist direction (continuing Plan 04/05 precedent).** This is a consistency sweep, not a brand expression — restraint, precision, and token discipline rule the contract:
  - Color: 60/30/10 mapped onto neutral preset; every className uses tokens (`text-foreground`, `text-muted-foreground`, `bg-muted`, `border-border`, `border-destructive/30`). Zero raw color literals across `apps/web/{app,features}` className strings.
  - Typography: 4 sizes (16/14/20/30) + 2 weights (400/600); landing H1 escalated `text-2xl font-semibold` → `text-3xl font-semibold tracking-tight` to match UI-SPEC §Typography "Display"; docs index heading similarly normalized.
  - Spacing: PageShell variant per surface locks the container width contract (auth=max-w-md, app=max-w-3xl, marketing=max-w-5xl, docs=max-w-3xl). Internal spacing flows from PageShell + SectionCard rhythm; no ad-hoc `mx-auto max-w-*` wrappers remain.
  - Composition: `<Card><h2>...` replaced by `<SectionCard heading={t(...)}>` across `/settings`, `/onboarding`, `/login`. ReconnectPrompt collapses from a hand-crafted Alert into a 4-line StatusAlert wrapper.
  - Motion: zero — sweep is pure render. Animation lives only inside Plan 04 LoadingState (`animate-pulse` from shadcn Skeleton).
- **Differentiation through cohesion, not novelty.** Each refactored surface sits inside the existing shadcn neutral preset's visual language; the deliverable is consistency across 9 files, not brand expression (Phase 5 owns the brand finalize).
- **Single-account note as confident-not-apologetic copy.** The `settings.gmailConnection.singleAccountNote` footer (D-D5) sets v1 expectation forward-looking ("Multi-account support is on the roadmap") rather than apologizing for a limitation.

The skill's discipline applied to skeleton structure as well as polish — every spacing/typography/color decision was checked against UI-SPEC §Spacing/Typography/Color before write.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] @base-ui/react/button useRef null-dispatcher when onboarding test renders full page**

- **Found during:** Task 1 first vitest run on `onboarding-error.test.tsx`.
- **Issue:** The onboarding page's 3 `<Button>` instances (connect-cta, save-template-cta, completion-cta) and the form-submit Button all wrap `@base-ui/react/button`'s `Button` primitive. Under vitest's React-dedupe configuration, that primitive's internal `useRef` hits a null hooks dispatcher (separate React module instance — same root cause as the Plan 04 StatusAlert / EmptyState findings). All 5 onboarding-error tests failed with `TypeError: Cannot read properties of null (reading 'useRef')` at `useButton`.
- **Fix:** Replaced `<Button type="submit">{...}</Button>` with `<button type="submit" className={cn(buttonVariants())}>{...}</button>` and the same pattern for the other 2 Button uses. The DOM contract is identical (`role="button"` + `onClick`), and `buttonVariants()` preserves the styling contract exactly. Same precedent as Plan 04 StatusAlert (deviation #3 in 01.4-04-SUMMARY.md) and LanguageSwitcher.
- **Files modified:** `apps/web/app/(protected)/onboarding/page.tsx`.
- **Commit:** `0771dc7`
