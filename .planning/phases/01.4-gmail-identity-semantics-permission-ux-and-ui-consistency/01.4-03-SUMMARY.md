### Task 1 — `GmailConnectionService.upsert(...)` body (commit `d9f92a1`)

**`backend/core/src/main/java/com/zeromail/core/gmail/service/GmailConnectionService.java`**

Thay forward-decl stub `throw new UnsupportedOperationException("Plan 01.4-03 lands implementation")` bằng body theo D-A4:

```java
@Transactional
public void upsert(UUID tenantId, String googleEmail, String scopesGranted, byte[] refreshTokenEncrypted) {
    GmailConnectionEntity row = connections.findByTenantId(tenantId)
            .orElseGet(() -> new GmailConnectionEntity(
                    UUID.randomUUID(), tenantId, googleEmail, GmailConnectionStatus.CONNECTED));
    row.setStatus(GmailConnectionStatus.CONNECTED);
    row.setRefreshTokenEncrypted(refreshTokenEncrypted);
    row.setScopesGranted(scopesGranted);
    row.setConnectedAt(Instant.now());
    row.setDisconnectedAt(null);
    connections.save(row);
}
```

**Contract chính (locked theo D-A4):**

| Phần tử | Hành vi |
|---------|---------|
| Nếu row tồn tại cho `tenantId` | UPDATE in-place; signature gọi `setStatus / setRefreshTokenEncrypted / setScopesGranted / setConnectedAt / setDisconnectedAt` |
| Nếu chưa có row | INSERT row mới qua constructor `(UUID.randomUUID(), tenantId, googleEmail, CONNECTED)` rồi setters cho các trường còn lại |
| `googleEmail` trên path UPDATE | KHÔNG ghi (subject check ở Plan 02 đã guarantee equality post-A1 — RESEARCH Q4) |
| `disconnectedAt = null` | Reset bắt buộc — re-grant sau disconnect phải xóa timestamp cũ (yêu cầu rõ ràng D-A4) |
| `connectedAt = Instant.now()` | Set trên CẢ 2 path — D-A4 contract |
| Transaction | `@Transactional` default propagation (REQUIRED) — join caller's tx; caller (Plan 02 `GmailOAuthSuccessHandler`) bind `TenantContext.TENANT` ScopedValue trước khi gọi (Pitfall 6 / FND-05) |
| Optimistic lock | `version` + `updated_at` được auditing listener (Phase 1.2.1) cập nhật tự động qua `save` |
| Privacy | KHÔNG có `log.X(...)` reference `googleEmail / scopesGranted / refreshTokenEncrypted` (T-1.4-03-token-leak / D-E1) |

**Import thêm:** `com.zeromail.core.gmail.persistence.GmailConnectionEntity` (đã có sẵn qua repo type tham chiếu, được explicit-import cho `orElseGet` lambda).

### Task 3 — Test scaffold repair `GmailOAuthSuccessHandlerIntegrationTest` (commit `28cba82`)

**`backend/api/src/test/java/com/zeromail/api/security/GmailOAuthSuccessHandlerIntegrationTest.java`**

2 scaffold issue Plan 02 SUMMARY đã flag, sửa cả hai:

**(a) Mock injection issue** — Plan 01 scaffold tạo `mock(OAuth2AuthorizedClientService.class)` LOCAL trong helper `stubAuthorizedClient(...)` rồi không wire — handler bean autowired default `InMemoryOAuth2AuthorizedClientService` của Spring Boot, không thấy mock local nên `loadAuthorizedClient(...)` trả null → NPE tại `authorizedClient.getRefreshToken()`.

**Fix:** Thêm inner static `@TestConfiguration MockAuthorizedClientServiceConfig` expose `@Primary @Bean OAuth2AuthorizedClientService = Mockito.mock(...)`. `@Import` vào test class. Sửa `stubAuthorizedClient(...)` để gọi `when(authorizedClientService.loadAuthorizedClient(...))` trên mock đã được autowire (cùng instance handler nhận qua DI), không tạo local mock nữa.

**(b) Tenant binding issue** — Test gọi `users.findById(seed.userId()).orElseThrow()` / `connections.findByTenantId(...)` post-throw NGOÀI ScopedValue → bị `@TenantId` filter chặn → `NoSuchElementException`. Cùng root cause với scaffold của `GmailConnectionServiceUpsertTest`.

**Fix:** Wrap toàn bộ assertion-side JPA reads trong `ScopedValue.where(TenantContext.TENANT, tenantId).run(...)`. Cho `idempotentReGrant` test (cần capture first-grant state để compare với second-grant), dùng single-element holder arrays (`UUID[1]`, `Integer[1]`, `Instant[1]`) vì lambda-captured locals phải effectively final.

**Implementation impact:** ZERO. Handler implementation từ Plan 02 vẫn đúng theo D-A1 / D-A4 contract — chỉ là test scaffold sai nên không thấy được. 3 RED → 3 GREEN.
