## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, alert icon/text gaps |
| sm | 8px | Compact control gaps, badge/button internal gaps |
| md | 16px | Default element spacing, card body rhythm |
| lg | 24px | Section padding, default page padding on mobile |
| xl | 32px | Desktop page padding, card-to-card gaps |
| 2xl | 48px | Major section breaks and centered auth vertical rhythm |
| 3xl | 64px | Top-level public page rhythm only |

Exceptions: none. Minimum pointer target size is 44px for compact/icon triggers, but it is a component dimension, not a layout spacing token.

Layout rules:
- `PageShell` owns page max width and responsive horizontal padding. Pages must not repeat `mx-auto max-w-* p-*` directly.
- `SectionCard` owns card padding. Feature pages must not use raw `<Card className="p-6">` once the primitive exists.
- Repeated vertical page sections use `space-y-6` or `gap-6` only through `PageShell`/`SectionCard` composition.

## Typography

Use exactly four UI sizes and two weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / metadata | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.25 |
| Page title / auth headline | 28px | 600 | 1.2 |

Rules:
- Allowed weights are regular `400` and semibold `600`; do not introduce medium, bold, or extra-bold in Phase 1.4.
- No viewport-scaled font sizes and no negative letter spacing.
- Vietnamese and English copy must fit the same components without truncation; prefer wrapping over smaller text.

## Color

Phase 1.4 defines retunable structure, not final brand identity. Token names matter more than exact hue values, but executors must avoid a one-note all-neutral UI by giving the working accent a specific job.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background: oklch(0.99 0.005 250)` | Page background and quiet empty space |
| Secondary (30%) | `--card`, `--muted`: oklch near 0.96-0.98 | Cards, headers, section bands, skeleton surfaces |
| Accent (10%) | `--primary: oklch(0.48 0.15 250)` | Primary Gmail CTA, selected onboarding template ring, active public nav link, focus ring |
| Destructive | `--destructive: oklch(0.58 0.22 25)` | Disconnect Gmail and delete account actions only |

Accent reserved for: `Connect Gmail`, retry/error recovery CTAs, selected onboarding template state, active navigation, and keyboard focus. It is not for every link, every icon, or all hover states.

Semantic status colors:
- Info: neutral/blue-tinted surface with `text-foreground`.
- Success: green-tinted surface only for connected/success states.
- Warning: amber-tinted surface only for revoked/attention states.
- Error: destructive-tinted surface only for identity mismatch, consent denied, and error-boundary fallbacks.

Hard bans for touched JSX:
- `text-stone-*`, `text-gray-*`, `bg-white`, `border-red-*`, `bg-amber-*`, and similar raw palette utilities.
- Use token-aware classes instead: `text-foreground`, `text-muted-foreground`, `bg-background`, `bg-card`, `border-border`, `text-destructive`, `ring-primary`.

## Visual Hierarchy

Primary focal points:
- `/onboarding`: if `?error=gmail_identity_mismatch` or `?error=gmail_consent_denied` is present, the top `StatusAlert variant="error"` is the first focal point. Otherwise the active onboarding step `SectionCard` is the focal point.
- `/settings`: the Gmail connection `SectionCard` is the first focal point, followed by privacy and danger-zone sections.
- `/login`: the auth card headline and Google sign-in CTA are the only visual anchors; safety bullets remain secondary.
- Public landing/docs: keep the current scaffold quiet and utilitarian. Do not introduce final marketing hero art, decorative gradients, or brand illustrations in Phase 1.4.

Component hierarchy:
- `PageShell` wraps page content.
- `SectionCard` frames a single logical section with heading, optional description, and body.
- `StatusAlert` handles inline info/success/warn/error states.
- `EmptyState` handles 404 and future empty lists.
- `LoadingState` handles page-level skeletons and route `loading.tsx`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Connect Gmail` / `Kết nối Gmail` |
| Retry CTA | `Try again` / `Thử lại` |
| Settings reconnect CTA | `Reconnect Gmail` / `Kết nối lại Gmail` |
| Empty state heading | `Page not found` / `Không tìm thấy trang` |
| Empty state body | `This page does not exist or you no longer have access. Go back home to continue.` / Vietnamese equivalent with the same meaning |
| Error state | Identity mismatch: `Use the same Google account you signed in with. Zero Mail v1 supports one Gmail account for this workspace.` Consent denied: `Gmail access was not granted. Connect Gmail to continue setup.` |
| Destructive confirmation | `Disconnect Gmail`: require an explicit confirmation dialog or inline confirmation before revoking access. `Delete account and data`: keep typed phrase confirmation `delete my data`. |

Copy rules:
- No generic CTA labels such as `Submit`, `OK`, or `Save`.
- User-facing copy must come from `apps/web/messages/vi.json` and `apps/web/messages/en.json`, except `app/global-error.tsx`, which is an English-only last-resort fallback because it replaces the root layout and cannot rely on the next-intl provider.
- Do not render `error.message`, `error.stack`, Google subject, email, OAuth token content, raw email body, prompt, or completion in any user-visible state.
- Add keys for `errors.boundary.*`, `errors.notFound.*`, `gmail.identity.mismatch.*`, `gmail.consent.denied.*`, and `settings.gmailConnection.singleAccountNote`.

## Phase-Specific Interaction Contracts

### Gmail Permission Errors

- `/onboarding` reads only the allow-listed query values `gmail_identity_mismatch` and `gmail_consent_denied`.
- Unknown query values are ignored and must not be rendered.
- The error renderer is a small client component using `useSearchParams()` and must sit under a `Suspense` boundary if the parent route is statically prerendered.
- Dismissal clears the query with `router.replace('/onboarding', { scroll: false })`. The URL is static and must not be assembled from untrusted input.
- The retry CTA reuses the existing `/tenant/connect-gmail` flow.

### Settings Gmail Card

- Show one Gmail connection only. Do not add "add another account", disabled multi-account stubs, workspace UI, or coming-soon badges.
- Add footer note: `Zero Mail v1 supports one Gmail account, the email you logged in with. Multi-account support is on the roadmap.` with Vietnamese equivalent from `settings.gmailConnection.singleAccountNote`.
- `ConnectionHealthBadge` remains badge-shaped and only retokens colors.

### Error Boundaries

- Add `app/global-error.tsx`, `app/(public)/error.tsx`, `app/(auth)/error.tsx`, `app/(protected)/error.tsx`, and `app/not-found.tsx`.
- Error boundaries are client components. The installed Next.js 16.2.4 docs expose `unstable_retry()` for recovery and still document `reset()` as a lower-level state reset; use the recovery callback exposed by the local type signature, preferring `unstable_retry()` when available.
- `global-error.tsx` must include its own `<html>` and `<body>` and use minimal inline fallback styling plus English-only copy.
- Segment `error.tsx` files render `SectionCard + StatusAlert + recovery button`.
- Root `not-found.tsx` renders `PageShell + EmptyState + Back home` link.
