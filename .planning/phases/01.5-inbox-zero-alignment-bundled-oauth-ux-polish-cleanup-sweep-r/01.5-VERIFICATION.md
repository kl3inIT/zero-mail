### Gaps Summary

Phase 01.5 ships the bundled-OAuth migration substantively but with **four BLOCKER-grade defects** that prevent must_have #2, #3, and #5 from being achieved:

1. **The atomic single-transaction promise is broken on the race-loser code path** (must_have #2). Under concurrent first-login from the same Google subject, the loser thread opens a SECOND transaction after the first rolled back — exactly the half-provisioned state the HIGH-1 fix was supposed to eliminate.

2. **The reconnect UX is wired but unreachable in production** (must_have #3). The settings POST form has no CSRF token (Spring will 403 it), the DISCONNECTED button uses GET against a POST-only endpoint (will 405), and the failure-handler cleanup of partial AuthorizedClients runs under `"anonymous"` so it never matches.

3. **The CLAUDE.md "No GCP starters" lock is violated** (must_have #5). The cleanup sweep (Plan 05) updated STATE.md ceremony language to be deployment-secret-source-agnostic, but did not remove the offending Gradle dependency or the dead `sm://` placeholder from application.yml — which was the explicit point of HIGH-6 / CR-04.

Three deferred items are correctly scoped to later phases (Pub/Sub OIDC ceremony, key rotation drill, prod cookie override) — these are NOT gaps.

Recommended next plan focus (for `/gsd-plan-phase --gaps`):
- **Group A (atomicity):** Fix `OAuthProvisioningService.provisionBundledOAuth` race-loser branch — remove the second-tx upsert OR guard it with an existence check. Add a concurrency test that exercises the race path.
- **Group B (reconnect surface):** Pick a CSRF-safe shape (recommended: GET + `<a>` link, mirroring the login-page pattern). Update `ConnectGmailController`, settings page, and ReconnectPrompt together. Optionally fix the `currentPrincipalName` → `token.getName()` cleanup in the success handler.
- **Group C (stack lock):** Remove `spring-cloud-gcp-starter-secretmanager` from `build.gradle.kts:18`. Replace `sm://` placeholder in `application.yml:73` with a `:?` fail-fast required-env-var pattern. Drop `spring.cloud.gcp.secretmanager.enabled` from application.yml. OR explicitly amend CLAUDE.md to override the "No GCP" lock if the team wants to keep the starter.
