## Claude's Discretion

- **Frontend primitive deflation Q1** — User said "you decide" on which of the 5 Phase 01.4 primitives die/stay. Claude applied rule-of-three + composition test from `feedback_raw_shadcn_first` memory and chose to deflate all 5. Captured in CONTEXT.md `<decisions>` section D-C1.
- **Spring Security 7 runtime resolver branching pattern** — How exactly to toggle `prompt=consent` for reconnect vs first-time login (session attribute, query param, distinct authorization URL). Researcher to verify and planner to pick.
- **Partial-grant detection edge case** — Whether Google's consent UI actually allows users to un-check individual scopes from a bundled grant. Researcher to verify; if UI doesn't allow, the partial-grant code path stays defensive but rarely triggered.
- **`SectionCard` replacement granularity** — Whether every consumer uses the full Card/CardHeader/CardTitle/CardDescription/CardContent chain, or some surfaces inline simpler `<Card className="p-6">` when no header exists.
- **Per-route-group container hoisting** — Whether `max-w-3xl`, `p-6` etc. relocate from per-page to per-group `layout.tsx` if the pattern is truly identical.
- **OAuthScopes constants holder** — Whether to introduce a small helper for bundled scope strings. REVIEW.md §5 hinted at scope-string duplication.
- **New loading.tsx files** — Whether to add for `/onboarding`, `/settings`, `/login` only when the surface flashes empty content during fetch.
- **Naming of new login-side error codes** — `auth.consent_denied` vs `login.error.consent_denied` vs `auth.login.consent_denied`. Match existing ErrorCodes namespace.
