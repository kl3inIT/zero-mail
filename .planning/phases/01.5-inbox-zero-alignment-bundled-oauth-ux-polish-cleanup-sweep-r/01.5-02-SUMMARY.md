## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] TypeScript compile error: next-intl template literal key not assignable to strict typed namespace**
- **Found during:** Task 2 (login/page.tsx RSC rewrite)
- **Issue:** `t(\`error.${error}.title\`)` — TS error "Argument of type is not assignable to NamespacedMessageKeys" because next-intl 4 uses a strict typed bundle; template literal keys cannot be inferred
- **Fix:** Split into two translators: `tLogin` (typed, for static keys) + `tError = tLogin as unknown as (key: string) => string` (loose cast, for dynamic template-literal keys). Mirrors LanguageSwitcher pattern documented in STATE.md
- **Files modified:** `apps/web/app/(auth)/login/page.tsx`
- **Committed in:** cc44012

**2. [Rule 1 - Bug] ESLint error: `<a href="/">` triggers `@next/next/no-html-link-for-pages` in not-found.tsx**
- **Found during:** Task 2 (not-found.tsx refactor)
- **Issue:** Using `<Link>` from next/link caused vitest React-dedupe boundary failure (TypeError: Cannot read properties of null — useContext); but plain `<a>` triggered ESLint rule
- **Fix:** Used `<a>` with `// eslint-disable-next-line @next/next/no-html-link-for-pages` comment documenting the vitest boundary reason. Mirrors lucide-react inline-SVG boundary documented in STATE.md line 149
- **Files modified:** `apps/web/app/not-found.tsx`
- **Committed in:** cc44012

**3. [Rule 1 - Bug] i18n:check failure: missing `errors.auth.consent_denied` + `errors.auth.gmail_scope_required`**
- **Found during:** Task 2 (verification gate)
- **Issue:** Backend Plan 01 added `AUTH_CONSENT_DENIED` and `AUTH_GMAIL_SCOPE_REQUIRED` to `ErrorCodes.java`; the i18n:check script reads ErrorCodes.java and verifies `errors.*` namespace coverage — these new codes had no frontend bundle entries
- **Fix:** Added `errors.auth.consent_denied` and `errors.auth.gmail_scope_required` to both `en.json` and `vi.json`
- **Files modified:** `apps/web/i18n/messages/en.json`, `apps/web/i18n/messages/vi.json`
- **Committed in:** cc44012

**4. [Rule 1 - Bug] vitest failure: mdx-pipeline.test.ts regex `/readdir/` failed after docs/page.tsx delegated to `listDocFilenames()`**
- **Found during:** Task 2 (vitest run)
- **Issue:** Test asserted `expect(src).toMatch(/readdir/)` but docs/page.tsx now calls `listDocFilenames()` from `@/lib/docs/loader` — no longer calls `readdir` directly
- **Fix:** Updated test regex to `expect(src).toMatch(/readdir|listDocFilenames/)` with explanatory comment
- **Files modified:** `apps/web/__tests__/docs/mdx-pipeline.test.ts`
- **Committed in:** cc44012

**5. [Rule 2 - Missing Critical] Deleted onboarding-error.test.tsx (no longer tests an existing contract)**
