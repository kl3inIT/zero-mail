# Phase 01.5 Plan 03: /me fetch React cache() — Primitive-keyed dedupe (HIGH-2 fix) Summary

**One-liner:** React `cache()` wrapper keyed on primitive cookie header string eliminates /me fetch duplication across RSC consumers within one render pass, with `cache: 'no-store'` preserved for cross-request freshness.

## What Was Built

### Final me.ts shape (three exports)

`apps/web/features/account/api/me.ts` now exports:

1. **`fetchCurrentUser(opts)`** — raw async function (renamed from `getCurrentUser`). Used by `proxy.ts`, client-side/TanStack callers, and internally by `getCurrentUserCached`. Keeps `cache: 'no-store'` on the underlying fetch.

2. **`getCurrentUserCached(cookieHeader: string | undefined)`** — server-only cached wrapper using `import { cache } from 'react'`. Cache key is a PRIMITIVE STRING (the raw cookie header). Value equality semantics → two calls with the same cookie string within one RSC render pass dedupe to one underlying fetch. Two calls with different cookie strings produce separate fetches (different users → no false-positive dedupe).

3. **`getCurrentUser`** — `const` alias = `fetchCurrentUser`. Preserves import compatibility for `proxy.ts`, `useCurrentUser.ts` hook, and any other client-side consumer. Zero call-site changes required for those consumers.

### HIGH-2 Review Fix Evidence

The previous design wrapped `getCurrentUser(opts)` directly with `cache()`. React's `cache()` keys by argument **reference** equality for object args. RSC callers that construct a fresh `{ headers: { cookie } }` object on each render (exactly what `reassertServerLocale` does) → cache miss every time → no real dedupe.

The fix: `getCurrentUserCached(cookieHeader: string | undefined)` accepts a PRIMITIVE STRING. String equality in JavaScript is value-based → same cookie string → same cache entry → same Promise within one render pass.

**RSC contract:**
```
const cookieHeader = (await cookies()).toString(); // primitive string
await getCurrentUserCached(cookieHeader);          // dedupes by value
```

### layout.tsx call-site update

`reassertServerLocale` now:
1. Imports `cookies` from `next/headers` (alongside existing `headers`)
2. Guards on `headerStore.get('cookie')` (fast early-exit for unauthenticated)
3. Calls `(await cookies()).toString()` to get the primitive cache key
4. Passes that string to `getCurrentUserCached(cookieHeader)` — NOT a fresh object

**React cache() vitest limitation:** `cache()` is RSC-context-only — outside a React server component render pass (vitest/jsdom), it is a pass-through and does NOT dedupe. `Object.is(p1, p2)` cannot be asserted in unit tests. Tests instead verify export shape, fetch behavior, and cookie header forwarding — which ARE testable and prove implementation correctness. The actual per-request dedupe is a React runtime guarantee when called from RSC context.
