## Decisions Made

- **GET not POST for OAuth redirect trigger**: OAuth redirect is idempotent; actual token rotation happens on the `/login/oauth2/code/google` callback which is already CSRF-exempt by design. Spring Security CSRF only applies to state-changing methods (POST/PUT/DELETE) by default. Using GET avoids needing `X-XSRF-TOKEN` in the request entirely.
- **token.getName() instead of req.getUserPrincipal().getName()**: Spring Security does not commit the authentication principal to `SecurityContext` until `super.onAuthenticationSuccess()` is called. Since both throw sites execute before `super`, `req.getUserPrincipal()` returns null → `"anonymous"` → `removeAuthorizedClient("google", "anonymous")` no-ops. `OAuth2AuthenticationToken.getName()` is always available as it comes directly from the token payload.
