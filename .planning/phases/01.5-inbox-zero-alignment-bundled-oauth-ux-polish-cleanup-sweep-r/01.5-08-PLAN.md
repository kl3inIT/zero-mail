**1. Replace the crypto.refresh-token-key-base64 value (line 73).**

Current:
```yaml
  crypto:
    # Prefer Secret Manager in deployed environments; fall back to local env var in dev/test.
    refresh-token-key-base64: ${REFRESH_TOKEN_KEY_BASE64:${sm://oauth-refresh-token-key-v1/versions/1:}}
```

Replace with:
```yaml
  crypto:
    # Required deployment secret — must be supplied via Docker secret, systemd credential,
    # or locked-down env file on the VPS. No GCP Secret Manager fallback (CLAUDE.md stack lock).
    # Boot fails immediately with a clear error if this env var is absent.
    refresh-token-key-base64: ${REFRESH_TOKEN_KEY_BASE64:?REFRESH_TOKEN_KEY_BASE64 must be supplied via deployment secret source (Docker secret, systemd credential, or locked-down env file)}
```

The `:?` syntax is Spring Boot ConfigData's fail-fast required-property pattern — if REFRESH_TOKEN_KEY_BASE64 is unset, Spring Boot will fail at startup with:
"Could not resolve placeholder 'REFRESH_TOKEN_KEY_BASE64' in value '${REFRESH_TOKEN_KEY_BASE64:?...}'"
This is preferable to the opaque base64-length error that the sm:// → empty-string path produced.

Current:

```yaml
  cloud:

```

Delete these 4 lines entirely. The `spring.cloud.gcp` namespace is no longer on the classpath (starter removed in Task 1), so the property would cause an "Unknown configuration key" warning at startup if left.
