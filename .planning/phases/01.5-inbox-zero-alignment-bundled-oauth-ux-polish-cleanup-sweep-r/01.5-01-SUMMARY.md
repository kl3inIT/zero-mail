# Phase 01.5 Plan 01: Bundled OAuth — Single-Tx Provisioning + 2-Leg Deletion Summary

Single bundled Google OAuth2 registration with TRUE one-transaction `provisionBundledOAuth`, dropping 7 two-leg files and `OnboardingStep.SIGNED_IN`, with Liquibase 008+009 migration changesets and 13 test cases (5 integration + 4 resolver + 4 failure handler) all GREEN.

## What Was Built

### Task 1 — Wave 0 RED Scaffolds (88f16c0)

- `application.yml`: Replaced `google` + `google-gmail` two-registration block with single bundled `google` registration (5 scopes: openid, profile, email, gmail.modify, gmail.settings.basic).
- `ApiPostgresTestBase`: Removed `google-gmail` DynamicPropertySource stub.
- `OnboardingStepPersistenceTest`: Updated inline comment (SIGNED_IN → GMAIL_CONNECTED entry state).
- `008-cleanup-gmail-registration-data.yaml`: Delete stale `oauth2_authorized_client` rows for `google-gmail`.
- `009-drop-signed-in-onboarding-step.yaml`: Migrate `SIGNED_IN` → `GMAIL_CONNECTED` in `users` table.
- Three RED test scaffolds: `GoogleAuthorizationRequestResolverTest` (4 cases), `LoginRedirectAuthenticationFailureHandlerTest` (4 cases), `BundledGoogleOAuthIntegrationTest` (5 cases).

### Task 2 — Bundled OAuth Implementation (7d07478)

- `OAuthScopes.java`: Constants for `GMAIL_MODIFY`, `GMAIL_SETTINGS_BASIC`, `GMAIL_PREFIX`.
- `GoogleAuthorizationRequestResolver.java`: Replaces `GmailScopeRequestResolver`. Always sets `access_type=offline` + `include_granted_scopes=true`. Adds `prompt=consent` only on `?reconnect=true`.
- `LoginRedirectAuthenticationFailureHandler.java`: Extends `SimpleUrlAuthenticationFailureHandler`. Routes `access_denied` → `/login?error=consent_denied`, `gmail_scope_required` → best-effort `removeAuthorizedClient` + redirect, unknown errors → `super.onAuthenticationFailure`.
- `OAuthProvisioningService.java`: New `provisionBundledOAuth` method with `PROPAGATION_REQUIRED` `bundledTx` wrapping all four steps atomically. Null refresh token on first-login raises `IllegalStateException` (caller throws `OAuth2AuthenticationException` before reaching here). Race condition handled via `DataIntegrityViolationException` catch + re-read.
- `GoogleOAuthSuccessHandler.java`: Rewritten — scope check (`gmail.modify` required), MED-3 null refresh token detection, INFO-7 `gmail.settings.basic` partial grant warning, calls `provisioning.provisionBundledOAuth(...)`.
- `SecurityConfig.java`: Rewired to new `successHandler/failureHandler/authRequestResolver`.
- `ErrorCodes.java`: Added `AUTH_CONSENT_DENIED`, `AUTH_GMAIL_SCOPE_REQUIRED`; removed `GMAIL_IDENTITY_MISMATCH`, `GMAIL_CONSENT_DENIED`.
- `ConnectGmailController.java`: POST redirects to `/oauth2/authorization/google?reconnect=true`.
- `OnboardingStep.java`: Removed `SIGNED_IN`; rebalanced weights: `GMAIL_CONNECTED(10)`, `TEMPLATE_SELECTED(20)`, `COMPLETE(30)`.
- `UserEntity.java`: Default `onboardingStep = OnboardingStep.GMAIL_CONNECTED`.
- `core.account/package-info.java`: Added `"gmail"` to `allowedDependencies`.
- Deleted 7 source files + 4 test files (all 2-leg artifacts).
- Tests updated: `OnboardingStateMachineTest`, `GoogleOAuthSuccessHandlerTest`, `LoginRedirectAuthenticationFailureHandlerTest`.

### Task 3 — Full Gate + Fixes (3b9804f, 888fbb9)

- `008-cleanup-gmail-registration-data.yaml`: Added `tableExists preCondition` (onFail=MARK_RAN) — fresh test DBs without Spring Session schema no longer fail with `relation does not exist`.
- `BundledGoogleOAuthIntegrationTest.java`: Replaced all `users.count()`, `tenants.count()`, `connections.count()` JPA calls with native `JdbcTemplate` queries — bypasses Hibernate `@TenantId` filter which returned 0 without an active tenant context.
- `build.gradle.kts`: Removed stale `google-gmail` client-id/secret from openapi-emit task args.
- `GmailConnectionService.java`: Updated stale Javadoc references from `GmailOAuthSuccessHandler` to `GoogleOAuthSuccessHandler`.

**Result:** 102/103 tests PASS. 1 pre-existing failure (`CorsIntegrationTest.actual_response_for_frontend_origin_includes_cors_headers`) logged to deferred-items.md.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Liquibase changeset 008 fails on fresh test DBs**
- **Found during:** Task 3 full check
- **Issue:** `DELETE FROM oauth2_authorized_client WHERE ...` fails with `relation does not exist` when the Spring Session JDBC schema hasn't been applied (fresh test containers never ran Spring Session schema init).
- **Fix:** Added `preConditions: tableExists(oauth2_authorized_client), onFail=MARK_RAN`.
- **Files modified:** `008-cleanup-gmail-registration-data.yaml`
- **Commit:** `3b9804f`

**2. [Rule 1 - Bug] BundledGoogleOAuthIntegrationTest assertions return 0**
- **Found during:** Task 3 full check
- **Issue:** `users.count()`, `connections.count()` use Hibernate `@TenantId` filter which returns 0 when `TenantContext.TENANT` ScopedValue is not bound in the test thread (normal outside a request thread). Rows exist in DB but are hidden by filter.
- **Fix:** Replaced all JPA `.count()` / `.deleteAll()` calls with `JdbcTemplate` native SQL queries that bypass the tenant filter.
- **Files modified:** `BundledGoogleOAuthIntegrationTest.java`
- **Commit:** `3b9804f`

**3. [Rule 1 - Bug] openapi-emit Gradle task still references google-gmail registration**
- **Found during:** Surface scan after Task 3
- **Issue:** `build.gradle.kts` had `google-gmail.client-id=openapi-emit` and `google-gmail.client-secret=openapi-emit` args that would cause Spring context startup to warn about unknown registration.
- **Fix:** Removed the two stale lines; kept only the `google` registration stub.
- **Files modified:** `backend/api/build.gradle.kts`
- **Commit:** `888fbb9`

**4. [Rule 1 - Bug] GmailConnectionService Javadoc references deleted class**
- **Found during:** Surface scan
- **Issue:** Javadoc referenced `GmailOAuthSuccessHandler` which was deleted in Task 2.
- **Fix:** Updated Javadoc to reference `GoogleOAuthSuccessHandler`.
- **Files modified:** `GmailConnectionService.java`
- **Commit:** `888fbb9`
