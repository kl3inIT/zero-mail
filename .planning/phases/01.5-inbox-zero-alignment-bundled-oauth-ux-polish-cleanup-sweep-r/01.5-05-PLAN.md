    ```markdown
    ## Conventions

    ### 1. Thin controllers + service-owned `@Transactional`

    Controllers map record views via private `toResponse(...)` helpers and never touch repositories directly. Transaction boundaries belong in `@Service` classes; controllers translate HTTP-shape ↔ domain-shape and forward to services. This keeps controllers cheap to test (no DB), centralizes transaction logic, and lets Modulith + ArchUnit enforce domain boundaries cleanly.

    **Example:** `backend/api/src/main/java/com/zeromail/api/controllers/<TenantStatusController-or-similar>.java`
    ```java
    @GetMapping("/tenant/status")
    public TenantStatusResponse status() {
        return toResponse(tenantStatusService.currentStatus());
    }

    private static TenantStatusResponse toResponse(TenantStatusView view) {
        return new TenantStatusResponse(view.connectionStatus(), view.onboardingStep().id());
    }
    ```

    **Anti-pattern:** controller injecting `UserRepository` or `GmailConnectionRepository` and calling `findById` directly.

    ### 2. Records for DTOs, classes for entities, Lombok-free

    Java 25 records cover ~all DTO/value-object use cases — immutable, equals/hashCode/toString for free, exhaustive deconstruction patterns. Entities stay class because Hibernate proxies need a no-args constructor and field mutation. Lombok is banned project-wide because it lags JDK releases by 3-12 months and Java 25 features (flexible constructors, module imports) trip it. Builder needed? Write an explicit nested `Builder` class.

    **Example DTO:** `backend/api/src/main/java/com/zeromail/api/dto/account/UserResponse.java`
    ```java
    public record UserResponse(UUID id, String email, String preferredLanguage, OnboardingStepResponse onboardingStep) {}
    ```

    **Example entity:** `backend/core/src/main/java/com/zeromail/core/account/persistence/UserEntity.java`
    ```java
    @Entity @Table(name = "users")
    public class UserEntity extends AbstractTenantOwnedEntity {
        @Column(unique = true, nullable = false) private String googleSubject;
        // explicit no-args constructor + getters/setters; no Lombok
    }
    ```

    **Anti-pattern:** `@Data`, `@Builder`, `@AllArgsConstructor`, `@NoArgsConstructor` (Lombok forbidden).

    ### 3. Enum state machines via `OrderedEnum` / `IdentifiedEnum` + static `fromId` fail-loud

    Domain enums never rely on `name()` for DB storage or `ordinal()` for ordering. Implement `core.shared.lang.OrderedEnum` (carries `id()` + `weight()` + `labelKey()`) for ordered state machines, or `IdentifiedEnum` for unordered identity sets. Storage uses `id()` (string), so DB rows survive enum reordering. Lookup uses static `fromId(String)` that throws `NoSuchElementException` on unknown ids — never returns null, never silently maps to a default.

    **Example:** `backend/core/src/main/java/com/zeromail/core/onboarding/model/OnboardingStep.java`
    ```java
    public enum OnboardingStep implements OrderedEnum {
        GMAIL_CONNECTED(10), TEMPLATE_SELECTED(20), COMPLETE(30);
        // ...
        public static OnboardingStep fromId(String id) {
            return Stream.of(values()).filter(e -> e.id().equals(id)).findFirst()
                    .orElseThrow(() -> new NoSuchElementException("Unknown OnboardingStep id: " + id));
        }
    }
    ```

    **Anti-pattern:** `@Enumerated(EnumType.ORDINAL)`, `MyEnum.valueOf(input)` without try/catch, returning `Optional.empty()` for unknown ids and silently treating it as a default.

    ### 4. Privacy logging format

    Every log statement emits an opaque `event=` name plus structured fields — never raw email, Google subject, OAuth refresh-token bytes, OAuth access-token bytes, message body, LLM prompt, or LLM completion. Tenant context is the only stable identifier and is logged as a UUID via `tenantId={}`. ArchUnit rules (Phase 1 FND-04) and Logback scrub filter (FND-03) catch most violations at build/runtime, but the convention is the first line of defense.

    **Example:** `backend/api/src/main/java/com/zeromail/api/security/GoogleOAuthSuccessHandler.java`
    ```java
    log.info("event=oauth_provisioning_complete tenantId={}", tenantId);
    log.info("event=login_consent_denied"); // pre-tenant failure path
    ```

    log.info("provisioned user " + email + " sub=" + sub); // PII in log
    log.error("Token decrypt failed: " + new String(tokenBytes)); // secret bytes in log
    log.warn("Body: " + emailBody); // body content in log
    ```
