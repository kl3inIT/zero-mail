# Phase 01.5 Plan 09: UAT Gap Closure

## Goal

Close the two blocker gaps found during Phase 01.5 UAT:

1. `/login?error=consent_denied` crashes in Vietnamese because the login page resolves `auth.login.error.*` while messages store `auth.error.*`.
2. `/onboarding/select-template` returns 403 in production flow because SPA CSRF handling is not wired/tested against the real security filter chain.

## Tasks

### 1. Fix login error i18n namespace

- Update `apps/web/app/(auth)/login/page.tsx` so error titles/bodies resolve against the actual message namespace.
- Prefer `getTranslations('auth.error')` with `${error}.title` / `${error}.body` to avoid duplicating message keys.
- Update `apps/web/__tests__/pages/login-error-rendering.test.tsx` so the mocked translator respects the requested namespace and would fail on this mismatch.
- Verify:
  - `pnpm --dir apps/web run i18n:check`
  - `pnpm --dir apps/web exec vitest run apps/web/__tests__/pages/login-error-rendering.test.tsx`

### 2. Fix SPA CSRF for onboarding mutations

- Update `backend/api/src/main/java/com/zeromail/api/security/SecurityConfig.java` to use Spring Security 7 SPA CSRF support (`csrf.spa()`) or an equivalent explicit setup that:
  - stores the token in `XSRF-TOKEN`
  - accepts the raw `X-XSRF-TOKEN` header from the frontend
  - preserves CSRF ignores for OAuth callback paths
- Keep frontend `xsrfHeader()` behavior unless diagnosis shows the cookie is not being issued to the browser.
- Add a production-security integration/slice test for `/onboarding/select-template` that runs the real security filter chain and proves:
  - POST without CSRF token is rejected
  - POST with valid CSRF token and authenticated tenant succeeds
- Verify:
  - `./gradlew.bat :backend:api:check --warning-mode all`
  - manual retry of template selection from `/onboarding`

## Acceptance Criteria

- `/login?error=consent_denied` and `/login?error=gmail_scope_required` render localized alerts in `vi` without `MISSING_MESSAGE`.
- Unknown login error query values still render no alert.
- Authenticated onboarding template selection no longer returns 403 when the frontend sends a valid XSRF token.
- Test coverage catches both regressions.

## Notes

- Reconnect UAT remains blocked until onboarding can advance to Settings.
- `TestSessionSupport` disables CSRF in the current `test` profile; do not rely on it for this security regression.
