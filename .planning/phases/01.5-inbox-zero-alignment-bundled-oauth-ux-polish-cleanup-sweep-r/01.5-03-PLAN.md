<objective>
Wrap the `/me` fetch in React `cache()` keyed on a PRIMITIVE COOKIE HEADER STRING (not the options object) so multiple invocations within a single request truly dedupe in real RSC call graphs. Keep `cache: 'no-store'` on the underlying fetch (fresh per request, deduplicated within the request). Closes REVIEW.md §2 / §7 — implements D-D2 with the HIGH-2 review fix applied.

**HIGH-2 review fix (load-bearing):** The previous plan wrapped `getCurrentUser(opts)` directly. React's `cache()` keys arguments by REFERENCE EQUALITY, not semantic equality. RSC callers that build a fresh `{ headers: { cookie } }` object per render (which is exactly what `app/layout.tsx`'s `reassertServerLocale` does) get NO dedupe — each call produces a new object reference, so the cache misses every time. The fix is to introduce a server-only wrapper `getCurrentUserCached(cookieHeader: string | undefined)` whose argument is a PRIMITIVE STRING (the raw `cookies().toString()` value). Primitive string equality is semantic — two calls with the same cookie header dedupe to the same Promise. The wrapper internally builds the options object before calling `fetchCurrentUser`. The raw `fetchCurrentUser(opts)` export is preserved for client/TanStack consumers that don't need or want this server-only memoization.

Purpose: Phase 01.3 P04 made the `/me` fetch the single source of truth, but `app/layout.tsx` `reassertServerLocale()` plus any future RSC consumer can each trigger a redundant fetch within one render. Per-render-pass primitive-keyed memoization eliminates the duplicate request without introducing staleness windows.

Output: Cached `getCurrentUserCached` exported from `features/account/api/me.ts`; RSC consumers updated to pass the cookie header STRING; client/TanStack consumers unchanged via the un-cached `getCurrentUser` alias.
</objective>
