## Mailbox State Matrix (REVIEW FIX — codex HIGH #3, the design-level root cause)

`GmailConnectionStatus` = `NOT_CONNECTED | PENDING | CONNECTED | DISCONNECTED`. Each account-management surface accepts a DIFFERENT set of statuses. This table is the single source of truth that the two resolver methods, the controllers (Plan 06), and the Wave 0 tests (Plan 01) all align to. There are TWO ownership resolvers because "operate on a usable mailbox" and "re-authorize a broken mailbox" need opposite dispositions on `DISCONNECTED`:

| Endpoint / operation | Resolver used | NOT_CONNECTED | PENDING | CONNECTED | DISCONNECTED | Missing / not-owned |
|----------------------|---------------|---------------|---------|-----------|--------------|---------------------|
| list (`GET /api/gmail/mailboxes`) | none (read) | included | included | included | included (metadata) | n/a (only this tenant's rows) |
| set-primary | `resolveOwnedConnectionOrThrow` | 409 | 409 | OK | 409 | 404 |
| disconnect | raw `findByIdAndTenantId` (idempotent, NOT a resolver) | no-op | no-op | disconnects | no-op (idempotent) | 404 |
| **reconnect** | **`resolveReconnectableConnectionOrThrow`** | OK (re-authorize) | OK (re-authorize) | OK (re-consent / refresh) | **OK (the canonical reconnect target)** | 404 |
| factory build (`buildClientForMailbox`) | own guard (Plan 03) | 409/illegal | 409/illegal | OK | 409/illegal | fail loud |
| legacy default lookup (`buildClientForTenant`) | deprecated adapter | n/a | n/a | resolves single CONNECTED | n/a | fail loud on 0 or >1 |

Key consequences encoded below:
- `resolveOwnedConnectionOrThrow` is the "operate on a usable mailbox" guard. It MUST fail closed on `DISCONNECTED`, `PENDING`, AND `NOT_CONNECTED` (codex HIGH #6) — only `CONNECTED` passes. Used by set-primary and any future mailbox-scoped state change that needs a live grant.
- `resolveReconnectableConnectionOrThrow` is the "re-authorize a broken/incomplete mailbox" guard (codex HIGH #2). It 404s on missing/not-owned but PERMITS `DISCONNECTED`/`PENDING`/`NOT_CONNECTED`/`CONNECTED` (re-consent is always allowed) so the reconnect flow can target exactly the disconnected mailbox it is meant to repair. The OAuth success handler still re-validates ownership against the live session on callback (Plan 05).
- disconnect deliberately bypasses both resolvers and uses raw `findByIdAndTenantId` so a re-disconnect is idempotent rather than 409.
