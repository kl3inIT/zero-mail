<objective>
Expose the Gmail account-management REST surface (GMA-01..05, AUD-04) under the typed mailbox path segment `/api/gmail/mailboxes/{gmailConnectionId}/...` (D-05, OpenAPI-native typed path param — not header/query). `ConnectedMailboxesController` lists mailboxes (metadata only), sets primary, disconnects one mailbox, and reports metadata-only status/health. `ConnectMailboxController` writes a server-side `OAuthIntentSnapshot` into the Redis-backed `HttpSession` (key `ZEROMAIL_OAUTH_PENDING_INTENT`) and THEN issues the add/reconnect OAuth trigger redirect (302 → the bundled Google flow at `/oauth2/authorization/google?reconnect=true` with NO `intent`/`targetMailboxId` query params — codex HIGH-A, honors D-01). Branch authority rides only that session snapshot, which Plan 05's resolver consumes; the URL carries no branch authority. `MailboxSummaryResponse` is a record with `from(MailboxSummaryProjection)` + accurate `@Schema`. Thin controllers; service-owned transactions; controllers never inject repositories.

Purpose: Account management = backend REST APIs + OAuth triggers (D-00c). The UI/switcher is Phase 11 (UX-01/02), so this plan ships endpoints only — NO OpenAPI→frontend regen (VER-02/04 deferred).
Output: 1 DTO + 2 controllers.

| Boundary | Description |
|----------|-------------|
| client → mailbox-scoped REST | `{gmailConnectionId}` is attacker-controllable on every mailbox-scoped endpoint |
| controller → service | Controllers must not enforce invariants themselves; all ownership/state checks live in the service |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-10-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs (zero new deps) |
