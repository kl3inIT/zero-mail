<interfaces>
From existing `SenderSafetyNetController`:
- `GET /api/triage/sender-safety-net` → list of observations for the current tenant.
- `POST /api/triage/sender-safety-net/{senderEmail}/opt-in` → upserts an observation with `created_by_user=TRUE` (NEW column from 09-01). The path variable accepts BOTH a full email (`ceo@acme.com`) and a domain pattern (`@acme.com`). The service inspects the value to decide `pattern_kind`.
- NEW `DELETE /api/triage/sender-safety-net/{id}` → deletes the observation if and only if (a) it belongs to the current tenant AND (b) `created_by_user = TRUE`. Cross-tenant returns 404; observation-created (FALSE) returns 403 with `code=safety_net.observation_not_deletable`.

From `TenantProtectedSenderObservationEntity` (extended in 09-01):
- New fields `patternKind String` (EMAIL/DOMAIN) and `createdByUser boolean`.

From existing `SenderEmailCanonicalizer`:
- Extend with a `Pattern recognize(String input)` (or `CanonicalizedPattern`) that returns a record `{kind: EMAIL|DOMAIN, value: String}`. EMAIL: requires `@` and at least one char before and after; lowercase + trim. DOMAIN: starts with `@`, no local part; lowercase + trim. Reject malformed (e.g. `@` alone, `acme.com` without `@`) with `IllegalArgumentException` mapped to HTTP 400 `code=safety_net.pattern_invalid`.

From the existing triage worker decision pipeline (locate `TriageDecisionEngine` or equivalent):
- A `SafetyNetMatcher.findMatch(senderEmail, tenantId) -> Optional<String matchedPattern>` checks EMAIL exact + DOMAIN suffix (incoming `ceo@acme.com` matches DOMAIN `@acme.com` when the suffix matches).
- When a match exists, decision becomes `REJECTED_BY_SAFETY_NET` and the audit row's `blocked_by_safety_net_pattern` is set to the matched pattern string.

ArchUnit / sanity:
- DOMAIN matcher MUST NOT be a substring check — it's a suffix check on `@acme.com`. A sender `acme.com@evil.com` MUST NOT match `@acme.com`. Use `email.endsWith(domainPattern)` AFTER the local-part `@` boundary.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/triage/sender-safety-net/* | User-typed pattern; must canonicalize + reject malformed values |
| triage worker → triage_audit | Worker writes blocked_by_safety_net_pattern with matched pattern; must not leak unrelated content |
| cross-tenant DELETE | Must return 404 (tenant isolation), not 403 (which leaks existence) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03-01 | Tampering | DOMAIN pattern matched via substring | mitigate | Suffix check anchored at `@` boundary: `senderEmail.toLowerCase().endsWith(domainPattern.toLowerCase())` AND `domainPattern.startsWith("@")` |
| T-09-03-02 | Information disclosure | Cross-tenant DELETE returns 403 (existence leak) | mitigate | Cross-tenant returns 404, opaque |
| T-09-03-03 | Elevation of privilege | User deletes observation-created entry (system-inferred) | mitigate | DELETE rejects entries with `created_by_user=FALSE` → 403 `code=safety_net.observation_not_deletable` |
| T-09-03-04 | Information disclosure | Audit pattern leaks tenant's contact lists | accept | Pattern strings are user-typed protections, not extracted email content |
| T-09-03-05 | Spoofing | Forged DELETE on another tenant's row | mitigate | Tenant ID always derived from `TenantContext.currentOrThrow()`, never from request body |
| T-09-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages |
</threat_model>
