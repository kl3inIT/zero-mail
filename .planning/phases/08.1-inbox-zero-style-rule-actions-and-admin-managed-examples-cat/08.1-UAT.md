## Tests

### 1. Admin Rule Catalog Management
expected: In the admin console, the Rule Catalog nav item opens a management page with Personas, Examples, and Actions tabs. Admin can edit English and Vietnamese text, toggle enabled state, reorder rows, save changes, refresh, and see the persisted catalog state without disabled rows disappearing from admin.
result: issue
reported: "On wider screens the admin Rule Catalog does not use the available width; examples should belong under the selected persona instead of a separate Examples tab; managing action descriptors in this UI feels unnecessary because actions rarely change."
severity: major

### 2. Rule Composer Examples
expected: In the user Rules workspace, the existing RuleComposer Describe tab has a Choose from examples control. Selecting a persona such as Personal lists DB-backed examples below the prompt box, and clicking an example replaces the prompt textarea with that example text.
result: issue
reported: "The rule authoring flow should show a compact Choose from examples button near the prompt box, then let the user choose a persona and show that persona's examples below. The current layout still feels like examples/actions are separate panels instead of an Inbox Zero-style guided picker."
severity: major

### 3. Available Actions Panel
expected: The Rules workspace shows a catalog-backed Available Actions panel listing Label, Archive, Save draft, Mark read, Star, Add to digest, Mark spam, Send reply, Forward, and Send email. Outbound actions explain whether Auto-send rules will send immediately or fall back to Gmail drafts.
result: issue
reported: "The available actions panel should not appear prominently in the rule authoring flow. Actions are mostly stable system capabilities, so showing all action cards here distracts from the user's main task of choosing examples and writing a rule."
severity: major

### 4. Global Auto-send Rules Setting
expected: Settings contains exactly one Auto-send rules switch. It defaults ON for a tenant, persists when toggled, and when OFF the rules UI still allows outbound rules but clearly indicates runtime fallback to Gmail draft instead of sending.
result: issue
reported: "The Auto-send rules setting is AI automation behavior and should live on the existing AI configuration page, near protected senders and other AI behavior controls, not on the generic Settings page."
severity: major

### 5. Manual Rule Action Builder
expected: Manual rule editing can create and round-trip every supported rules.v1 action: label, archive, save draft, mark read, star, add to digest, mark spam, send reply, forward email, and send email. Outbound actions expose structured fields for recipients, subject, and body/instructions without using raw Gmail-read body fields.
result: issue
reported: "The UI shows technical copy such as 'Cách gửi outbound', 'gate', and 'webhook', which is unclear to normal users. It should use user-facing language such as automatic replies, automatic forwarding, automatic new email, safety checks, and Gmail draft fallback."
severity: major

### 6. Safe Outbound Runtime UAT
expected: With a controlled Gmail test tenant and safe recipient allow-list, an outbound matching rule sends exactly one Gmail message when Auto-send rules is ON; when Auto-send rules is OFF or a sender safety/low-trust gate applies, no email is sent and an equivalent Gmail draft is created with an audit fallback reason such as AUTO_SEND_DISABLED.
result: blocked
blocked_by: third-party
reason: "User asked the agent to test this later with a controlled Gmail test tenant and safe recipients."

### 7. No-bypass and Privacy Gates
expected: Architecture and privacy verification passes: only the shared outbound gateway owns direct Gmail send calls, chat confirmations and rule runtime both use that gateway, tenant mismatch blocks before send/draft, provider error logs do not include raw Gmail-read bodies, and transient read-tool bodies are one-shot for the next model call only.
result: pass
