# Phase 8 — UI Design Contract (apps/admin)

> Visual and interaction contract for the NEW `apps/admin` Vite + React 19 SPA on `admin.zeromail.com`. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: this contract ONLY governs `apps/admin/**`. `apps/web` (user-facing Next.js on `zeromail.com`) is UNCHANGED by Phase 8. Do not specify, touch, or import anything from `apps/admin` into `apps/web`.

## Spacing Scale

Tailwind default 4-px grid. Declared values (every value MUST be a multiple of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs    | 4px  | Icon gaps, tight inline padding (badge dot to label, table cell inner padding) |
| sm    | 8px  | Compact form-field gaps, button icon-to-label gap, breadcrumb separator gap |
| md    | 16px | Default element spacing: stack of form fields, card body padding (inner) |
| lg    | 24px | Card outer padding, section-header-to-body, table row vertical padding |
| xl    | 32px | Page gutter (`apps/admin` content max-width 1280px with 32px gutters) |
| 2xl   | 48px | Major section breaks between dashboard widgets, between filter row and table |
| 3xl   | 64px | Page-level top spacing under fixed banner+header |

Layout grid:
- Persistent ADMIN MODE banner: fixed top, **40px** height.
- Top app bar (below banner): **56px** height with logo + breadcrumbs + admin email + sign-out.
- Left sidebar (desktop): **240px** width, collapsible to **64px** (icon-only) via `sidebar.tsx` primitive.
- Content max-width: **1280px** with 32px gutters on viewports >=1440px; full-bleed minus 32px below.
- Minimum supported viewport: **1280×800** (operator desktop). Below 1024px collapse sidebar to off-canvas `sheet.tsx`. Mobile is NOT a target — admin work is desktop-only.

Touch targets: not a primary concern (desktop-only), but interactive elements stay >= **36px** tall to comply with WCAG 2.5.5 AAA.

Exceptions:
- Floating ADMIN MODE banner stays **40px** (intentional, height-fixed) — drives all sticky calculations.
- Tabular dense rows in `/queue` and `/spend` may use **32px** row height with **8px** vertical padding for information density (still 4-multiples).

## Typography

Two weights (regular 400 + semibold 600), four sizes. **No italic** in admin UI (italic is reserved for the user-facing serif accent in `apps/web`).

| Role          | Size  | Weight        | Line Height | Usage |
|---------------|-------|---------------|-------------|-------|
| Body          | 14px  | 400 (regular) | 1.5 (21px)  | Default text in tables, cards, forms, banners, descriptions |
| Label         | 12px  | 600 (semibold)| 1.4 (16.8px)| Form labels, table column headers, badge text, eyebrow tags, audit-row metadata |
| Heading       | 20px  | 600 (semibold)| 1.3 (26px)  | Page H1 (e.g. "Master keys", "Audit log"), card titles inside dashboards |
| Display       | 28px  | 600 (semibold)| 1.2 (33.6px)| KPI big numbers on Dashboard + Spend (`$1,247.40`, `42 tenants`, `1.3k jobs`) |

Monospace font is used inline (not a separate type-scale role) for: model IDs (`anthropic/claude-4.7-opus`), tenant UUIDs, audit event IDs, HMAC hashes, masked key suffixes (`sk-****abc1`), timestamps in audit table (`2026-05-19T14:23:11Z`), spend numbers in tables. Always `text-xs` (12px) or `text-sm` (14px) monospace — never bumped up.

Letter-spacing: default Tailwind (none). Eyebrow / uppercase labels (`ADMIN MODE`, `LAST 7 DAYS`) use `tracking-wider` (0.05em) with `text-[11px]` monospace caps.

Tabular numerals required on KPI displays, spend tables, queue counts: `font-variant-numeric: tabular-nums` (`tabular-nums` Tailwind utility). Prevents column jitter on auto-refresh.

## Copywriting Contract

All admin copy is **English** (admin product surface; operator audience is bilingual but English-only here keeps audit-log strings stable for forensic search). User-facing app keeps EN/VI per existing i18n.

Tone: operator-direct, factual, low-emotion. No exclamation marks. No marketing language. Action verbs are imperative. Numbers are always concrete. Reference Gmail-tools / Postgres / kube/ops phrasing the operator already knows.

### Error states

| Trigger | Inline copy / toast |
|---------|---------------------|
| WebAuthn ceremony failure (`/enroll` or `/login`) | `Passkey ceremony failed. Try again, or contact a co-admin if the issue persists. Error: {RP error code}.` |
| Enrollment token expired (HTTP 410) | `This enrollment link has expired. Ask a co-admin to issue a fresh one with `POST /api/admin/grant-admin`.` |
| Master key test FAIL | `Connection test failed against {provider} /models. The previous key is preserved. Provider returned: {enum reason — never raw body}.` |
| Master key save without test PASS | `Save blocked — run Test connection first and wait for PASS.` |
| Master key edit session expired (>5 min) | `Edit session expired. Re-open the key form to mint a new edit token.` |
| Master key rate limit (>10/hr) | `Too many key operations this hour. Wait or contact a co-admin.` |
| Catalog Sync diff race (60s debounce) | `Sync already in progress for {provider}. The previous fetch is still being computed — try again in a moment.` |
| Catalog Sync provider error | `Sync failed: {provider} /models returned an unexpected shape. No models were imported. See audit row {auditId} for the raw error category.` |
| Catalog model ID rejected | `Model ID does not match the allowed format. Use only `a-z A-Z 0-9 . _ : / -` and stay under 128 characters.` |
| Tenant action without reason | `Provide a reason of at least 8 characters before continuing. The reason will be recorded in the audit log.` |
| Tenant action sentinel-leak in reason | `Your reason contains forbidden tokens (e.g. raw API key prefix). Rephrase before continuing.` |
| Body-ban filter trip | `The server refused this response because it contained content that admins are not permitted to view. Audit row {auditId} captured the incident. This is a privacy invariant — please file an issue if the field should not be flagged.` |
| Generic 401 admin chain | `Your admin session expired. Sign in again with your passkey.` |
| Generic 5xx | `Server error. Audit row {auditId} captured the call. Retry; if it persists, check `/admin/queue` for backend health.` |

### Destructive action confirmations (D-08 confirm-twice + reason)

All destructive actions use the same `alert-dialog.tsx` shell with the layout:
1. **Header (red strip)**: action name + target name. e.g. `Delete tenant — sarah@example.com`.
2. **Body**: concrete consequence list ("Gmail OAuth tokens will be revoked", "Pub/Sub subscription will be deleted", "all chat sessions will be hard-deleted", "this action is irreversible").
3. **Reason textarea**: label `Reason (recorded in audit log)`, placeholder `e.g. user-requested deletion per support ticket ZM-1284`, validation `8-500 chars`, monospace counter `8 / 500`.
4. **First confirm button**: `Continue` (secondary style, requires reason valid).
5. **Second step** (replaces body): `Type "{target.email}" to confirm` text input.
6. **Final destructive button**: `Delete tenant` (full destructive style).
7. **On success**: toast `Tenant deleted. Audit row {auditId}.` with link to audit detail.

| Action | Step 5 confirmation token | Final button label |
|--------|---------------------------|--------------------|
| Pause tenant | `pause` | `Pause tenant` |
| Disconnect Gmail | tenant email | `Disconnect Gmail` |
| Delete tenant | tenant email | `Delete tenant` |
| Revoke admin grant | admin email | `Revoke admin` |
| Rotate master key | provider name (e.g. `openai`) | `Rotate key` (less-destructive variant: secondary button + amber strip; still confirms twice but no token-type step — operator can re-test on failure) |
| Disable catalog model (no pins) | model ID | `Disable model` |
| Disable catalog model (with pinned tenants) | model ID **+** count `(N tenants pinned)` shown in red | `Disable {N} pinned model` |
| Re-queue dead-letter job | job ID first 8 chars | `Re-queue job` |

### Microcopy

- **Masked key display**: render `sk-****{last-4-chars}` for OpenAI-shape and `sk-ant-****{last-4}` for Anthropic shape — never first-4. Full token bytes never appear in DOM, network, or audit JSON (MKEY-08).
- **Audit row collapsed**: `{actor.email} · {action} · {target.kind}:{target.id-short} · {timestamp.local}`. Click expands JSON diff inline.
- **Audit row expanded diff**: 2-pane (Before / After) JSON tree using `react-json-view-lite` or shadcn `accordion.tsx` + `<pre>`; PRE entries are unselectable text in `bg-secondary` rounded boxes.
- **Catalog Sync diff page step labels**: `1. Fetch`, `2. Diff`, `3. Confirm` — connected by 1px horizontal stepper with active step bolded.
- **Queue auto-refresh indicator**: pulsing 6px purple dot + monospace `Updated 4s ago` text top-right of dashboard; "Pause refresh" toggle next to it.
- **Spend k-anonymity note (footer of `/spend` and `/tenants`)**: `Per-tenant spend bucketed by 7-day k-anonymity (k≥5). Exact per-tenant cost is not exposed.`

## Interaction Patterns

1. **Confirm-twice destructive flow** — described above (Copywriting → Destructive). Implemented via `<ConfirmTwiceDialog>`. On success, toast contains audit row ID linking back to `/audit?id={auditId}` for verification.
2. **Auto-refresh widgets** (`/queue`, `/spend`) — `useQuery` with `refetchInterval: 10_000` for queue, `60_000` for spend; `<AutoRefreshIndicator>` shows pulsing accent dot + "Updated Ns ago" + pause toggle. Auto-refresh pauses when tab is `document.hidden`.
3. **Lazy tab data fetch** (`/tenants/:id`) — `overview` query runs on mount; `health`, `billing`, `spend`, `activity` queries only fire on `onTabChange`. Each tab change pushes URL state via `useSearchParams` so URL is shareable. Each tab change writes a fresh `admin_read_event`.
4. **Sync wizard 3-step** — controlled stepper component with internal state machine `{step: 'fetch' | 'diff' | 'confirm'}`. Backward navigation allowed via stepper click on step 1-2. Step 3 has explicit `Confirm sync` button; closing the dialog rolls back fetched data (no commit).
5. **Masked secret entry** — focus on input reveals nothing (one-way write). After Test connection PASS, the Save button becomes enabled and shows micro-pill `Tested OK · 2s ago`. On Save, the form clears to masked-only state with `sk-****abc1` redacted preview.
6. **Filter bar pattern** (audit, tenants, spend) — top-of-page row with: date-range popover (presets: today, 7d, 30d, custom max-90d for spend / max-indefinite for audit), `<Select>` for actor/action/status, free-text `<Input>` for target ID (UUID prefix match, never email substring). `Apply filters` button right-aligned. Active filters render as removable badges below the bar.
7. **Auto-refresh + filter conflict** — when filters change, refetch immediately and reset the "Updated Ns ago" counter; never silently merge stale rows.
8. **CSV export** — streaming response, button shows spinner during stream; on completion, browser auto-downloads file `audit-{from}-{to}.csv` or `spend-{from}-{to}.csv`. Max 10k rows per export (per ADMIN-07).

## Accessibility

| Concern | Target |
|---------|--------|
| Color contrast | AA (4.5:1 body, 3:1 large). All token pairs verified: `--foreground` on `--background` = 11.2:1; `--ink-2` on `--amber-soft` (banner) = 7.3:1; `--primary` on white = 5.1:1. |
| Focus ring | 2px solid `--ring` (`#867AEB`) + 2px offset on all interactive elements. Never `outline: none` without replacement. |
| Keyboard | Tab order matches reading order; ESC closes dialogs; Enter submits forms; ⌘K opens `command.tsx` palette for cross-route navigation. |
| Screen reader | All icon-only buttons have `aria-label`; status badges use both color AND text; destructive confirm dialogs announce as `alertdialog`. |
| Reduced motion | Respect `prefers-reduced-motion: reduce` — disable pulsing dot, disable shimmer, retain page transitions but cut to instant. |
| Live regions | Auto-refresh "Updated Ns ago" text uses `aria-live="polite"`; toast container uses `aria-live="polite"` with `role="status"` (`sonner.tsx` default). |
