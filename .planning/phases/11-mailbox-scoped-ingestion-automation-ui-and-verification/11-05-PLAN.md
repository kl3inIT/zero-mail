<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client session → active-mailbox binding | a client may have a stale/disconnected/foreign active mailbox; the resolver must re-validate every request |
| PUT active-mailbox → session attribute | only an owned, connected mailbox may become active (fail closed) |
| read consumer → Gmail client | the active MailboxContext, not the tenant primary, decides which mailbox is read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05-01 | Elevation/Info disclosure | crafted/foreign gmailConnectionId becomes active and reads another mailbox | mitigate | PUT validates via resolveOwnedConnectionOrThrow (404/409); resolver re-validates each request; CrossAccountIsolationTest |
| T-11-05-02 | Elevation | binding the stored active mailbox blindly after it was disconnected | mitigate | resolver re-validates ownership/status every request, falls back to primary (Pitfall 2) |
| T-11-05-03 | Tampering | MailboxContext bound after the Hibernate session opens → wrong scope captured | mitigate | filter binds after TenantBindingFilter, before transaction; never @Transactional (GmailAccessGuard invariant) |
| T-11-05-04 | Elevation | invalid-grant disconnects the primary instead of the failing mailbox, leaving the bad grant live | mitigate | GmailAccessGuard resolves the specific failing mailbox (AUD-02) |
| T-11-05-05 | Tampering | a leftover shim caller silently routes a mailbox-scoped op to primary | mitigate | drain both ArchUnit allow-lists (own + Wave 3 entries from Plans 03/04); only ActiveMailboxResolver + documented chat tools remain |
| T-11-05-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — no package installs (RESEARCH: zero new deps) |
