# Phase 5A — UI Design Contract

> Visual and interaction contract for the authenticated `apps/web` product surface (app shell + persistent chrome, triage audit/undo/shadow/sender-net, billing balance/top-up/ledger, in-product privacy, plus a convergence pass on existing authenticated screens to 320px). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** authenticated screens use the *base* token contract from `app/globals.css` `:root` / `.dark` (teal accent `#0E5E5A`, paper-warm neutrals). They do **NOT** opt into the `.zm-proto` / `.zm-auth` clay-accent prototype skin — that skin is public/marketing/auth-only (Phase 1.6). New authenticated UI is built from raw shadcn `base-nova` primitives bound to the existing CSS-variable tokens; no wrapper components until the rule-of-three applies (D-03, conventions).

## Spacing Scale

8-point base scale (12 included as 4×3). Use Tailwind spacing utilities only; never arbitrary px values for layout gaps.

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 4px | Icon-to-label gaps, inline chip padding |
| xs | 8px | Compact element spacing, table cell vertical padding (dense mode), list item gaps |
| sm | 12px | Form field internal padding, card list item gaps, tab padding |
| md | 16px | Default element spacing, card body padding, between form fields |
| lg | 24px | Card padding (default), section padding within a page, gap between cards |
| xl | 32px | Page content gutters (desktop), gap between major sections |
| 2xl | 48px | Major section breaks, empty-state vertical centering padding |
| 3xl | 64px | Page-level top/bottom rhythm on wide layouts |

Layout spacing scale, cleanly: **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64**.

**Optical micro-adjustments (not part of the layout spacing scale):** a `2px` (`3xs`) nudge is permitted *only* for badge optical centering, status-dot offsets, and similar hairline insets — **never used for layout gaps, padding, or margins between elements**.

**Touch targets:** all interactive controls in the persistent chrome (pause toggle, balance pill if clickable, health indicator, `SidebarTrigger`) and all per-row Undo buttons render with a **minimum 40px hit area** (44px on the 320px breakpoint) even if the visual element is smaller — pad the hit area, not the glyph.

**Exceptions:**
- Icon rail (collapsed sidebar) item slots follow the shadcn `sidebar` block defaults (~32–40px square) — do not override.
- The audit/ledger `Table` uses a **dense row rhythm** (`py-2` / 8px vertical cell padding, ~36–40px row height) at `≥ md` — this is the intended density for an "evidence locker" log, not a violation of the 16px default. The card-list renderer below `md` reverts to `lg` (24px) card padding.
- Top-header chrome bar height: fixed **56px** (matches the public `--zm-nav` 60px family closely enough; use 56px for the authenticated shell to leave room for the `SidebarInset` border).

## Typography

Exactly **4 type sizes**. Geist Sans for everything except the rare serif headline accent and Geist Mono for data/code/reference fields. Role differentiation between card titles and section headings vs. page headings is done with **weight and color**, not extra sizes.

| Role | Size | Weight | Line Height | Covers |
|------|------|--------|-------------|--------|
| Label / small | 12px | 500 (medium) | 1.4 | Form field labels, badge text, table column headers, eyebrow/section kickers (uppercase, 0.06em tracking), nav item labels, "Undo window closed" muted note. |
| Body | 14px | 400 (regular) | 1.5 | Default UI text, table cells, descriptions, card body, helper text. (UI-dense product surface — 14px body, not 16px; matches the existing app and shadcn `base-nova` defaults.) |
| Heading | 20px | 600 (semibold) | 1.25 | **Page headings** (`/triage`, `/billing`, `/settings/privacy`), **section headings within a page**, and **card titles**. Differentiate the three tiers with weight (600 vs. 500) and color (`--foreground` vs. `--muted-foreground`), not size — e.g. page heading = 20px/600/`--foreground`, section heading = 20px/600/`--foreground` with more leading above, card title = 20px/500–600/`--foreground` tighter. |
| Display | 28px | 600 (semibold) | 1.2 | Reserved for the largest in-product moments only — the credit balance figure on `/billing`, the top-up success amount, an onboarding completion headline. Not used on routine screens. |

Type scale, restated: **12 / 14 / 20 / 28** — four sizes, no more. There is no 16px text size anywhere in this contract.

Weights are **400 and 600 only** (medium 500 is permitted *solely* for the Label role and nav items, mirroring the existing globals.css usage — treat 500 as a sub-variant of the Label role, not a third general weight). No light, no extrabold, no black.

**Mono (`--font-mono`) usage** (data, not body): timestamps in the audit/ledger tables, the VietQR memo/reference code and account number on the top-up screen, credit amounts in the ledger rows, intent IDs, the eyebrow kickers if a kicker is monospaced (consistent with `.zm-eyebrow`). Mono renders at the **12px Label step** (visually ~11.5–12px Geist Mono) — it is the **data-typeface variant of the existing 12px size**, not a fifth size.

**Serif (`--font-serif`, Instrument Serif italic) usage**: optional, at most one italicized accent word in a single page-level headline (e.g. an onboarding-complete "*done*"). Never in body, never in tables, never in chrome.

## Color

60 / 30 / 10 split, reading the existing `--*` tokens. Authenticated surfaces use the **base teal contract** (`:root` teal `#0E5E5A` / dark `#6FB3A8`), NOT the `.zm-proto` clay skin.

| Role | Token (light → dark) | Usage |
|------|----------------------|-------|
| Dominant (~60%) | `--background` `#FAFAF7` → `#131312`; `SidebarInset` content area | Page background, the main content canvas behind cards |
| Secondary (~30%) | `--card` `#FFFFFF` → `#1C1C1A`, `--secondary`/`--muted` `#F1EFE7` → `#232220`, `--sidebar` `#FAFAF7` → `#131312`, header bar bg | Cards, the sidebar rail, the top-header chrome strip, table header rows, tab strip backgrounds, popovers |
| Accent (~10%) | `--primary` / `--accent` / `--ring` `#0E5E5A` → `#6FB3A8`; `--accent-soft` `#D6E8E5` → `#1F3A37` for soft fills | See reserved-for list below |
| Destructive | `--destructive` `#B0413E` → `#DA8480`; `--red-soft` for soft fills | Destructive-action affordances only (see Copywriting) — never decorative |
| Warning (secondary semantic) | `--warning` / `--amber` `#B5731F` → `#D9A064`; `--amber-soft` for soft fills | The "pause is ON" state surface, the "top-up intent expiring soon / expired" panel, low-balance warning band |
| Success (status only, not a brand color) | `--green` `#2F7D5C` → `#6FB389`; `--green-soft` for soft fills | Gmail health "Connected" dot, top-up "Credited" success state, ledger top-up rows |
| Info | `--blue` `#2C5BA8` → `#8DA8E0`; `--blue-soft` | Shadow-mode "active" informational badge, neutral informational callouts |

**Accent reserved for** (explicit — never "all interactive elements"; default buttons/links inherit neutral `--foreground` / `--ink`, not accent):
- The primary CTA button on a screen (one per screen max): "Add a rule", "Top up credits", "Connect Gmail", "Confirm undo".
- The active nav item indicator in the sidebar (left border / background tint).
- The active tab underline on the `/triage` `Tabs` (mirrors `.zm-rules-tab.active` accent underline).
- Focus rings (`--ring`) on all focusable controls.
- Inline text links inside body copy (privacy page, descriptions) — accent-colored, underlined on hover.
- The credit-balance pill's positive emphasis (the figure may be accent-tinted; the pill chrome itself is neutral `badge`).
- Small "AI"/automated-action markers in the audit log (the mono `AI`-style tag, accent-colored, like `.zm-gm-ai`).

**Status-color discipline:** the Gmail health indicator uses exactly three states — `Connected` (green dot), `Action needed` (amber dot + reconnect affordance), `Disconnected` (red/destructive dot + prominent `ReconnectPrompt`). The pause toggle "ON/paused" state is **amber**, never red — pausing is a deliberate safe state, not an error. The audit-log action `Badge` colors map: label action → accent-soft, archive/skip-inbox → neutral/muted, draft-saved → blue-soft, undone → muted with strikethrough-adjacent treatment.

## Visual Hierarchy — Primary Anchor Per Screen

Each key screen has **one** focal element that the layout subordinates everything else to:
- **`/triage`** — the audit `Table` (desktop) / card list (mobile) is the focal element; chrome, tabs, and filters frame it but never compete with it.
- **`/billing`** — the **credit-balance figure** (Display type) is the focal element on the balance screen; the ledger and top-up CTA sit beneath/beside it.
- **Top-up screen** — the copyable VietQR block (image + memo + account + amount) is the focal element of the waiting state; the success state's focal element is the new balance figure (Display type).
- **`/rules`** — the **rule composer** (the natural-language rule input + its preview) is the focal element; the rule list is secondary.
- **`/settings/privacy`** — the "What we never store" section is the focal element; other sections are supporting context.
- **App shell (any route)** — within the chrome itself, the **active nav item** + the page heading are the hierarchy anchors; the balance pill, health dot, and pause toggle are peripheral status, not focal.

## Responsive Contract

| Breakpoint | Behavior |
|------------|----------|
| `≥ lg` (~1024px+) | Sidebar expanded by default (cookie-controlled), full top-header chrome, `Table` renderer for audit/ledger, two-column layouts allowed (e.g. `/settings` sections, billing balance + ledger side by side if it reads well — planner's call). Max content width ~1200–1280px, 32px gutters. |
| `md`–`lg` | Sidebar may be collapsed to icon rail; `Table` renderer still used; single-column page bodies; 24px gutters. |
| `< md` | Sidebar becomes the offcanvas `Sheet` (opened by `SidebarTrigger` in the header); audit/ledger switch to the **card-list renderer** (one card per entry, full Reason text shown); `/triage` `Tabs` stay but may scroll horizontally; all pages single-column; 16–20px gutters. |
| **320px (hard floor)** | Everything must render and function with no horizontal scroll: chrome strip wraps/compacts (balance pill, health dot, pause toggle, `SidebarTrigger` all fit — collapse labels to icons + accessible names if needed); audit/ledger card renderer; top-up copyable fields stack vertically full-width; tab labels truncate; touch targets ≥ 44px. Playwright e2e covers golden paths + key states at 320px AND desktop. The existing `globals.css` already has `@media (max-width: 360px)` handling for the public nav — the authenticated shell needs its own equivalent guard. |

Reduced motion: any decorative animation introduced (there should be almost none in the authenticated product — no marketing-style scan/shimmer effects) must respect `prefers-reduced-motion: reduce`.

## Notes for the Planner

- **Single source of truth for pause state** (D-13): chrome toggle, `/settings` toggle, and `PauseBanner` all render off one query key (`triageKeys.pauseState()`) + one read hook + the existing write hook with the optimistic `onMutate`/`onError`/`onSettled` recipe. No local `useState`, no ad-hoc query keys. This is a *correctness* contract, not just visual.
- **Chrome data prefetched in `(protected)/layout.tsx`** (D-10) and consumed within the shell subtree (not a deeper page boundary — TanStack #8479). Balance polls at ~45s (`refetchIntervalInBackground: false`, `staleTime ~30s`) plus invalidate-after-action; pause + health are invalidate-only.
- **Reason field is the trust artifact** (D-16): in the `Table` renderer it may be truncated-with-expand, but in the card renderer (and on the 320px floor) it is shown in full. Never let it become invisible.
- **Undo capability must read as finite, not absent** (D-18): the "Undo window closed" muted label is mandatory past 30 days.
- **Authenticated screens do not use the `.zm-proto` / `.zm-auth` clay skin** — base teal token contract only. Don't import or apply those classes.
- **Onboarding keeps its minimal layout** (D-05) — convergence pass only (tokens + shared loading/empty/error primitives + 320px), no flow redesign, no full-shell mounting.
- Icon choices, exact header spacing, tab order, settings section order, ledger column set, skeleton shapes — left to the planner + the `frontend-design` skill (invoke it before writing any UI, and pass the rule into executor subagents touching frontend), within everything above.
