# Phase 01.2: Domain-owned persistence restructuring - Pattern Map

**Mapped:** 2026-04-26
**Files analyzed:** ~30 source moves + ~10 net-new package-info.java + 1 net-new ArchUnit test + ~6 reference-only updates
**Analogs found:** 100% (this is a refactor — every "new" file has its own current self as the analog)

---

## Overview

This is a STRUCTURAL REFACTOR. Most "new files" are pure relocations: existing class bodies are byte-identical, only the `package` declaration and import lines change. Patterns the executor genuinely needs to replicate (not just `git mv`) are concentrated in three places:

1. **`package-info.java` `@ApplicationModule(allowedDependencies = {...})` annotations** — copy the existing `core.tenant/package-info.java` form and adjust the displayName + dependencies array. Per CL-3, the planner runs an empirical naming probe in Plan 01.2-01 (try `"shared.privacy"` first, fall back to `"privacy"` or named-interface form).
2. **ArchUnit test fixtures** (existing `SafetyContractArchTests`, `TenantIsolationArchTests`, plus net-new `DomainBoundaryArchTests` in Plan 06) — copy the `@AnalyzeClasses` + `@ArchTest static final ArchRule` shape.
3. **Controller `private static toResponse(view)` helper** (`MeController` is the analog; `TenantStatusController` adopts it in Plan 06).

Two additional concrete refactors driven by CL-2:
- `AccountService` loses 3 of its 4 repository injections (Plan 03).
- `AccountDeletionController` becomes the orchestration point that chains four single-domain service calls under one controller-level `@Transactional` (Plan 06).
