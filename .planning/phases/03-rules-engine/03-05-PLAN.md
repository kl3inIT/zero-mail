    Add a read-only preview data service:
    - Select recent observed Gmail message ids for tenant ordered by internal date/observed date.
    - Check `GmailConnectionService` before remote fetch. If the tenant is disconnected, revoked, or lacks a usable read grant, throw `GmailPreviewUnavailableException` with safe reason metadata that the API maps to `error.rules.gmail.unavailable`.
    - Fetch Gmail metadata for the current request only.
    - Prefer metadata headers and label ids; compute `requiresBodyEvidence` from the compiled matcher AST before fetching. Fetch sanitized/truncated body-derived evidence only when at least one matcher returns `requiresBodyEvidence() == true`.
    - Use Google API Client batch HTTP requests for bounded `messages.get` calls where supported by the existing Gmail client; otherwise use a bounded sequential fallback with clear per-preview limits. Do not name a nonexistent Gmail `users.messages.batchGet` endpoint.
    - Set a preview wall-clock budget in service code/tests (for example, max 5 seconds for remote fetch under test fakes) so Gmail latency does not hang the Rules page indefinitely.
    - Sanitize and truncate display fields before returning preview DTO input. Subject display is an excerpt, never a raw stored field.
    - Do not persist fetched headers, subject, snippet, body, prompt, completion, or model output.
    - Do not log Gmail email addresses, subjects, snippets, body text, token bytes, prompts, or completions.

    Addresses review concern: locks the header-first/body-evidence rule, disconnected grant path, and Gmail fan-out latency budget.
