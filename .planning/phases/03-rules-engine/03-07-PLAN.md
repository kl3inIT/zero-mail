  <action>
    Add rules DTO records and `RulesController`.

    Endpoints:
    - `GET /api/rules` - materialize onboarding templates idempotently, return ordered rules and template summaries, and set `Cache-Control: no-store` because the locked D-C2 first read has a side effect.
    - `GET /api/rules/{ruleId}`
    - `POST /api/rules/compile`
    - `POST /api/rules` - create disabled rule from validated compile payload.
    - `PUT /api/rules/{ruleId}` - edit source/compiled payload and reset preview eligibility.
    - `PATCH /api/rules/{ruleId}/enabled` - enable/disable, with enable requiring successful preview of current version.
    - `PUT /api/rules/reorder` accepting `RuleReorderRequest(List<RuleOrderEntry> entries)` where each entry is `{ UUID ruleId, int entityVersion }`; it is a full ordered list, not a partial move.
    - `DELETE /api/rules/{ruleId}`
    - `POST /api/rules/{ruleId}/preview`
    - `POST /api/rules/preview`
    - `GET /api/rules/templates`
    - `POST /api/rules/templates/{templateKey}/materialize`

    DTO contracts:
    - `RuleCompileResponse` is a tagged record/union shape with `status` values `compiled`, `clarificationRequired`, `invalid`; clarification payload contains one sanitized question and no raw model arguments.
    - `RuleResponse` exposes `entityVersion` and `lastPreviewedEntityVersion`; it does not expose ambiguous `version` naming in frontend-facing JSON.
    - Template/materialization responses include `skippedTemplates` entries from Plan 06 with key + safe reason enum.

    Add stable error codes under `error.rules.*` for invalid compile output, clarification required when called through an endpoint that expected a compiled payload, not found, preview required, invalid sample size, invalid reorder, unsafe action, and Gmail preview unavailable. Map rule exceptions in `GlobalExceptionHandler` without leaking raw input. Confirm only compile calls can map insufficient credits to HTTP 402 / `error.billing.insufficient`; preview is deterministic/read-only and must not return the billing code.

    Addresses review concern: locks reorder DTO shape, clarification response shape, GET cache semantics, skipped-template feedback, and compile-only credit behavior.
  </action>

  </verify>
