## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Vite import-analysis pre-resolved gray-matter literal spec, breaking discovery**

- **Found during:** Task 2 (mdx-pipeline.test.ts initial run via `pnpm --filter zeromail-web test`)
- **Issue:** The plan's verbatim `await import('gray-matter')` body — even though gated by the static `existsSync` predicate via `it.skipIf` (REVIEWS Revision 4) — failed at vitest's transform stage with `ERR_MODULE_NOT_FOUND`. Vite's `vite:import-analysis` plugin pre-resolves any dynamic-import whose spec is a string literal, regardless of whether the body ever executes. This trips the plan's W-01 / REVIEWS Revision 4 acceptance gate that mandates "vitest can DISCOVER and START all four test files without ERR_MODULE_NOT_FOUND".
- **Fix:** Hop the spec through a non-literal expression — `const moduleId = ['gray','matter'].join('-'); await import(moduleId)` — so Vite defers resolution to runtime. The static `existsSync` predicate at module load continues to gate the `it.skipIf`, so the body still only runs after Plan 06 installs gray-matter. (`@vite-ignore` comment alone was insufficient because the spec itself remained a literal string.)
- **Files modified:** `apps/web/__tests__/docs/mdx-pipeline.test.ts`
- **Verification:** `npx pnpm test __tests__/docs/mdx-pipeline.test.ts -- --run` now reports `9 failed | 1 skipped (10)` — discovery succeeds, structural assertions are RED as expected, frontmatter-shape gate is correctly SKIPPED.
- **Committed in:** `cdd9804` (Task 2 commit)
