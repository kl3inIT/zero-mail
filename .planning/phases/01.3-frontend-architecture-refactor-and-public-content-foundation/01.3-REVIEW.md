## Warnings

### WR-001: Pre-commit Hook Is Not Executable

**File:** `.husky/pre-commit:1`

**Issue:** The hook content is present (`pnpm exec lint-staged`), but Git tracks the file as mode `100644` (`git ls-files --stage .husky/pre-commit`). On Linux/macOS clones, Git hooks must be executable, so this pre-commit gate will be skipped. User-visible impact: formatting, lint, and i18n checks can be bypassed even though Phase 01.3 added the hook to enforce them.

**Fix:**

```bash
git update-index --chmod=+x .husky/pre-commit
git ls-files --stage .husky/pre-commit  # should show 100755
```

Also add a workspace cleanup test assertion for the executable bit so this does not regress.

### WR-002: Protected-Route Smoke Test Allows Direct Anonymous 200s

**File:** `apps/web/__tests__/e2e/route-smoke.spec.ts:27`

**Issue:** `/onboarding` and `/settings` are documented as anonymous -> `/login`, but the test accepts `[200, 302, 307]` and only checks the final response status at lines 41-46. Because Playwright follows redirects, a correct redirect and an accidentally public protected page can both end as `200`. Security impact: removing or breaking the proxy auth gate could still pass this smoke test.

**Fix:**

```ts
for (const path of ['/onboarding', '/settings']) {
  test(`${path} redirects anonymous users to login`, async ({ page }) => {
    await page.goto(path, { waitUntil: 'domcontentloaded' });
    await expect(page).toHaveURL(/\/login$/);
  });
}
```

If the test needs to inspect the initial response instead, assert `response?.request().redirectedFrom()` or disable redirect following at the request layer.

### WR-003: Slug-Validation Test Can Pass From Comments

**File:** `apps/web/__tests__/docs/mdx-pipeline.test.ts:84`

**Issue:** The path-traversal test searches the docs page source for the literal regex text. The current page contains that regex in a hardening comment, so the assertion can pass even if the actual `SLUG_RE.test(slug)` guard is removed. Security impact: a future regression in docs slug validation could slip through while the test still reports the traversal mitigation as covered.

**Fix:**

```ts
const src = readFileSync(DOCS_SLUG, 'utf8');
expect(src).toMatch(/SLUG_RE\.test\(slug\)/);
expect(src).toMatch(/notFound\(\)/);

const loaderSrc = readFileSync(DOCS_LOADER, 'utf8');
expect(loaderSrc).toMatch(/export const SLUG_RE\s*=\s*\/\^\[a-z0-9-\]\+\$\/;/);
```

Prefer checking the code path (`SLUG_RE.test(slug)` plus `notFound()`) and the exported loader regex rather than matching comment text.
