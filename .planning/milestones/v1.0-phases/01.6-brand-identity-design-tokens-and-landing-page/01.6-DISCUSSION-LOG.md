## A. Token migration strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Rebind shadcn names + add reference-style supplemental tokens | Keep `--background`/`--primary`/etc. names, retune values to Teal/Paper-warm hex; ADD `--accent-soft`, `--ink`, semantic-soft tokens, chrome helpers that have no shadcn equivalent | ✓ |
| Replace shadcn names entirely | Drop shadcn tokens, use `--bg`/`--accent`/etc. like reference. Risk: breaks shadcn auto-generated CLI source for future primitives | |
| Keep shadcn names, do NOT add supplemental tokens | Section components forced to use opacity utilities (`bg-accent/14`) for soft accents. Risk: muddy color reproduction | |
| Convert reference hex → oklch before rebind | Match shadcn philosophy. Risk: perceptual drift from reference values; extra step | |

**User's choice:** Rebind + supplemental tokens (Recommended).
**Notes:** Hex values used verbatim from reference (D-A2). 4-palette swatch (Clay/Ink/Electric) explicitly NOT exposed (D-A3). Phase 1.5's `--warning` retunes to amber-warm `#B5731F` light / `#D9A064` dark.

## B. Component location convention

| Option | Description | Selected |
|--------|-------------|----------|
| Split landing-domain vs auth-domain | `features/landing/components/` for TopBar/Footer/ZMLogoMark/Hero/sections; `features/auth/components/` for AuthTopBar/TrustPanel/LegalFooter; `features/landing/lib/setTheme.ts` for Server Action | ✓ |
| Everything in `features/landing/` | All chrome (incl. AuthTopBar, TrustPanel) under landing. Risk: blurs domain ownership; `features/auth/` becomes effectively unused on FE | |
| Per-route-group `_components/` | `(public)/_components/`, `(auth)/_components/`. Risk: hard to reuse cross-group | |
| Logo to `apps/web/components/brand/`, rest split | Pull ZMLogoMark out as cross-cutting brand asset. Reasonable but introduces extra boundary at single consumer | |

**User's choice:** Split by domain (Recommended).
**Notes:** ZMLogoMark stays in `features/landing/` per YAGNI (D-B3). LanguageSwitcher reused from `features/i18n/` if compatible; else minor variant prop (D-B2). Route-group `_components/` directories explicitly held in reserve for shared protected chrome (Phase 1.3 D-A3 contract).

## C. Theme cookie implementation

| Option | Description | Selected |
|--------|-------------|----------|
| Server Action + form action | `'use server'` `setTheme()` writes cookie via `cookies().set()`; ThemeToggle is client form with `useTransition` | ✓ |
| Route Handler `POST /api/theme` | New API route returns set-cookie + redirect. Risk: not idiomatic Next 16 RSC | |
| Client-side `document.cookie` + `router.refresh()` | JS write + RSC refresh. Risk: adblock/strict-mode interference, doesn't align with `NEXT_LOCALE` pattern | |

**User's choice:** Server Action + form action (Recommended).
**Notes:** Cookie attributes locked: `sameSite=lax`, `secure=true` in prod, `httpOnly=false`, `maxAge=1 year`, `path=/` (D-C3). NO `localStorage` (D-C4). Default = light when cookie absent; no `prefers-color-scheme` detection in v1 (D-C5). First-paint flash prevented by reading cookie in root `app/layout.tsx` server-side (D-C2).

## D. Onboarding step indicator pattern

| Option | Description | Selected |
|--------|-------------|----------|
| Named-step pills with active accent | 3 inline pills "Kết nối Gmail → Chọn template → Hoàn tất"; active = filled Teal, completed = `accent-soft` + check icon, future = muted outline | ✓ |
| Numeric counter "Bước 2/3" | Compact one-line; no step names visible | |
| 3 dots filled/unfilled | Minimal visual; doesn't convey step content | |
| Progress bar (0–33–66–100%) | Smooth gradient; doesn't distinguish discrete steps | |

**User's choice:** Named-step pills (Recommended).
**Notes:** Mobile (<sm 640px) collapses to single active pill + numeric subtitle "Bước 2 trên 3" / "Step 2 of 3" (D-D2). i18n keys `onboarding.steps.{gmailConnect,templateSelect,complete}.shortLabel` + `onboarding.steps.progressLabel` (D-D3). Currentstep prop derived from `users.onboarding_step` server-side, NOT from URL params (D-D4). Completed pills are `<Link>` for backward navigation; active and future pills are `<span>` (D-D5).
