<objective>
Collapse the two-leg `google` + `google-gmail` OAuth architecture into a single bundled-scope `google` registration aligned with Inbox Zero's pattern. The success handler delegates to a NEW single-transaction `OAuthProvisioningService.provisionBundledOAuth(...)` method that creates user + tenant + GmailConnectionEntity AND advances onboarding step inside ONE @Transactional boundary (REVIEW HIGH-1 fix — replaces the prior REQUIRES_NEW + second-tx design that allowed half-provisioned state). The failure handler maps OAuth2 errors to /login?error=... redirects with no half-provisioned DB state. Drop OnboardingStep.SIGNED_IN and delete all six 2-leg flow Java files plus their tests. Phase pivots AUTH-01/AUTH-02 implementation shape — no new product requirements.

Purpose: Match Inbox Zero's verified production pattern (single consent screen for everything you need), eliminate the mismatch-architecture surface, deliver true atomic provisioning per Phase 1.5 success criterion 2, and remove dead code per D-A3 (no transitional aliases).

Output: Single bundled OAuth flow shipping with full test coverage (including new atomicity-rollback integration test), clean DB cleanup migrations, and a single-tx provisioning service method.
