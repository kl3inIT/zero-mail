  <action>
    Create evaluation input/result records and `RuleEvaluator`.

    Input must include only preview-safe fields:
    - sanitized sender email/domain.
    - sanitized recipient emails.
    - sanitized subject excerpt.
    - Gmail label ids/categories.
    - internal date, observed date, attachment/list-unsubscribe/newsletter flags.
    - optional sanitized body-evidence-present boolean and derived flags, not raw body text.

    Evaluate:
    - sender email/domain.
    - recipient to/cc.
    - subject contains/equals/regex.
    - Gmail label/category present/absent.
    - has attachment.
    - list-unsubscribe/newsletter indicators.
    - message age/date.
    - all/any/not boolean groups with tri-state semantics.
    - semantic intent as `DEFERRED` with evidence id, not match true/false.

    Regex safety:
    - Use the RE2J dependency added in Plan 01 for regex matcher compilation/evaluation.
    - Compile validation from Plan 03 rejects invalid, unsupported, or overlong patterns before persistence.
    - Evaluator handles only prevalidated bounded patterns and never calls `java.util.regex.Pattern` on user-authored regex.
    - Preserve deterministic evidence ordering with `LinkedHashMap`/ordered lists or explicit sorting; do not rely on `HashMap` iteration order.

    Body evidence contract:
    - Evaluation asks `MatcherNode.requiresBodyEvidence()` only to interpret precomputed request-scoped evidence flags.
    - Header/metadata matchers never require body evidence.
    - `SEMANTIC_INTENT` returns `DEFERRED` and does not request body content or an LLM call in Phase 3.

    Addresses review concern: closes regex DoS risk and makes the body-derived evidence boundary explicit.
  </action>

    - Each matcher type's `requiresBodyEvidence()` value is asserted.

      - `CATEGORY_LABEL_MISMATCH` when an inferred/category label action conflicts with current Gmail category evidence.
    - Conflicts remain warnings only per D-D3.
    - Never include raw subject/body/header content in conflict metadata.
