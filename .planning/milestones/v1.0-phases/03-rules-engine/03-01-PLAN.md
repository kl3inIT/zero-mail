    `rules` table:
    - `id uuid` primary key.
    - `tenant_id uuid not null references tenants(id) on delete cascade`.
    - `display_name varchar(160) not null`.
    - `source_text text not null`.
    - `source_language varchar(16) not null`.
    - `schema_version varchar(32) not null check (schema_version = 'rules.v1')` for newly written rows; Java read validation must also reject unknown values.
    - `matcher_ast jsonb not null`.
    - `action_intents jsonb not null`.
    - `enabled boolean not null default false`.
    - `order_index int not null`.
    - `last_previewed_entity_version int null`.
    - `last_previewed_at timestamptz null`.
    - `template_key varchar(128) null`.
    - `template_version int null`.
    - `customized boolean not null default false`.
    - `created_at`, `updated_at`, `version` matching existing auditable entities; expose this to domain/API code as `entityVersion` to avoid confusion with AST schema version and previewed entity version.
    - mandatory btree indexes on `(tenant_id, order_index)` and `(tenant_id, enabled, order_index)`.
    - JSONB GIN indexes using `jsonb_path_ops` only where backed by raw SQL blocks and named explicitly; do not leave index creation as executor discretion.
    - partial unique index on `(tenant_id, template_key) where template_key is not null` to make concurrent template materialization idempotent at the database level.

    `rule_template_catalog` table:
    - tenantless catalog row with `id`, `template_key`, `template_version`, `display_name`, `source_text`, `source_language`, `schema_version`, `matcher_ast`, `action_intents`, `status`, timestamps, and version.
    - unique `(template_key, template_version)`.
    - seed starter templates for onboarding keys `archive-receipts`, `label-newsletters`, and `pin-calendar`, plus gallery-only `calendar-invites` if UI-SPEC requires it. Tests must prove onboarding selection keys exactly match materializable catalog keys and that any gallery-only key is never silently expected from onboarding.

    Create `RuleEntity`, `RuleRepository`, `RuleTemplateEntity`, and `RuleTemplateRepository`. Use JSONB mapping and real Postgres round-trip tests. Repository/service reads must validate `schema_version` into `RuleSchemaVersion` before returning a domain view.
