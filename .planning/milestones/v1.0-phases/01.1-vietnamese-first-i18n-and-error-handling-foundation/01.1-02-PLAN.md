<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted request body / validation arguments → ProblemDetail.params | Bean Validation `getArguments()` may include rejected user input |
| Server-built strings → response body | Any `MessageSource` call inside web layer would build a localized prose string and leak it to FE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.1.02-01 | Information Disclosure | params Map values | mitigate | `AllowedParamScalars.filter` allow-list (regex `[a-zA-Z0-9_.\-]{1,64}` + Number + Boolean only) — Plan 08 D-D4 sentinel test asserts no leak |
| T-1.1.02-02 | Tampering / Bypass | spring.mvc.problemdetails.enabled silently bypasses custom validation handler | mitigate | `GlobalExceptionHandler extends ResponseEntityExceptionHandler` — verified by reflection test (cite Spring #35982) |
| T-1.1.02-03 | Information Disclosure | title / detail | accept | Generic English diagnostics by design (RFC 7807); Plan 08 safety test asserts no sentinel leaks into them |
| T-1.1.02-04 | Information Disclosure | Server-built localized prose in error responses | mitigate | Plan 08 ArchUnit ban on MessageSource in `com.zeromail.api..` web layer |
</threat_model>
