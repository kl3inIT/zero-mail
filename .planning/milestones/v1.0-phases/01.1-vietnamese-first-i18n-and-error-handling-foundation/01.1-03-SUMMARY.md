## What Was Built

### `OpenApiConfig.java` (modified)

Two beans now contribute to the OpenAPI document:

1. **`phase1Info()`** (existing — retained, version bumped):
   - Title: "Zero Mail API"
   - Version: `0.1.1` (was `0.1.0`)
   - Description: "Phase 1 skeleton + Phase 1.1 i18n/error contract"

2. **`apiErrorCustomizer()`** (NEW — `GlobalOpenApiCustomizer`):
   - **Registers `ApiError` schema** in `components.schemas` with:
     - RFC 9457 base members: `type` (uri), `title`, `status` (int32), `detail`, `instance` (uri)
     - Extension members from `ProblemDetail.setProperty(...)`: `code` (required), `params` (Map), `fieldErrors` (array of `$ref FieldErrorDto`), `message` (deprecated transitional alias of `code`)
     - `required: ["code"]`
     - Verbose descriptions noting that `title`/`detail` are operator-only and not user-facing
   - **Registers `FieldErrorDto` schema** with `field`, `code`, `params` properties; `required: ["field", "code"]`. Explicitly omits JHipster's `message` string and `objectName` (CONTEXT.md §E reject).
   - **Defaults every operation's response slots for status codes 400/401/403/404/409/500**: when not already declared on the operation, adds an `ApiResponse` with `content: application/problem+json: schema: $ref #/components/schemas/ApiError`. Existing 200/201/etc. responses are untouched.

**Why `GlobalOpenApiCustomizer` and not `OpenApiCustomizer`:** plain `OpenApiCustomizer` only customizes the default OpenAPI document — once Phase 2+ introduces `GroupedOpenApi` for splitting public vs internal docs, plain customizers silently miss grouped paths. `GlobalOpenApiCustomizer` extends `OpenApiCustomizer` and applies to both. The interface signature is identical (one-arg `customise(OpenAPI)`), so the only cost is forward-compatibility insurance. Verified against `springdoc-openapi-starter-common-2.8.6-sources.jar`.

**Why explicit schema registration:** `ProblemDetail.setProperty(...)` writes extension members onto the wire via Jackson 3's `ProblemDetailJacksonMixin`, but those members are not Java fields on `ProblemDetail` — reflection-based schema generation never sees them. Without explicit registration, `openapi-typescript` would emit an `ApiError` interface with only `type/title/status/detail/instance`, and the frontend `useLocalizedApiError` helper (Plan 05/06) could not type-safely switch on `code`. RESEARCH.md Pitfall 6 calls this out by name.

### `ApiErrorSchemaTest.java` (new, 6 tests, all GREEN)

Boots the full Spring context (`@SpringBootTest(webEnvironment = RANDOM_PORT)` via `ApiPostgresTestBase`), hits `/v3/api-docs` via `RestClient`, parses with Jackson `ObjectMapper`, asserts:

- `components.schemas.ApiError` exists with `properties.code.type == "string"`, all eight property names present, `required` contains `"code"`, and `properties.fieldErrors.items.$ref == "#/components/schemas/FieldErrorDto"`.
- `components.schemas.FieldErrorDto` exists with `properties.field/code/params`, `required` contains both `"field"` and `"code"`, and `properties.message` does NOT exist (the JHipster reject invariant from CONTEXT.md).
- `paths./me.get.responses.401.content.application/problem+json.schema.$ref == "#/components/schemas/ApiError"` — proves the per-operation defaulting is wired.
- `info.version == "0.1.1"`.

Strategy choice: snapshot via real HTTP boot rather than reflective invocation of the `GlobalOpenApiCustomizer` lambda. The plan's deviation_policy explicitly preferred this: "easier to debug and less likely to drift from real behavior."

**2. [Rule 2 — Missing critical functionality] Added 500 to the defaulted-status list**
- **Found during:** Task 1 implementation.
- **Issue:** Plan body's `<action>` line listed status codes "400, 401, 403, 404, 409, 500" but `<behavior>` listed only "400, 401, 403, 404, 409". The two lists drift.
- **Fix:** Defaulted 500 alongside the others. Unexpected server faults must still serialize through `application/problem+json`/`ApiError` so the FE's `useLocalizedApiError` helper can render `errors.unknown` as a localized fallback (UI-SPEC §"API Error Localization Contract"). Without 500 defaulting, `openapi-typescript` would emit `ApiError | undefined` for 5xx slots and the FE would have to handle the `undefined` branch separately.
