## What Was Built

### `apps/web/i18n/routing.ts` (NEW — locked configuration)

```ts
defineRouting({
  locales: ['vi', 'en'] as const,
  defaultLocale: 'vi',
  localePrefix: 'never',
  localeCookie: {
    name: 'NEXT_LOCALE',
    maxAge: 60 * 60 * 24 * 365, // 1 year — REQ-2; mitigates T-1.1.05-02
    sameSite: 'lax',
    secure: true,
  },
});
```

The `maxAge` literal is intentionally `60 * 60 * 24 * 365` (not `31536000`) per the plan body's grep-verifiable acceptance criterion.

### `apps/web/i18n/request.ts` (NEW)

`getRequestConfig` reads `requestLocale` (set by next-intl's middleware after cookie negotiation), validates via `hasLocale(routing.locales, requested)`, and falls back to `routing.defaultLocale = 'vi'`. Loads the dictionary with a static dynamic import: `(await import(\`../messages/${locale}.json\`)).default`.

### `apps/web/proxy.ts` (MODIFIED — composes auth + i18n)

Next.js 16 enforces a single proxy file. The new `proxy.ts` calls `createIntlMiddleware(routing)` first to set the `NEXT_LOCALE` cookie & locale rewrite headers, then layers the existing `/onboarding`+`/settings` auth gate that redirects to `/login` when `ZEROMAIL_SESSION` is missing. Matcher: `/((?!api|_next|_vercel|.*\\..*).*)`.

### `apps/web/next.config.ts` (MODIFIED)

Wrapped with `createNextIntlPlugin('./i18n/request.ts')`.

### `apps/web/global.d.ts` (NEW)

Augments `next-intl.AppConfig` with `Locale = (typeof routing.locales)[number]` and `Messages = typeof messages` (typed against en.json — Plan 07's CI parity check ensures vi.json never drifts).

### `apps/web/app/layout.tsx` (MODIFIED — converted to async RSC)

```tsx
export async function generateMetadata(): Promise<Metadata> {
  const t = await getTranslations('common.app');
  return { title: t('title'), description: t('description') };
}

export default async function RootLayout({ children }) {
  const locale = await getLocale();
  const messages = await getMessages();
  return (
    <html lang={locale} className={`${geistSans.variable} ${geistMono.variable} h-full antialiased`}>
      <body className="min-h-full flex flex-col">
        <NextIntlClientProvider locale={locale} messages={messages}>
          <QueryProvider>{children}</QueryProvider>
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

`<html lang="en">` literal removed — `lang` now resolves server-side from `getLocale()`. Geist subsets extended to `['latin', 'latin-ext']` so Vietnamese diacritics render correctly.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Geist `vietnamese` subset literal rejected by TypeScript**
- **Found during:** Task 1 verify (`pnpm exec tsc --noEmit -p .`)
- **Issue:** Initial layout.tsx draft passed `subsets: ['latin', 'vietnamese']` to `Geist({...})`, hoping to opt-in to a Vietnamese-specific glyph set. `next/font/google`'s TS types only expose `'cyrillic' | 'latin' | 'latin-ext'` for Geist (TS2322).
- **Fix:** Switched to `['latin', 'latin-ext']`. Latin-ext covers the Vietnamese diacritic block (U+1E00–U+1EFF) — the visual end-state is unchanged, but the types are now valid.
- **Files modified:** `apps/web/app/layout.tsx`
- **Commit:** rolled into `b94505c` (T1)

**2. [Rule 3 — Blocking] Backend boot required GOOGLE_OAUTH_CLIENT_ID + REFRESH_TOKEN_KEY_BASE64 placeholders**
- **Found during:** Task 3 — `./gradlew :backend:api:bootRun` failed with `IllegalStateException: Client id of registration 'google' must not be empty.` and Spring Boot 4 OAuth2 client property validation refused to start the context.
- **Fix:** Re-launched with `GOOGLE_OAUTH_CLIENT_ID=dev-client-id`, `GOOGLE_OAUTH_CLIENT_SECRET=dev-client-secret`, `REFRESH_TOKEN_KEY_BASE64=$(node -e ...)` (32-byte base64 placeholder), and `GCP_SECRET_MANAGER_ENABLED=false`. The codegen path only exercises `/v3/api-docs` (springdoc), so OAuth and KMS are never actually invoked.
- **Files modified:** none (env-only)
- **Commit:** rolled into `9cae09f` (T3)

**3. [Rule 3 — Blocking] Plan body said `middleware.ts`; Next.js 16 only accepts `proxy.ts`**
- **Found during:** Task 1 — `apps/web/AGENTS.md` warns that this Next.js has breaking changes; `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` confirms `middleware.ts` is deprecated in favor of `proxy.ts` and there is exactly one such file. The repo already had `apps/web/proxy.ts` for the `/onboarding`+`/settings` auth gate.
- **Fix:** Composed `createIntlMiddleware(routing)` inside the existing `proxy.ts` (i18n first, then auth redirect overrides for protected paths). Did NOT create a parallel `middleware.ts` (Next.js 16 doesn't honor it). Plan body's intent (next-intl matcher excluding api/_next/files-with-dot) is preserved verbatim.
- **Files modified:** `apps/web/proxy.ts`
- **Commit:** rolled into `b94505c` (T1)

### Auth gates / blocked verifications

None required user-supplied secrets — `dev-client-id` / `dev-client-secret` placeholders are sufficient because the codegen never exercises the OAuth flow.
