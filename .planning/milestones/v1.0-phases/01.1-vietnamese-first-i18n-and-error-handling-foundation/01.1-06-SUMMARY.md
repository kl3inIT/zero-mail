## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Vitest "Cannot read properties of null" hooks crash from duplicate React install**

- **Found during:** Task 1 GREEN test run.
- **Issue:** pnpm hoists `react` and `react-dom` to BOTH `apps/web/node_modules` and the workspace root. With two React module instances on disk, the renderer (`react-dom-client`) and our component code wired up to different React objects — every hook (`useState`, `useTransition`, `useContext`) crashed with `TypeError: Cannot read properties of null (reading 'use*')` because the dispatcher singleton was set on the wrong instance.
- **Fix:** Updated `apps/web/vitest.config.ts` to alias `react` and `react-dom` (and their subpaths: `jsx-runtime`, `jsx-dev-runtime`, `client`, `test-utils`) to absolute paths under the workspace root, plus `resolve.dedupe` for both packages.
- **Files modified:** `apps/web/vitest.config.ts`.
- **Commit:** 290cd0c.

**2. [Rule 3 — Blocking] @base-ui/react Menu and lucide-react crashed under Vitest's React graph**

- **Found during:** Task 1 GREEN test run, after the dedupe fix above.
- **Issue:** Even with the React dedupe, `@base-ui/react`'s `Menu` (which uses an internal `FastComponent` pattern) and `lucide-react` icons resolved their own React imports via paths that bypassed the alias and re-introduced the duplicate-React graph. Hooks crashed inside `Button` and `<Languages>` icon.
- **Fix:** Replaced `@base-ui/react/menu` with a hand-rolled menu (native `<button>` trigger + `role="menu"` popup + `role="menuitemradio"` items, plus outside-click/Escape handlers). Replaced `lucide-react` icons with three inline SVG components (`LanguagesIcon`, `ChevronDownIcon`, `CheckIcon`). The DOM contract still matches the shadcn DropdownMenu shape VALIDATION.md expects (the test asserts `role="menuitemradio"` rather than a base-ui-specific selector).
- **Files modified:** `apps/web/components/LanguageSwitcher.tsx`.
- **Commit:** 290cd0c.

**3. [Rule 1 — Bug] TS5 readonly `process.env.NODE_ENV` mutation in test**

- **Found during:** `pnpm exec tsc --noEmit` after Task 1.
- **Issue:** The original `error-render.test.tsx` toggled `process.env.NODE_ENV` between `'development'` and `'production'` to exercise the sentinel-vs-fallback branches. Under TypeScript 5's `NodeJS.ProcessEnv` type, `NODE_ENV` is `readonly`, so `tsc --noEmit` failed with `error TS2540: Cannot assign to 'NODE_ENV' because it is a read-only property` (5 occurrences).
- **Fix:** Replaced the assignments with `vi.stubEnv('NODE_ENV', 'development' | 'production')` and `vi.unstubAllEnvs()` in the `afterEach`. Vitest 4's `stubEnv` is the supported, type-safe API.
- **Files modified:** `apps/web/__tests__/i18n/error-render.test.tsx`.
- **Commit:** 290cd0c.
