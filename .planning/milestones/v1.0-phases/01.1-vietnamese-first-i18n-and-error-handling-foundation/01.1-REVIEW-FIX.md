## Fixed Issues

### CR-01: Data-integrity handler logs raw exception stack traces

**Files modified:** `backend/api/src/main/java/com/zeromail/api/config/GlobalExceptionHandler.java`, `backend/api/src/test/java/com/zeromail/api/error/GlobalExceptionHandlerSafetyTest.java`
**Commit:** `ccda2c5`
**Applied fix:** Changed `log.warn("Data integrity violation translated to 409", ex)` to `log.warn("Data integrity violation translated to 409: {}", ex.getClass().getSimpleName())` — passing the throwable caused Logback to render the full stack trace plus the wrapped `SQLException`'s message and SQL state into appender output, leaking schema details into logs. Also extended `GlobalExceptionHandlerSafetyTest.assertNoSentinelLeak` to assert that translated events from the `GlobalExceptionHandler` logger never carry a `Throwable` proxy, so this regression class fails the suite next time.

### WR-01: Top-level validation errors do not localize to errors.validation.generic

**Files modified:** `apps/web/lib/api/errors.ts`, `apps/web/__tests__/i18n/error-render.test.tsx`
**Commit:** `ae6b802`
**Applied fix:** Added a `bundleKeyForCode()` shim inside `apps/web/lib/api/errors.ts` that redirects the bare `validation` namespace to `validation.generic` (which is the actual string leaf in `messages/<locale>.json`). Wired it into `useLocalizedApiError` so a server `code: "error.validation"` now renders the localized generic prompt instead of falling through to `[MISSING:validation]` in dev or `errors.unknown` in prod. Added two Vitest cases asserting the vi and en bundles render `validation.generic` for `{ code: "error.validation" }`.

### WR-02: Authenticated locale cookie reconciliation is attempted from a root layout

**Files modified:** `apps/web/app/layout.tsx`, `apps/web/proxy.ts`
**Commit:** `88b14ac`
**Applied fix:** Made `reassertServerLocale` in `app/layout.tsx` read-only — it now returns the preferred locale for this render but does not attempt `cookies().set(...)` (which is unreliable from a Server Component render path). Moved the durable cookie mutation into `proxy.ts` (formerly middleware.ts) where `response.cookies.set(...)` is reliably honored. The proxy hits `/me` once per protected navigation and only writes `NEXT_LOCALE` when the server preference differs from the incoming cookie, restoring the documented "server preference wins across devices" contract.

**Status note:** "fixed: requires human verification" — the new `proxy.ts` reconciliation path adds a fetch on protected navigations, which is a behavior change worth a manual smoke test (authenticated visit to `/onboarding` or `/settings` with `NEXT_LOCALE=vi` cookie + server `preferredLanguage=en` should land on the English render with the cookie rewritten).

### WR-03: Network failures during authenticated language switching skip rollback

**Files modified:** `apps/web/components/LanguageSwitcher.tsx`, `apps/web/__tests__/components/LanguageSwitcher.test.tsx`
**Commit:** `5645904`
**Applied fix:** Wrapped the authenticated PATCH branch in `try/catch/finally`. The `catch` block rolls the optimistic `NEXT_LOCALE` cookie back to `currentLocale` and renders the localized `errors.unknown` fallback (never the raw exception). The `finally` block always runs `onSettled?.()`. Added a Vitest case where `patchSpy.mockRejectedValueOnce(new TypeError('Failed to fetch'))` verifies cookie rollback plus alert text matches `errors.unknown` and never echoes `Failed to fetch`.

### WR-04: OpenAPI declares params values as objects instead of allowed scalars

**Files modified:** `backend/api/src/main/java/com/zeromail/api/config/OpenApiConfig.java`, `backend/api/src/test/java/com/zeromail/api/openapi/ApiErrorSchemaTest.java`, `apps/web/openapi/spec.json`, `apps/web/lib/api/schema.d.ts`
**Commit:** `c0f3a6e`
**Applied fix:** Defined a shared `safeParamScalar` schema (`oneOf: [string, integer, number, boolean]`) inside `apiErrorCustomizer()` and reused it as `additionalProperties` on both `ApiError.params` and `FieldErrorDto.params` — replacing the previous `new ObjectSchema()` value. Regenerated `apps/web/openapi/spec.json` plus `apps/web/lib/api/schema.d.ts` via `openapi-typescript`; the generated TypeScript now exposes `params?: { [key: string]: string | number | boolean }`, matching the actual `AllowedParamScalars`-filtered wire shape. Added an `ApiErrorSchemaTest.api_error_params_additional_properties_are_scalar_union` test that asserts the `oneOf` shape on both maps so a regression to `{ type: object }` fails the suite.
