## Decisions Made

- **Pitfall 1 sweep folded into Task 1.** Plan 02's `<read_first>` listed only the moved files; the 10 import sites were not enumerated in the action steps. But the verify command (`./gradlew :backend:core:compileJava :backend:api:compileJava`) would have failed with "cannot find symbol" on every stale import — making this Rule 3 (auto-fix blocking issue). Bundled into the Task 1 commit so no commit in `git log` ever has stale imports (Plan 01 lesson — separate fix-up commits make bisect noisier; better to land the sweep atomically). Tracked as deviation R1 below.
- **Task 2 had no code change.** `core.tenant/package-info.java` was already in the locked CL-3 form `allowedDependencies = {"shared.privacy"}` from Plan 01 Task 3 (the empirical probe step). Per the plan's own action-step 1 ("This task is a verification + safety net"), I confirmed the file is correct, ran the validation gates, and produced no commit. Task 2 contributes verification evidence but no modified code.
- **Proactive `lowlevel/` package-info.** CONTEXT D-D3 leaves `lowlevel/` per-domain creation as planner discretion ("proactive vs lazy"). I chose proactive: created the empty `core/tenant/persistence/lowlevel/package-info.java` now even though no native-SQL inhabitants exist yet. Reason: Plan 06 will update the ArchUnit regex from `..core.persistence.lowlevel..` to `..persistence.lowlevel..`. If the per-domain `lowlevel/` packages don't exist when that regex change ships, the rule no-ops silently — and silent no-ops are exactly the failure mode the regex update is meant to prevent. Pre-creating the package now makes Plan 06's rule update structural-surprise-free.
- **No fix-up commit needed.** Unlike Plan 01 Task 1 (which had to fix up stale package decls in a follow-on `9769dd7` commit), this plan staged the package-decl edits BEFORE running `git commit`. Verified by reading the renamed files in the working tree before staging. Self-check confirms.
