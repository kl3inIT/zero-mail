<objective>
Move `TenantEntity` and `TenantRepository` from the global `com.zeromail.core.persistence.*` bucket to the domain-owned `com.zeromail.core.tenant.persistence.*` package. Update `core.tenant/package-info.java` to declare its outgoing dependency on the new `shared.privacy` module (using the CL-3 form locked in Plan 01.2-01). Proactively create the empty per-domain `lowlevel/` marker (per planner discretion — see CONTEXT D-D3 + D-A3).

Purpose: Tenant is the foundational module that every other domain depends on. Moving it second (after privacy) sets the precedent for the per-domain `persistence/` + `lowlevel/` shape used in Plans 03-05 and proves the new Modulith allowed-dependency edge before touching the bigger account/onboarding/gmail moves.

**CRITICAL ENTITY-SCAN INTERIM:** `Application.java` and `CoreTestApplication.java` currently use `@EntityScan(basePackages = "com.zeromail.core.persistence")`. After this plan moves `TenantEntity` to `core.tenant.persistence`, the scan no longer covers it. **Plan 05 widens both scans to root `"com.zeromail.core"` — until then, this plan MUST also patch both `@EntityScan` and `@EnableJpaRepositories` to include both legacy and new locations.** See Task 1 step 5.

Output: TenantEntity + TenantRepository at the new path; old persistence files deleted; tenant package-info updated; new persistence/ and persistence/lowlevel/ package markers; both Application classes' entity-scan widened to discover the relocated entity.
</objective>
