# Phase 01.4 Plan 02: OAuth2 Second-Leg Integrity Dispatcher Summary

**One-liner:** Hardened OAuth2 callback boundary với typed-exception dispatcher: GmailOAuthSuccessHandler enforce same-Google-subject + delegate persistence; GmailOAuthFailureHandler revoke+redirect mismatch / consent-denied paths; cross-account grants bị reject TRƯỚC khi bất kỳ DB row nào được ghi (D-A1 / D-A3 / D-D4).

**Duration:** ~10 minutes (3 atomic tasks, 6 created + 4 modified Java/YAML files).

**Completed:** 2026-04-26T20:53:20Z

## What Landed

### Task 1 — Foundational primitives (commit `b88aa34`)

1. **`ErrorCodes.java`** — thêm 2 constants `GMAIL_IDENTITY_MISMATCH = "error.gmail.identity.mismatch"` và `GMAIL_CONSENT_DENIED = "error.gmail.consent.denied"` (mirror `error.gmail.disconnected` precedent line 24). Redirect query strings `gmail_identity_mismatch` / `gmail_consent_denied` (snake_case không có prefix `error.gmail.`) là contract độc lập per D-A3.

2. **`GmailIdentityMismatchException.java`** — `extends OAuth2AuthenticationException` để Spring Security route automatic qua failureHandler (RESEARCH Q2 recommendation; non-OAuth RuntimeException sẽ bypass và trigger 500). Carry `accessTokenToRevoke` field để failure handler revoke được sau khi AuthorizedClient bị remove (Pitfall 2). Privacy: OAuth2Error message + exception message KHÔNG chứa email/subject/token bytes (D-E1, T-1.4-02-token-leak).

3. **`GoogleTokenRevocationClient.java`** — Spring `@Component` wrap `RestClient`. Constructor inject `@Value("${google.revoke.base-url:https://oauth2.googleapis.com}")`. Method `revokeQuietly(String token)` POST `/revoke?token=<value>` với `Content-Type: application/x-www-form-urlencoded`; catch `RestClientException`, log chỉ `event=google_revoke_non_2xx` (T-1.4-02-revoke-token-leak). No-op khi token null/empty. Pitfall 8: không retry trên cùng token.

4. **`application.yml`** — thêm root-level `google.revoke.base-url` property (chèn giữa `zeromail:` block và `server:` block).

### Task 2 — GmailOAuthSuccessHandler (commit `1c121ae`)

5. **`GmailOAuthSuccessHandler.java`** — Spring `@Component`, `extends SimpleUrlAuthenticationSuccessHandler`, mirror `GoogleOAuthSuccessHandler` shape. Constructor: `(UserRepository, GmailConnectionService, RefreshTokenCipher, OAuth2AuthorizedClientService, PlatformTransactionManager, ZeroMailApiProperties)`. `setDefaultTargetUrl(...)` redirect `/onboarding` post-success.

   Flow trong `onAuthenticationSuccess`:
   1. Load `OAuth2AuthorizedClient` ĐÚNG 1 LẦN (Issue 3 mitigation).
   2. Capture `accessTokenForRevoke` local (chuỗi rỗng nếu null) để failure handler tái sử dụng.
   3. `users.findByGoogleSubject(leg2.getSubject())` — nếu thiếu, throw `GmailIdentityMismatchException(accessTokenForRevoke)`.
   4. Subject equality check (tautological with step 3 nhưng giữ explicit cho future refactor).
   5. Extract refreshToken + scopes từ AuthorizedClient (no second loadAuthorizedClient call).
   6. Filter scopes theo `https://www.googleapis.com/auth/gmail.` prefix (Pitfall 5: include_granted_scopes returns leg-1 openid+profile+email — không phải audit trail của Gmail connection).
   7. **`ScopedValue.where(TenantContext.TENANT, tenantId.toString()).run(() -> tx.executeWithoutResult(...))`** — bind ScopedValue TRƯỚC khi mở JPA transaction (Pitfall 6 / FND-05; mirror `OAuthProvisioningService.createTenantAndUser` lines 78-86).
   8. Trong tx: encrypt refresh-token via `cipher.encrypt(bytes, tenantId)`, gọi `connections.upsert(tenantId, email, gmailScopes, envelope)`, advance user.advanceTo(GMAIL_CONNECTED), save.
   9. Log `event=gmail_connection_upserted tenantId={UUID}` only.

6. **`GmailConnectionService.upsert(...)`** — *signature only* (throws `UnsupportedOperationException("Plan 01.4-03 lands implementation")`). Cross-plan seam: signature lives Plan 02 nên `compileJava` GREEN; body lands Plan 03.

### Task 3 — Failure handler + dispatchers + SecurityConfig (commit `b8efe6d`)

7. **`OAuth2LoginDispatchingSuccessHandler.java`** — single bean wire vào `oauth2Login().successHandler(...)`. Switch trên `OAuth2AuthenticationToken.getAuthorizedClientRegistrationId()`: `"google"` → `GoogleOAuthSuccessHandler` (Phase 1.1 invariant — không thay đổi behavior); `"google-gmail"` → `GmailOAuthSuccessHandler`; default → `super.onAuthenticationSuccess(...)`.

8. **`GmailOAuthFailureHandler.java`** — distinguish thrown-exception type:
   - `GmailIdentityMismatchException` → `removeAuthorizedClient(GMAIL_REGISTRATION_ID, principalName)` (Pitfall 2 / T-1.4-02-stale-grant) + `revokeQuietly(captured token)` + redirect `/onboarding?error=gmail_identity_mismatch`. Log `event=gmail_identity_mismatch outcome=rejected`.
   - `OAuth2AuthenticationException` với `error=access_denied` → redirect `/onboarding?error=gmail_consent_denied`, NO revoke (no token issued). Log `event=gmail_consent_denied outcome=user_declined`.
   - Other failures → `super.onAuthenticationFailure(...)` (preserve existing semantics for non-Gmail flows).

9. **`OAuth2LoginDispatchingFailureHandler.java`** — single bean wire vào `oauth2Login().failureHandler(...)`. Dispatch criterion = thrown-exception type (`AuthenticationException` không carry registration id reliably). Cả `GmailIdentityMismatchException` lẫn `OAuth2AuthenticationException(access_denied)` route tới `GmailOAuthFailureHandler`. Future provider-specific failure handlers extend cùng pattern.

10. **`SecurityConfig.java`** — replace constructor parameter `GoogleOAuthSuccessHandler successHandler` bằng `OAuth2LoginDispatchingSuccessHandler dispatchSuccess` + `OAuth2LoginDispatchingFailureHandler dispatchFailure`; chain bây giờ:
    ```java
    .oauth2Login(o -> o
        .successHandler(dispatchSuccess)
        .failureHandler(dispatchFailure)
        .authorizationEndpoint(a -> a.authorizationRequestResolver(gmailResolver)))
    ```
    `GoogleOAuthSuccessHandler` bean vẫn ở context — dispatcher inject nó.

### Auto-fixed Issues

**1. [Rule 3 — Blocking] `TransactionTemplate` không phải bean toàn ứng dụng**
- **Found during:** Task 2 implementation review.
- **Issue:** Plan đề xuất constructor inject `TransactionTemplate tx`. Spring Boot không auto-config `TransactionTemplate` bean — chỉ có `PlatformTransactionManager`. Việc inject `TransactionTemplate` trực tiếp sẽ fail Spring DI nếu chưa định nghĩa bean (Phase 01.2 chưa expose).
- **Fix:** Mirror `OAuthProvisioningService` precedent — inject `PlatformTransactionManager` rồi build `TransactionTemplate` nội bộ trong constructor (`new TransactionTemplate(txManager)`). Pattern đã có sẵn trong codebase (`backend/core/src/main/java/com/zeromail/core/account/service/OAuthProvisioningService.java` lines 47-52). Không cần expose new bean.
- **Files modified:** `GmailOAuthSuccessHandler.java` (constructor signature change từ `TransactionTemplate` → `PlatformTransactionManager`).
- **Verification:** `compileJava` GREEN; full test suite vẫn boot Spring context (FailureHandler 3/3 GREEN proves DI wires correctly).
- **Commit:** `1c121ae`
