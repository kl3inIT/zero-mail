# Phase 01.4 — UI Design Contract

> Visual and interaction contract for the Gmail identity semantics + UI consistency sweep. Generated by gsd-ui-researcher from CONTEXT.md (decisive), STATE.md, ROADMAP.md, REQUIREMENTS.md. Verified by gsd-ui-checker.

**Phase scope reminder:** ship a tokens layer + 5 reusable primitives, refactor every current frontend surface to consume them, add the Next.js error-boundary baseline, and surface localized Gmail mismatch / consent-denied alerts. Brand identity (logo, final palette, font pairings, illustrations) stays Phase 5.

## Typography

Tailwind 4 default scale, restricted to 4 sizes and 2 weights for v1:

| Role | Class | Size / Line-Height | Weight | Usage |
|------|-------|--------------------|--------|-------|
| Body | `text-base` | 16px / 1.5 (24px) | 400 (regular) | Default paragraph, alert body, form helper text, MDX prose body |
| Label | `text-sm` | 14px / 1.4 (~20px) | 500 (medium) | Form labels, badges, footer notes (`settings.gmailConnection.singleAccountNote`), button text |
| Heading | `text-xl` | 20px / 1.3 (~28px) | 600 (semibold) | `<SectionCard>` heading, `/settings` section titles, alert titles |
| Display | `text-3xl` | 30px / 1.2 (36px) | 600 (semibold) | Page heading on `/login`, `/onboarding` step heading, landing H1, `/docs` index heading, `<EmptyState>` heading |

**Locked rules:**

- **Two weights only:** `font-normal` (400) and `font-semibold` (600). NO `font-medium` (500) introduction beyond the existing shadcn-default usage in primitives — keeps the contract testable.
- **Body line-height = 1.5** (Tailwind `leading-normal` / `leading-6`). Heading line-height tightens to ~1.2–1.3 (`leading-snug` / `leading-tight`).
- **No font-family overrides in Phase 01.4.** All copy inherits `font-sans` from the `html` rule in `globals.css`. Code blocks inside MDX use `font-mono`.
- **Auxiliary `text-xs` (12px)** allowed only inside shadcn primitives that already use it (e.g., Badge default). Do NOT introduce `text-xs` in new application code — drift target.

**Source of decision:** CONTEXT.md does not pin specific px values; defaults derived from shadcn neutral preset + Tailwind 4 defaults + the user's persistent feedback memory (frontend-design skill discipline). Tailwind class names match Phase 1.3 codebase (`text-3xl font-bold tracking-tight` on `(public)/page.tsx` H1 — refactor to `text-3xl font-semibold tracking-tight` for weight consistency).

## Color

60 / 30 / 10 split mapped onto the existing shadcn neutral tokens. **No raw color names** (`text-stone-*`, `bg-white`, `text-gray-500`) anywhere in JSX (CONTEXT.md D-C2). All references go through token-aware utilities.

| Role | % | Token (CSS variable) | Tailwind class | Usage |
|------|---|----------------------|----------------|-------|
| Dominant | 60% | `--background` (`oklch(1 0 0)` light / near-black dark) | `bg-background`, `text-foreground` | Page background, primary text on every surface |
| Secondary | 30% | `--card`, `--secondary`, `--muted` (near-white surfaces in light) | `bg-card`, `bg-muted`, `text-muted-foreground` | `<SectionCard>` surfaces, `<StatusAlert variant="info">` background, sidebar-style nav, footer notes, MDX code background |
| Accent | 10% | `--primary` (near-black neutral; placeholder for Phase 5 brand) | `bg-primary`, `text-primary`, `text-primary-foreground` | **Reserved-for list below.** Never on body text, never on borders, never on multiple CTAs per page |
| Destructive | semantic | `--destructive` (`oklch(0.577 0.245 27.325)` red) | `text-destructive`, `bg-destructive`, `border-destructive` | DeleteAccountDialog confirm button; `<StatusAlert variant="error">` accents only |
| Border / Ring | structural | `--border`, `--ring` | `border-border`, `ring-ring` | All borders, focus-ring outlines |

**Accent reserved for (explicit list — anything outside this is a violation):**
1. The single primary CTA per page: `[Connect Gmail]` on `/onboarding` first step, `[Sign in with Google]` on `/login`, `[Get started]` on landing.
2. `[Try again]` retry CTA inside `<StatusAlert variant="error">` when it's the page's primary recovery action.
3. The active link state in `LanguageSwitcher`'s currently-selected locale.
4. Active step indicator in the onboarding step machine (if rendered as breadcrumbs).

**Status alert color mapping (extension — discretion item):**

| Variant | Background | Foreground | Icon |
|---------|------------|------------|------|
| `info` | `bg-muted` | `text-foreground` | `<Info />` |
| `success` | Existing shadcn neutral; if executor adds a `--color-success` token in `globals.css`, place it here | `text-foreground` | `<CheckCircle2 />` |
| `warn` | Existing shadcn neutral; if executor adds a `--color-warning` token, place it here | `text-foreground` | `<AlertTriangle />` |
| `error` | `bg-destructive/10` (10% opacity) | `text-destructive` | `<AlertCircle />` |

**Discretion (per CONTEXT.md):** executor may extend `globals.css` with `--color-success` / `--color-warning` semantic tokens (Tailwind 4 `@theme inline` block) if review finds the all-neutral info/success/warn variants too indistinguishable. Default = ship neutral; revisit during sweep review.

**Privacy color rule:** error alert copy MUST NOT include the user's email, Google subject, refresh-token bytes, or any stack-trace fragment (CONTEXT.md D-D3 + Phase 1 D-E1). Color is structural only — it does not unlock leaking data.

### Per-element contract

| Element | Key path | Notes |
|---------|----------|-------|
| Primary CTA (onboarding step 1) | existing `onboarding.connectGmail.cta` | Verb + noun form: "Kết nối Gmail" / "Connect Gmail" — do NOT change |
| Primary CTA (login) | existing `auth.login.signInWithGoogle` | Preserved verbatim |
| Primary CTA (landing) | existing `landing.primaryCta` | Preserved verbatim |
| Empty state heading (404) | `errors.notFound.title` | Confident, not apologetic |
| Empty state body (404) | `errors.notFound.body` | Tells user what happened + offers exit (`backHome` link) |
| Empty state heading (docs index when zero entries) | existing `docs.empty.heading` | Preserved (Phase 1.3 P07) |
| Error state (Gmail mismatch) | `gmail.identity.mismatch.{title,body,cta}` | Problem stated + retry path; never names the wrong account |
| Error state (consent denied) | `gmail.consent.denied.{title,body,cta}` | Frames Gmail access as a triage requirement, not a guilt trip |
| Error state (route boundary) | `errors.boundary.{title,body,reset}` | Generic — never reveals exception details |
| Destructive confirmation | existing `account.delete.confirmTitle` + `confirmBody` | Preserved; verify no raw English fallback in `DeleteAccountDialog` post-token migration |
| `global-error.tsx` last-resort | inline English: "Something went wrong. Please reload." + "Reload" button | Locked English-only; next-intl provider unavailable at root replacement (CONTEXT.md D-D3) |

### Copywriting voice

- **Confident, not apologetic.** "Zero Mail v1 supports one Gmail account" — NOT "Sorry, only one account is supported".
- **Forward-looking on limits.** Reference "roadmap" without committing to a date (`singleAccountNote`).
- **Action-oriented errors.** Every error state must have a clear next step (CTA or link), never a dead-end.
- **No app-name shortening.** "Zero Mail" everywhere; never "Zero" alone.
- **Vietnamese-first feel.** vi copy is conversational and natural, not a literal English translation. en copy is the mirror, not the source.

## Interaction & State Contracts

| State | Contract |
|-------|----------|
| **Focus visibility** | Every interactive element MUST show a `ring-ring`-class outline on `:focus-visible` (Tailwind 4 default `focus-visible:ring-2 focus-visible:ring-ring`). Don't rely on browser default. |
| **Hover states** | shadcn `<Button>` defaults preserved. New primitives (`<StatusAlert>` CTA, `<EmptyState>` CTA) inherit Button styles via `<Button asChild>` or composition — never reinvent hover. |
| **Disabled states** | `disabled:opacity-50 disabled:pointer-events-none` (shadcn default). Verify on `LanguageSwitcher` during refactor. |
| **Loading states** | Each suspense boundary (every `loading.tsx`) renders `<LoadingState variant="card">` by default. NEVER a blank flash. |
| **Empty states** | Every list view that can be empty renders `<EmptyState>` not "(no items)". 01.4 ships only the 404 instance; future views inherit the contract. |
| **Error states** | (a) Inline (in-page) errors render `<StatusAlert variant="error">`. (b) Route-segment crashes render `error.tsx` with `<SectionCard>` + `<StatusAlert variant="error">` + Reset button. (c) Root crash renders `global-error.tsx` (English-only). NEVER show `error.message` or `error.stack` to the user. `console.error(error)` allowed only when `process.env.NODE_ENV !== 'production'`. |
| **Reset/retry behavior** | `error.tsx` Reset button calls Next 16's `reset()` prop. `<StatusAlert>` CTA "Try again" on `/onboarding` re-triggers `/tenant/connect-gmail`. `not-found.tsx` "Back home" is a `<Link href="/">`. |
| **URL hygiene after error dismissal** | After the user dismisses the `?error=gmail_*` alert (or `useTenantStatus` reports CONNECTED), call `router.replace('/onboarding')` to clear the query param (CONTEXT.md D-D1). |
| **Prefer `<Link>` over `<Button asChild>` for navigation** | Phase 1.3 P05 D-decision: use `<Link className={buttonVariants()}>` not `<Button asChild>` (the local Button wraps a primitive that doesn't support `asChild`). Reaffirmed for 01.4. |
