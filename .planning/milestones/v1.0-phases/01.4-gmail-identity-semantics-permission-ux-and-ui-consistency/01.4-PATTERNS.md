#### `GmailScopeRequestResolver.customize()` (modification)

```java
private OAuth2AuthorizationRequest customize(OAuth2AuthorizationRequest r) {
    if (r == null) return null;
    Object regId = r.getAttribute("registration_id");
    if (regId == null || !GMAIL_REGISTRATION_ID.equals(regId.toString())) return r;
    var extra = new HashMap<>(r.getAdditionalParameters());
    extra.put("include_granted_scopes", "true");
    extra.put("prompt", "consent");
    extra.put("access_type", "offline");
    return OAuth2AuthorizationRequest.from(r).additionalParameters(extra).build();
}
```

**Adaptation:** Inside the `if (regId equals)` branch, before building, read `SecurityContextHolder.getContext().getAuthentication()`; if non-anonymous and principal exposes an email (cast or lookup `UserRepository`), `extra.put("login_hint", email)`. **Graceful degrade:** if no auth or no email, skip the put silently (RESEARCH Finding #4 + Specifics line "login_hint is graceful-degrade"). Do NOT throw, do NOT redirect.

**`SectionCard` adaptation (UI-SPEC §Component Inventory):**
- RSC by default (no client directive needed).
- Props: `heading?: string` (i18n key), `description?: string` (i18n key), `footer?: ReactNode`, `children` (body), `className?`.
- Internally: server component must accept already-resolved strings (not keys) to avoid client boundary; alternative — accept `headingKey`/`descriptionKey` and wrap in a client island. ### ScopedValue + tenant binding ordering (CRITICAL)

**Source:** `backend/core/src/main/java/com/zeromail/core/account/service/OAuthProvisioningService.java` lines 78–86 (entire `createTenantAndUser` method).

**Apply to:** `GmailOAuthSuccessHandler` persistence path AND `GmailConnectionService.upsert` callers.

```java
return ScopedValue.where(TenantContext.TENANT, tenantId.toString())
        .call(() -> provisioningTx.execute(status -> {
            // persistence calls here — JPA session opens AFTER ScopedValue is bound
        }));
```

**Why critical (analog comment lines 27–30):** "the create path binds `TenantContext` before opening a `REQUIRES_NEW` transaction. Hibernate captures the current tenant when the JPA session opens; opening the tx first would capture the bootstrap tenant and reject the user insert." Same hazard applies to Gmail upsert — bind tenant FIRST.

### Privacy / logging contract

**Source:** `backend/core/src/main/java/com/zeromail/core/account/service/OAuthProvisioningService.java` line 72 (`log.warn("OAuth provisioning lost a unique-constraint race; converging on existing user");` — note: no email, no subject in message) + class JavaDoc lines 22, 71.

**Apply to:** All new backend code in this phase.

- Allowed: structured event names (`event=gmail_identity_mismatch`, `event=gmail_connection_upserted`), `tenantId` (UUID is opaque), HTTP status codes from outbound calls, error code constants.
- Frontend: NEVER render `error.message` or `error.stack` in any boundary (CONTEXT D-D3); `console.error` allowed only when `NODE_ENV !== 'production'`.

### Refresh-token encryption envelope

**Source:** `backend/core/src/main/java/com/zeromail/core/gmail/persistence/crypto/RefreshTokenCipher.java` lines 36–53 (`encrypt` method).

**Apply to:** `GmailOAuthSuccessHandler` encrypts the leg-2 refresh token before passing to `GmailConnectionService.upsert`:
```java
byte[] envelope = refreshTokenCipher.encrypt(refreshToken.getBytes(StandardCharsets.UTF_8), tenantId.toString());
```

Consume verbatim — do NOT invent a parallel encryption path. Envelope shape `[key_version:int32 | nonce:12 | ciphertext:variable]` with `tenantId` as AAD is the contract.
