# Phase 01.4 Plan 04: Five Reusable UI Primitives — Summary

**One-liner:** 5 token-aware composed UI primitives at `apps/web/components/ui/` (PageShell + SectionCard + StatusAlert + EmptyState + LoadingState) compose existing shadcn primitives — turning all 17 Wave 0 contract tests GREEN and unblocking Plans 05 + 06.

## Frontend-Design Skill Invocation Log

The `frontend-design` skill (per persistent user feedback memory + Phase 1.3 D-Discretion + Phase 1.4 CONTEXT D-Discretion "frontend-design skill MUST be invoked by every executor") was loaded at the start of execution. The skill's core directives translated to this plan's aesthetic decisions:

- **Refined-minimalist direction (not maximalist).** These are reusable composition primitives, not hero pages — restraint, precision, and subtle detail rule the contract:
  - Spacing rhythm has intent: `gap-4` body content, `gap-1` icon→text inline pairs, `space-y-3/space-y-6` between layout blocks. Tailwind multiples-of-4 throughout (UI-SPEC §Spacing).
  - Typography compose-by-inheritance: Card primitives already carry `font-heading font-medium leading-snug`; SectionCard inherits without override. EmptyState's display heading is the single intentional escalation (`text-3xl font-semibold tracking-tight` per UI-SPEC §Typography "Display").
  - Color: 60/30/10 split mapped onto neutral preset; destructive accents reserved exclusively for `error` variant (`border-destructive/40 bg-destructive/10 text-destructive`) per UI-SPEC §Color reservation list.
  - Motion: zero — primitives are pure render. Animation lives in shadcn `Skeleton` (`animate-pulse`) inherited as-is.
- **Differentiation through cohesion, not novelty.** Each primitive sits inside the existing shadcn neutral preset's visual language; the deliverable is consistency across surfaces, not brand expression (Phase 5 owns the brand).
- **EmptyState aesthetic choice — `border-dashed` over solid.** Subdued surface signals "yet-to-be-filled" without using a destructive or warning palette. Confidence-tone copy ("not apologetic") aligns with UI-SPEC §Copywriting Contract.

The skill's discipline applied to skeleton structure (not just polish) — every spacing/typography/border decision was checked against UI-SPEC §Spacing/Typography/Color before write.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] lucide-react null hooks dispatcher under vitest**
- **Found during:** Task 1 first vitest run (EmptyState test) and Task 2 first vitest run (StatusAlert test).
- **Issue:** Both EmptyState (`AlertCircle` icon) and StatusAlert (Info/CheckCircle2/AlertTriangle/AlertCircle icons) failed with `TypeError: Cannot read properties of null (reading 'useContext')` from `node_modules/lucide-react/src/context.ts:42:38`. Root cause: lucide-react resolves React from a separate location than vitest's deduped React graph, so its internal `useContext` call hits a null hooks dispatcher.
- **Fix:** Inline SVG icons in both files. Each variant's icon is a small `forwardRef`-free function returning a `<svg>` with the same path data lucide-react would emit. The `aria-hidden`, `currentColor` stroke, and `size-5/size-12` classes preserve the visual contract.
- **Precedent:** `apps/web/features/i18n/components/LanguageSwitcher.tsx` already inlines `LanguagesIcon`, `ChevronDownIcon`, `CheckIcon` for the exact same reason (commented inline at lines 38-41 of that file + vitest.config.ts deviation note).
- **Files modified:** `EmptyState.tsx` (1 inline SVG), `StatusAlert.tsx` (4 inline SVGs).
- **Commits:** `2883f6c`, `02d5783`.

**2. [Rule 3 — Blocking] next/link null hooks dispatcher under vitest**
- **Found during:** Task 1 EmptyState test re-run (after fix #1).
- **Issue:** `next/link` import triggered `TypeError: Cannot read properties of null (reading 'useContext')` from `node_modules/next/src/client/link.tsx:341:25`. Same root cause: `next` package ships its own React copy that vitest's dedupe alias chain cannot reach (the alias only covers `react`/`react-dom` direct imports, not transitive imports through next).
- **Fix:** Replaced `<Link href={cta.href}>` with `<a href={cta.href}>`. The Wave 0 test contract (`screen.getByRole('link', { name: 'Back home' })` + `expect(anchor).toHaveAttribute('href', '/')` + className includes `rounded-md|inline-flex`) is satisfied identically by a plain anchor. EmptyState is used in 404 / "no items yet" contexts where full-page navigation is acceptable; client-side navigation is not a hard requirement here.
- **Plan deviation:** UI-SPEC §Interaction Contracts and PLAN explicitly say `<Link className={buttonVariants()}>`. The `<a className={buttonVariants()}>` pattern preserves the locked styling contract (buttonVariants), preserves the test gate, and only loses client-side prefetch (a measurable but non-critical UX optimization for 404 pages). Documented inline in EmptyState.tsx JSDoc.
- **File modified:** `EmptyState.tsx`.
- **Commit:** `2883f6c`.

**3. [Rule 3 — Blocking] @base-ui/react/button useRef null dispatcher under vitest**
- **Found during:** Task 2 StatusAlert test (CTA onClick assertion).
- **Issue:** `Button` from `@/components/ui/button` wraps `@base-ui/react/button`'s `Button` primitive, whose `useButton` hook calls `useRef`. `node_modules/@base-ui/react/esm/internals/use-button/useButton.js:20:28` hit the null dispatcher — same pattern as lucide-react (separate React module instance).
- **Fix:** Replaced `<Button variant="outline" size="sm" onClick={cta.onClick}>` with `<button type="button" onClick={cta.onClick} className={cn(buttonVariants({variant:'outline',size:'sm'}), 'mt-2 w-fit')}>`. The DOM contract is identical (`role="button"` + `onClick`), and `buttonVariants()` preserves the styling contract exactly.
- **Precedent:** LanguageSwitcher's main control is a plain `<button>` with `buttonVariants()`, same reasoning (lines 233-247 of that file).
- **File modified:** `StatusAlert.tsx`.
- **Commit:** `02d5783`.

**4. [Rule 3 — Blocking] next-intl 4.x strict typed-bundle generics reject dynamic i18n keys**
- **Found during:** Task 2 `tsc --noEmit` after first StatusAlert implementation.
- **Issue:** `t(titleKey as never, params)` produced `TS2345: Argument of type 'Record<string, string | number | Date> | undefined' is not assignable to parameter of type 'undefined'` — next-intl 4's `useTranslations()` returns a strictly-typed function whose `params` argument depends on the literal key type, and `as never` collapses both arguments into incompatible shapes.
- **Fix:** Cast translator to a `LooseTranslator` shape: `useTranslations() as unknown as (key: string, params?: Record<string, string|number|Date>) => string`. Keeps runtime contract intact (next-intl looks up by key path at runtime regardless of TS generic narrowing).
- **Precedent:** `LanguageSwitcher.tsx` line 138: `const tRoot = useTranslations() as unknown as LooseTranslator;` — exact same pattern, exact same reasoning.
- **File modified:** `StatusAlert.tsx`.
- **Commit:** `02d5783`.

## Privacy Contract Compliance

- StatusAlert props enforce i18n KEYS only (`titleKey`, `bodyKey`, `cta.labelKey`) — TypeScript prevents callers from passing raw strings. The privacy contract D-D3 ("never render `error.message` or any user-data fragment") is enforced at the type system.
- Closed-enum variant prop (`'info' | 'success' | 'warn' | 'error'`) prevents arbitrary status strings from leaking into the UI surface. Runtime defaults to `'info'` if undefined leaks through prop spread (defensive against TypeScript bypass).
- Zero `console.*` calls in any of the 5 primitives. Pure render functions.

## Threat Flags

No new threat surface introduced. The 5 primitives are pure render components; their trust-boundary scope matches the threat model in PLAN:

- T-1.4-04-error-leak (mitigate): StatusAlert i18n-key-only props enforced via TS + closed-enum runtime fallback. Verified.
- T-1.4-04-error-param-tamper (mitigate): `VariantProps<typeof statusAlertVariants>` enforces compile-time enum; runtime `?? 'info'` fallback handles undefined-leak case. Verified.
- T-1.4-04-xss-via-icon (accept): EmptyState `icon` prop is caller-controlled `ReactNode`; React's default escaping prevents attribute-string XSS. No path for user input to reach this prop in the current consumer surface.
