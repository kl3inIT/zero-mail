<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pub/Sub delivery transaction → event registry | The `MailMessageObserved` row must commit atomically with `mail_message_observed`; a non-transactional publisher would lose the action on listener failure / JVM crash. |
| event payload → downstream LLM call path | The orchestrator (Wave 3) feeds event-derived ids into a Gmail metadata fetch then an LLM call; the event itself must carry no email content (privacy invariant). |
| `core.triage` module boundary | Modulith `allowedDependencies` is the architectural fence preventing triage from reaching into other domains' internals. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | Tampering / Repudiation | `MailMessageObserved` publication | mitigate | Published via Spring Modulith JDBC registry inside the existing `@Transactional` delivery method (D-A1) — the event row commits with the observed-message insert; a crash leaves an `INCOMPLETE` publication the Wave-4 retry job resubmits, never a lost action. |
| T-04-01-02 | Information Disclosure | event payload | mitigate | `MailMessageObserved` is a 4-component record (`tenantId, gmailMessageId, gmailThreadId, observedAt`); ArchUnit-adjacent Wave-0 contract test asserts no subject/snippet/body/sender-name field; the publish-site log line carries ids only. |
| T-04-01-03 | Tampering (idempotency) | publish on duplicate delivery | mitigate | Publish fires only when `insertObservedIfAbsent` returns `1`; Pub/Sub redeliveries the Phase 2A layer absorbs publish nothing → no double-triage from a redelivered notification. |
| T-04-01-04 | Elevation of Privilege | `core.triage` allowedDependencies | mitigate | The module declares the minimal edge set and explicitly omits a direct `gmail.persistence.crypto` edge; `ApplicationModulesTest` fails the build on any undeclared cross-module access. |
| T-04-01-05 | Tampering | `024` schema vs Modulith expectations | mitigate | Changelog `024` mirrors the DDL dumped from the running starter (Pitfall 2), not authored from memory; auto-init disabled so Liquibase is the single source of truth. |
</threat_model>
