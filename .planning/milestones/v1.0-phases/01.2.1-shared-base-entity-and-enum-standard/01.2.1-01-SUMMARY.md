# Phase 01.2.1 Plan 01: Shared Base Entity Hierarchy + JPA Auditing + Audit-Column Migration Summary

3-tier `@MappedSuperclass` hierarchy (`AbstractEntity` → `AbstractAuditableEntity` → `AbstractTenantOwnedEntity`) wired to Spring Data JPA Auditing via Clock-backed `DateTimeProvider`, paired with Liquibase changeset 007 that adds the audit columns + backfills + Modulith graph updates — all delivered atomically so Hibernate `validate` never sees a missing column.

## Final Entity Hierarchy

```
AbstractEntity                      (id only)            ← TenantEntity
  └─ AbstractAuditableEntity        (+ createdAt, updatedAt, @Version version)
       └─ AbstractTenantOwnedEntity (+ @TenantId tenantId)
            ├─ UserEntity
            ├─ OnboardingSelectionEntity
            └─ GmailConnectionEntity
```

`@EntityListeners(AuditingEntityListener.class)` lives on `AbstractAuditableEntity` and inherits to both tenant-owned and tier-3 entities. `TenantEntity` does not pick up the listener (Tier 1 only) — by design per D-A1.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] gmail_connections table missing created_at column → added in changeset 007**

- **Found during:** Task 3 verification (`./gradlew :backend:core:check`)
- **Issue:** Plan and PATTERNS assumed all 3 tenant-owned tables had `created_at`. They didn't — `gmail_connections` was created in changeset 003 without `created_at`. Without this column the backfill `UPDATE gmail_connections SET updated_at = created_at WHERE updated_at IS NULL` failed at Liquibase apply time with `ERROR: column "created_at" does not exist`. Hibernate `validate` would also have failed against `AbstractAuditableEntity.createdAt @Column("created_at", nullable=false)` mapping.
- **Fix:** Prepended the changeset with an `addColumn` for `created_at TIMESTAMPTZ DEFAULT now()` on `gmail_connections`, plus a backfill `UPDATE gmail_connections SET created_at = COALESCE(connected_at, NOW()) WHERE created_at IS NULL`, then promoted the column to NOT NULL — matching the pattern for `updated_at`. Added `dropColumn created_at` to rollback.
- **Files modified:** `backend/core/src/main/resources/db/changelog/changes/007-add-audit-columns.yaml`
- **Commit:** `7b50b83`

**2. [Rule 1 - Bug] Raw-SQL inserts (GmailConnectionUniquenessTest) failed NOT NULL on new audit columns → added defaultValueComputed: now()**

- **Found during:** Task 3 verification (second pass after fix #1)
- **Issue:** `GmailConnectionUniquenessTest` (extends `PostgresContainerTest`) uses `JdbcTemplate.update("insert into gmail_connections(id, tenant_id, google_email, status) values(?, ?, ?, ?)", ...)` — raw SQL that doesn't pass through Hibernate's `AuditingEntityListener`. With the new audit columns NOT NULL and no DB default, the test failed with NOT NULL constraint violation BEFORE reaching the unique-constraint assertion it actually exercises.
- **Fix:** Added `defaultValueComputed: now()` to all `created_at` and `updated_at` `addColumn` blocks. This matches the existing pattern on `users.created_at` (changeset 002 line 14: `defaultValueComputed: now()`). The Spring Data JPA `AuditingEntityListener` still writes deterministic Clock-driven values for entity-managed inserts and overrides any DB default — no behavior change for production code.
- **Files modified:** `backend/core/src/main/resources/db/changelog/changes/007-add-audit-columns.yaml`
- **Commit:** `7b50b83` (folded into Task 3 commit because the changeset edits are tightly coupled with the entity refactor verification)

Both fixes are correctness fixes (Rule 1) — no architectural change; the plan's intent is preserved (audit columns are added; tenants stays out of scope; rollback is reversible). The DB-default addition is a strict superset of the plan's behavior because the Java auditing listener still wins for entity-managed paths.
