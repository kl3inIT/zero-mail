# Phase 01.2.1 Plan 03: Enum Standard Adoption + WR-01/WR-02/WR-03 Closure Summary

Wires the Plan 02 interface contracts (`OrderedEnum` / `IdentifiedEnum`) into the two existing domain enums, swaps `UserEntity.advanceTo` from ordinal-based comparison to explicit `weight()`, upgrades the bulk delete in `OnboardingService` to a JPQL `@Modifying` query with explicit tenant WHERE, replaces the pure-JVM `OnboardingStepEnumPersistenceTest` with a real-Postgres parametrized round-trip + raw-column assertion, and updates 3 domain Modulith `allowedDependencies` arrays to include `"shared.lang"`. Closes Phase 1.2 code-review warnings WR-01, WR-02, WR-03 and Phase 1.2.1 success criteria #2/#3/#5.

## Closure Map

| ID | Closure | Mechanism |
| --- | --- | --- |
| **WR-01** | Real-DB enum persistence test | New `OnboardingStepPersistenceTest extends PostgresContainerTest`, `@ParameterizedTest @EnumSource(OnboardingStep.class)` × 4 executions. Each: seed `tenants` row → bind `TenantContext.TENANT` ScopedValue → `users.saveAndFlush(UserEntity)` → `JdbcTemplate.queryForObject("SELECT onboarding_step ...")` raw column read → assert raw value == `step.id()` AND `data_type = 'character varying'`. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] CoreTestApplication missing `@EnableJpaAuditing` → Hibernate INSERT bound NULL on `@CreatedDate` / `@LastModifiedDate` → NOT NULL constraint on `users.created_at` failed**

- **Found during:** Task 3 first verification run of `OnboardingStepPersistenceTest`.
- **Issue:** All 4 parameterized executions failed with `null value in column "created_at" of relation "users" violates not-null constraint`. Root cause: production `JpaAuditingConfig` lives in `com.zeromail.api.config` (Plan 01 Task 1), but `CoreTestApplication` declares `scanBasePackages = "com.zeromail.core"` — so the `@EnableJpaAuditing` annotation is never picked up by the core integration-test context. Hibernate emits an INSERT statement with explicit NULL for the `@CreatedDate` field (and similarly `updatedAt`); the per-column `defaultValueComputed: now()` from changeset 007 does NOT fill the value because PostgreSQL DB defaults only apply to columns ABSENT from the INSERT, not to columns bound to NULL. The `OnboardingStepEnumPersistenceTest` (the old pure-JVM tautology) never persisted anything so the gap was never exposed before.
- **Fix:** Created `backend/core/src/test/java/com/zeromail/core/support/TestJpaAuditingConfig.java` — a test-only mirror of `api/JpaAuditingConfig` with the same `Clock` + `DateTimeProvider` + `@EnableJpaAuditing(dateTimeProviderRef = "appDateTimeProvider")` wiring. Picked up automatically by `CoreTestApplication`'s scan because it lives under `com.zeromail.core.support`.
- **Files created:** `backend/core/src/test/java/com/zeromail/core/support/TestJpaAuditingConfig.java`
- **Commit:** `e3ed1b7` (folded into the Task 3 commit because the test cannot be exercised without it; documenting it as a separate fix-up commit would have left the test red between Task 3 and the fix).

**Why a test-only mirror, not a production move:** `JpaAuditingConfig` belongs to `backend/api` per Plan 01's deliberate boundary (api owns Spring application config; core owns domain). Promoting it to `backend/core` would either (a) make `core` depend on Spring application infrastructure it does not need at runtime, or (b) duplicate scan-config decisions across two modules. The test-side mirror is the smallest correct surface — same wiring, only seen by tests. Future core-test classes that persist `AbstractAuditableEntity` subclasses with `saveAndFlush` will work without copy-paste.
