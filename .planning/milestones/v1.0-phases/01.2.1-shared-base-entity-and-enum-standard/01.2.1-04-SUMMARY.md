## Issues Encountered

- **Initial spec-emit attempt collided with port 8080.** A different application (Vaadin / Spring Boot 3.5) was already on `localhost:8080`. The plugin fetched `/v3/api-docs` and got an HTML response. Switched to port 58080 (`customBootRun.args.set(["--server.port=58080", ...])`) + matching `apiDocsUrl`. Resolved.
- **Spring Boot Docker Compose autostart needed `docker` on PATH.** Forked JVM inherited the calling shell's `PATH`; Git Bash's default PATH did not include the Windows Docker Desktop CLI. Augmented PATH for the gradle invocation: `export PATH="/c/Program Files/Docker/Docker/resources/bin:$PATH"`. Documented for future hermetic-emit invocations.
- **Setting `customBootRun.workingDir` triggered Gradle 9 input-tracking failure.** Gradle tried to MD5-hash the entire repo root (including `.gradle/9.4.1/checksums/checksums.lock`). Resolution: keep workingDir unset; pass `--spring.docker.compose.file=<absolute path>` via args instead.
- **Boot failed without OAuth credentials.** `OAuth2 Client id of registration 'google' must not be empty`. Resolution: pass dummy `--spring.security.oauth2.client.registration.google.client-id=openapi-emit` (and -secret, plus the `google-gmail` registration, plus `--spring.cloud.gcp.secretmanager.enabled=false`, plus a 32-byte zero AES key for `zeromail.crypto.refresh-token-key-base64`). Boot succeeded in 16.5 s.
