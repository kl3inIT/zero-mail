## Decisions Made

- **i18n:check is WARN-ONLY in lint-staged until Plan 07's final task.** The literal `pnpm --filter zeromail-web run i18n:check || true` in `apps/web/messages/*.json` makes the lint-staged chain pass even when i18n:check exits non-zero. Plans 05–06 intentionally introduce temporary translation drift; strict mode here would deadlock those commits. **Plan 07's final task removes the `|| true` to flip the gate to STRICT.** (REVIEWS Revision 3, OpenCode HIGH.)
- **lint-staged uses extglob negation to de-duplicate Prettier runs.** The broad nested glob `apps/web/!(messages)/**/*.{md,mdx,json,css}` excludes the messages directory; a separate entry `apps/web/messages/*.json` runs Prettier ONCE on translation files followed by warn-only i18n:check. (REVIEWS Revision 5, Codex MEDIUM + OpenCode LOW.)
- **Pre-declare `transpilePackages: ['next-mdx-remote']` in Plan 02 (not Plan 06).** The entry is a no-op when the package is absent — Next config compiles without resolution. Adding it now means Plan 06's runtime install is a single `pnpm add` with zero config follow-up. (RESEARCH.md Pitfall 6.)
- **`lib/api/schema.d.ts` added to ESLint globalIgnores in addition to .prettierignore** so the generated OpenAPI bundle never trips ESLint either; consistent with how Plan 01's Wave 0 tests already treat it as out-of-scope.
