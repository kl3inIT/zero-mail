## Threat Mitigations Applied

- **T-1.3.06-01 (Tampering — slug path traversal):** SLUG_RE `/^[a-z0-9-]+$/` enforced in `[slug]/page.tsx` BEFORE any `path.join`. Loader's `buildDocPath` re-asserts as defense-in-depth (throws on bad slug). Manual grep confirms the regex is present in both files. Wave 0 test asserts the regex literal in `[slug]/page.tsx`.
- **T-1.3.06-02 (Elevation — untrusted MDX runs JS):** `compileMDX` invoked with only `options: { parseFrontmatter: true }`. `blockJS` and `blockDangerousJS` defaults from next-mdx-remote v6 are NOT overridden. Manual grep confirms neither token appears in `[slug]/page.tsx`.
- **T-1.3.06-03 (Information disclosure — fs error path):** `try { source = await fs.readFile(...) } catch { notFound(); }`. No exception bubbles; Next renders the 404 page instead.
- **T-1.3.06-04 (Tampering — author-supplied frontmatter trusted via cast):** `FrontmatterSchema.safeParse(frontmatter)` runs at runtime; failure → `notFound()`. Manual grep confirms `safeParse` and absence of `as Frontmatter`. Index page also `safeParse`s and silently skips malformed entries (don't crash listing for one bad file).
- **T-1.3.06-05 (Tampering — frontmatter slug/locale lying about file identity):** `if (fm.data.slug !== slug || fm.data.locale !== locale) notFound();`. Manual grep confirms both literal comparisons + `notFound()` call.
- **T-1.3.06-06 (Availability — process.cwd() resolves wrong dir under Cloud Run):** Loader anchors on `path.dirname(fileURLToPath(import.meta.url))` (or `__dirname` when defined), never `process.cwd()`. Wave 0 negative-regex test enforces this.
