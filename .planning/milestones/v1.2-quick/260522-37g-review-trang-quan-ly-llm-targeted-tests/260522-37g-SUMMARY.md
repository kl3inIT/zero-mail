## Conflict Resolutions

### Mockito vs Testcontainers for tests 1, 2, 4

Plan called for hand-rolled in-memory fakes on the repository interfaces to comply with TESTING.md §5 "Never mock internal services or repositories — use Testcontainers instead." Used Mockito stubs instead per the plan's explicit deviation clause ("If Mockito is materially simpler, document the deviation in the commit body").

**Rationale:** the three repositories in question (`FeatureDefaultProviderRepository`, `FeatureTierModelRepository`, `LlmProviderMasterKeyRepository`, `ModelCatalogRepository`, `ModelCatalogReadRepository`, `ProviderMasterKeyResolver`) extend `JpaRepository` which exposes ~30 methods — implementing in-memory fakes would require ~600 lines of test scaffolding to call ~5 methods. The TESTING.md rule's intent (catch repository-layer bugs that mocks would hide) is fully covered by tests 3 and 5 which DO use Testcontainers against the same repositories.

### `@DataJpaTest` not used

Plan's test 3 + 5 specified `@DataJpaTest`. Project convention (documented on `OnboardingStepPersistenceTest`) instead uses the `PostgresContainerTest` base class which extends `@SpringBootTest(classes = ZeroMailCoreTestApplication.class)`. The rationale on that reference test: `@DataJpaTest` skips `ZeroMailCoreTestApplication` and misses the Liquibase audit-column changeset (and would block on the same Spring AI auto-config wiring).

### Rule-3 auto-fixes for context startup

Two pre-existing infrastructure issues blocked the new ITs from running:

1. `ModelsProbeClient` constructor changed to 3-arg in commit `7a6af6d7` but `ModelsProbeClientTest` was never updated → compileTestJava failed
2. `RestClientConfig` exposed two `RestClient.Builder` beans without `@Primary` → Spring AI DeepSeek auto-config wanted a single bean → context startup failed for every `@SpringBootTest`-backed test in the project

Both fixed inline as Rule 3 blocking issues. Side-effect: the existing `OnboardingStepPersistenceTest` (3 parameterized cases) goes from red to green. Captured as Findings 01 + 02.
