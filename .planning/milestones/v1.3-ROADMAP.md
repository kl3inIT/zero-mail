# Milestone v1.3: Gmail Workspace Foundation

**Status:** ✅ SHIPPED 2026-06-16
**Phases:** 10-11
**Total Plans:** 12 (6 + 6)

## Overview

Converted Zero Mail from a one-Gmail-per-tenant product into a workspace-owned, multi-Gmail
model where business configuration (credits, billing, AI provider/BYOK, global safety/auto-send,
templates) is shared at workspace level while all mail automation — ingestion, projection, rules,
triage, outbound execution, audit — is isolated per active Gmail mailbox. Users can connect,
label, reconnect, disconnect, and switch between multiple Gmail accounts, with each mailbox
operationally isolated and the active mailbox surfaced throughout the web app.

Gmail-only, workspace-shared, mailbox-isolated foundation. Microsoft/Outlook, Zalo OA, CRM,
full team collaboration, and the formal GA tag remain deferred.

## Milestone Summary

**Key Decisions:**

- Copy Inbox Zero's stable mailbox-id isolation concept (`emailAccountId` → `gmail_connections.id`), not its user-owned account model, Next/Prisma architecture, all-account UX, or raw-email logging posture.
- Workspace-shared business layer (credits/billing/provider/BYOK/global safety/templates) vs mailbox-isolated mail layer (OAuth/watch/history/inbox/rules/actions/audit/display identity) — explicit ownership boundary enforced by `MailboxContext` ScopedValue + `MailboxBindingFilter` + ArchUnit `findByTenantId` ban.
- Global active-email uniqueness (changeset 127): one CONNECTED Gmail → one tenant, for unambiguous Pub/Sub routing. Cross-tenant duplicate surfaced via `DuplicateActiveMailboxException.Scope` (SAME_WORKSPACE vs OTHER_WORKSPACE) with distinct friendly login error codes.
- Rules are mailbox-owned by default; cross-mailbox reuse is an explicit copy-rules action that clones disabled-for-review (never a silent all-mailbox runtime rule).
- Mailbox switching invalidates mailbox-scoped TanStack Query keys in one mutation hook; AccountMenu keeps workspace identity separate from the connected-Gmail list.

**Issues Resolved (found & fixed during 11-UAT, 2026-06-15):**

- **T3 — duplicate add-Gmail 500:** `DuplicateActiveMailboxException` bubbled to a raw Whitelabel 500 at the OAuth callback. Fixed: `GoogleOAuthSuccessHandler` translates it to `OAuth2AuthenticationException` → friendly `/login?error=mailbox_already_connected` / `mailbox_in_other_workspace` redirect.
- **T5 — inbox projection cross-mailbox leak (blocker):** the projection read path filtered `WHERE tenant_id` only, leaking one mailbox's inbox into another after a switch. Fixed: threaded `gmail_connection_id` through `findInboxPage` / `InboxProjectionReadService` / `RecentInboxReadService` + DB-backed regression test. (The 11-05 isolation test mocked the live path, so the projection branch slipped past it.)

**Issues Deferred:**

- T8 visual From-check in recipient inbox deferred (worker not running during UAT session; send path itself verified via `assistant_action_audit` COMMITTED + real Gmail thread).
- Source/executing audit labels render only when `source != executing`; today every row has source == executing by design (a mailbox triages and acts on its own mail), so the distinguishing labels are reserved for a future cross-mailbox-action case.

**Technical Debt / Carry-Forward to v1.4+:**

- OPS-FUT-01..03 (shadow-mode toggle, paste-import, protect/escalate per-entry) — still deferred.
- OPS-FUT-04 — hostile-corpus eval, Grafana dashboards, CASA refresh, LAUNCH-GO-NOGO, and the formal GA tag remain outstanding; v1.3 ships **without** a GA tag.
- Team collaboration (TEAM-01..06), Zalo OA / CRM (CHAN-01..03), Microsoft/Outlook — future milestones.
