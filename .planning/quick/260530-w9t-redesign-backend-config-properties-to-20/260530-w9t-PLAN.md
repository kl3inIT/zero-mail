<objective>
Redesign the backend config/properties surface to Spring Boot 4.0.6 best practices: eliminate duplication and the `zeromail.*` (no-dash) vs `zero-mail.*` (kebab) prefix inconsistency across backend/api, backend/worker, and backend/core.

This is a PURE structure/namespace refactor. NO runtime-effective value may change; behavior must be byte-identical. Every change is either (a) renaming a property key from the no-dash form to the canonical kebab form (annotation + yml in the SAME commit), (b) deleting a redundant value that a Java `@DefaultValue` / compact-constructor already supplies, (c) splitting one god-object `@ConfigurationProperties` record into per-feature records bound to the SAME keys, or (d) centralizing identical correctness-locked boilerplate into one imported file.

Purpose: convention #9 says each runnable module owns its env config, but correctness-locked privacy/AI-suppression boilerplate is currently duplicated verbatim across api+worker (and partially in prod profiles), and two prefix namespaces (`zeromail` and `zero-mail`) coexist — a real binder hazard. Unify and dedupe without changing behavior.

Output: 7 atomic-commit tasks, safe ordering (low-risk deletions first, prefix rename, then the record split — done in two passes 3a low-fan-out / 3b high-fan-out nested-record relocation — then the module-record rename, then the shared import, then final verification). RESEARCH.md (260530-w9t-RESEARCH.md) is authoritative and OVERRIDES any conflicting note.
</objective>
