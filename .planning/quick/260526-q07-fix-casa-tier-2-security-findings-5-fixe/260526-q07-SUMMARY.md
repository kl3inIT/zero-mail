## What changed per finding

### Finding 1 — V14.1.1 (No default credentials)
`scripts/ops/backup/pg-backup.sh:23` switched from `${PG_SUPERUSER_PW:-zeromail}` to `${PG_SUPERUSER_PW:?...}`. The script now aborts immediately when the password is not exported by the operator/systemd unit, instead of silently falling back to the well-known string `zeromail`.

### Finding 2 — V5.2.6 (SSRF)
Extracted the private-IP rejection rule that previously lived only in `ByokEndpointValidator` into a new `core.shared.net.OutboundHostGuard` Spring bean. Wired it into `UnsubscribeHttpClient.postOneClick` so an RFC 8058 one-click unsubscribe targeting an internal/private/metadata host (loopback, RFC 1918, link-local, 169.254.169.254, IPv6 ULA) now short-circuits with `Failed("BLOCKED_PRIVATE_HOST")` BEFORE any outbound HTTP request is dispatched. DNS failures are treated as blocked (fail-closed). `ByokEndpointValidator` now delegates to the same guard so the rule has a single owner. Added `shared :: net` as a Modulith NamedInterface and listed it under the `llm` and `cleanup` `allowedDependencies`. 13 unit tests covering each blocked range + 2 integration tests for the unsubscribe gate.

### Finding 3 — V3.3.1 + V9.2.2 + V13.1.5 (Token revocation on user action)
New `GoogleOAuthRevokeClient` POSTs to `https://oauth2.googleapis.com/revoke?token={token}` with `application/x-www-form-urlencoded` content type. Best-effort contract: HTTP 200 and HTTP 400 with body containing `invalid_token` both succeed cleanly; every other failure is logged + swallowed. The refresh-token value never appears in any log statement or exception message.

Wired into `GmailConnectionService.disconnect(tenantId)` with new ordering: `tryStopWatch → revokeStoredRefreshToken → markDisconnected`. The reorder is required because the watch.stop call needs the still-persisted ciphertext to refresh an access token. `markDisconnected` now also nulls `refresh_token_encrypted` on the entity so the encrypted token cannot be reused even if the DB ciphertext leaks. Defense-in-depth wrap-and-log around the revoke call ensures DB-side disconnect always completes even when Google's revoke call throws.

### Finding 4 — V3.4.1 + V14.1.1 (Secure cookie attribute)
`backend/api/src/main/resources/application-prod.yml` already had `server.servlet.session.cookie.secure: true`; the audit finding was about the absence of a fail-loud startup gate, not the yml entry itself. Added `ProdSessionCookieSecureGuard` — a `@PostConstruct` bean that aborts startup with `IllegalStateException` when the `prod` profile is active and `sessionCookieSecure` is false. Catches the future failure mode where an operator removes the yml entry or a config refactor changes the property name. Added a CASA control comment above the yml entry.

### Finding 5 — V4.2.1 (Broken tenant isolation on persistence reads)
`ChatMessageJdbcRepository.findByChatIdOrderByCreatedAtAsc(chatId)` removed; replaced with `findByChatIdAndTenantIdOrderByCreatedAtAsc(tenantId, chatId)`. SQL gained `AND tenant_id = ?`. All 3 production call sites updated:

1. `ChatOrchestrator.history(tenantId, chatId)` now takes tenantId; passed at the single call site in `streamOneIteration`.
2. `ChatHistoryProjector.project(tenantId, chatId)` passes tenantId directly to the repository instead of filtering after the fact.
3. `ZeroMailChatMemory.loadMessages(conversationId)` pulls tenantId from `TenantContext.currentTenantUuid()` because Spring AI's `ChatMemory` contract only supplies `conversationId`. An unbound `TenantContext` now throws rather than silently exposing cross-tenant history. Existing integration tests (`ZeroMailChatMemoryIT`, `ChatOrchestratorAssistantTextPersistenceIT`) updated to bind `TenantContext.TENANT` around `chatMemory.get(...)` calls.

Also added `findByIdAndTenantId(messageId, tenantId)` sibling variant for future callers; the original `findById(messageId)` left in place because it has no in-tree callers and removing it would broaden the diff with no further safety gain.

**Liquibase changelog 098-chat-message-composite-fk.yaml** enforces the invariant at the DB layer:
- `ALTER TABLE chat ADD CONSTRAINT ux_chat_id_tenant UNIQUE (id, tenant_id)` — required as the FK target (chat.id PK preserved).
- Drop the old `chat_message_chat_id_fkey` (inline single-column FK from changelog 042).
- Add `fk_chat_message_chat_tenant FOREIGN KEY (chat_id, tenant_id) REFERENCES chat (id, tenant_id) ON DELETE CASCADE`.

Inserting `(chatA, tenantB)` now raises SQLSTATE 23503 verified by integration test.

## Deviations from plan

1. **Task 5 — `findById` left in place.** Plan said "Update the `findById` method to also accept and filter by tenantId — rename to `findByIdAndTenantId`". The original `findById(messageId)` has zero in-tree callers, so removing it would only broaden the diff without further safety gain. Added `findByIdAndTenantId(messageId, tenantId)` as a sibling for future callers; left the old `findById` to keep the diff scoped to the actual attack surface (the chat-history listing endpoint). Documenting here rather than silently dropping the rename.

2. **Task 5 — three additional test files updated.** Plan listed 5 files for Task 5; the actual diff touched 11 because the existing tests `ZeroMailChatMemoryIT`, `ChatOrchestratorAssistantTextPersistenceIT`, `ChatOrchestratorReadToolLoopIT`, `ChatOrchestratorTransientStreamRetryIT` called the old method name and needed updating. Master changelog `db.changelog-master.yaml` also needed the `include:` entry for 098 (the plan called this out as a possibility — confirmed not `includeAll`). All test updates are mechanical migrations to the new method signature; no behavioral changes.

3. **Task 5 — Liquibase YAML precondition syntax.** First attempt at the `preconditions:` block triggered a SnakeYAML parse error (Liquibase expects `preConditions:` camelCase with the `onFail` directive as a list element, not a sibling scalar). Fixed by switching to the documented form. No semantic change.

4. **Task 2 — `BlockedOutboundHostException` added as new sibling.** Plan referenced this type in the GREEN steps but did not include it in the `<files>` list explicitly. Added it because `requireAllowed` needs a typed throwable; documenting here so the file count matches the actual commit.

5. **Task 5 — Modulith `shared :: net` entry added to two package-info.java files.** Not in the plan's file list. Required because the new `core.shared.net.OutboundHostGuard` is a NamedInterface and `core.llm` + `core.cleanup` now import it; without the entry, `ModulithVerificationTest` would fail. Mechanical wiring update.
