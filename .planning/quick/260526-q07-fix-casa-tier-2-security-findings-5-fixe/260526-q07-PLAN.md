<!-- OutboundHostGuard (Task 2) extracts these so UnsubscribeHttpClient can reuse them. -->

From `ByokEndpointValidator.java` (lines 166–200):
- `private void rejectPrivateResolvedAddresses(String host, BYOKProvider provider)` — resolves DNS, throws on private.
- `private static boolean isBlockedAddress(InetAddress address)` — checks `isAnyLocalAddress() || isLoopbackAddress() || isLinkLocalAddress() || isSiteLocalAddress() || isMetadataAddress(...) || isIpv6UniqueLocalAddress(...)`.
- `METADATA_IPV4_ADDRESS = "169.254.169.254"` — AWS/GCP metadata service.
- IPv6 ULA check: `(firstByte & 0xfe) == 0xfc` for `fc00::/7`.

Existing chat table contract (`041-chat.yaml` + `042-chat-message-and-body-ban-trigger.yaml`):
- `chat(id uuid PK, tenant_id uuid NOT NULL, ...)` — id is the table PK, no UNIQUE on `(id, tenant_id)` today.
- `chat_message(id uuid PK, chat_id uuid NOT NULL REFERENCES chat(id), tenant_id uuid NOT NULL REFERENCES tenants(id), ...)` — tenant_id stored on each row, but composite FK to `chat(id, tenant_id)` is NOT enforced (a malicious caller passing a chat_id from another tenant would currently insert successfully).

For composite FK target `chat(id, tenant_id)`, Postgres requires a UNIQUE or PRIMARY KEY constraint on the target columns. Add `ALTER TABLE chat ADD CONSTRAINT ux_chat_id_tenant UNIQUE (id, tenant_id);` (preserves existing PK on `id` since UNIQUE adds a secondary unique index — no behavior change, just enables FK target).
