# Quick Task 260523-m46 Summary

Implemented a Gmail-backed `/inbox` surface capped to the 100 most recent inbox messages.

## Delivered

- Added `RecentInboxReadService` in `backend/core` to list Gmail inbox message metadata directly with Gmail `nextPageToken`, page size capped at 20 and total cap at 100.
- Inbox cursors are HMAC-signed so clients cannot tamper with `loadedCount` and page past the 100-message cap.
- Added `GET /api/gmail/inbox` and `GET /api/gmail/inbox/{gmailMessageId}` in `backend/api`.
- Message content is fetched only from the detail endpoint when a user opens a message; raw Gmail content is not persisted.
- Detail now prefers sanitized transient Gmail HTML, falls back to linkified text/plain, and supports small inline `cid:` images without storing content.
- Added `/inbox` Next.js route, sidebar entry, two-pane inbox UI, TanStack infinite query lazy loading, refresh, Gmail-like unread/read rows, detail panel, Reply / Reply all / Forward chat handoff, and "Open Gmail" link.
- Fixed the Base UI `nativeButton` warning for link-rendered buttons by marking anchor-rendered actions as non-native buttons.
- Added `apps/web/e2e/inbox.spec.ts` to verify render, HTML detail fetch, 20-message lazy-load requests, action buttons, and no nativeButton warning in a real browser.
- Added e2e Gmail stub pagination support and a focused backend test for `nextPageToken` paging.
