# Quick Task 260508-g41 Summary

**Completed:** 2026-05-08
**Status:** Complete + follow-up refactor

## Outcome

BYOK now supports a required tenant model end-to-end, OpenRouter is a first-class UI preset, Anthropic native BYOK remains available, and custom OpenAI-compatible endpoints still work with explicit model entry. Spring AI is pinned to `2.0.0-M5`; the adapter code and docs use the M5 builder/options seams instead of the old M4 low-level client-cloning path.

Follow-up on 2026-05-08: BYOK request APIs now accept a provider preset instead of the persisted protocol enum. The UI groups official providers separately from compatible endpoints, adds OpenAI official and Anthropic-compatible options, and shows reason-specific validation failures for bad keys, rejected endpoints, connection failures/timeouts, and unavailable models.

## Changed

- Added BYOK `model` to backend commands, DTOs, persistence entity, current response, OpenAPI schema, frontend payloads, and gateway routing.
- Added Liquibase changeset `019-tenant-byok-model.yaml` for the persisted BYOK model.
- Updated OpenAI-compatible BYOK to build a one-call `OpenAiChatModel` with tenant `apiKey/baseUrl/model`.
- Updated Anthropic BYOK to pass `AnthropicChatOptions.Builder` per request with tenant `apiKey/baseUrl/model`.
- Updated BYOK settings UI with provider presets: `OpenRouter`, `Anthropic`, `Custom OpenAI Compatible`; OpenRouter maps to the fixed OpenRouter OpenAI-compatible endpoint.
- Regenerated frontend API schema and i18n bundles.
- Synced canonical project docs from Spring AI `2.0.0-M4` to `2.0.0-M5`, including `AGENTS.md`, `CLAUDE.md`, stack/research docs, Phase 2C docs, and pitfalls.
- Added `ByokProviderPreset` (`openrouter`, `openai`, `anthropic`, `openai-compatible`, `anthropic-compatible`) as the API/UI contract while keeping persisted `BYOKProvider` as the runtime protocol.
- Server-side preset resolution now owns fixed endpoints for official OpenRouter/OpenAI/Anthropic and requires endpoint input only for compatible presets.
- Added Anthropic-compatible endpoint policy support with the same SSRF/non-vendor guard style as OpenAI-compatible endpoints.
- Changed BYOK validation to return structured reasons such as `endpoint_rejected`, `upstream_rejected`, `connection_failed`, `timeout`, and `model_not_found`; the frontend maps those to specific localized messages.
